# §1 굽기는 프레임을 막지 않는다

- **굽기를 메인 스레드에서 뺀다.** 엔진(mypaint 이식 · 순수 TS · 캔버스 2D)을 **Worker + OffscreenCanvas**로. 안 되는 환경(OffscreenCanvas 없음)은 **시간 분할**로 대신한다: 프레임당 4ms 예산 안에서 획 N개씩 굽고 다음 프레임에 이어서(부분 업로드 65 ④ 그대로).
  - Worker 경로와 분할 경로는 **같은 함수**(bakeFaceTex)를 부른다 — 그림이 갈리면 안 된다. 게이트: 두 경로의 결과 픽셀 해시 동일.
  - 결정론 유지(63) — Worker에서도 시드는 획 id.
- **옛 그림을 계속 보인다.** 단계(lv)가 바뀌어 다시 굽는 동안 **직전 텍스처를 그대로 띄운다**(GPU가 늘려 그린다 — 잠깐 흐릿한 것이 빈 면·멈춤보다 낫다). 새 굽기가 끝나면 바꾼다. 빈 프레임 0.
- 그리는 동안(66의 초안 경로)은 지금대로 메인에서 — 지연이 곧 감각이다. 이 라운드는 «확정본 재굽기»만 뺀다.

**1-2 면마다 칠의 색인과 그림 탑** (사람의 제안 — 「면마다 따로 트리」)
- **색인**: `Map<(faceId, side), Stroke[]>`를 문서 옆에 든다. 획을 더하고 지우고 되돌릴 때 그 면의 목록만 고친다(문서 형식은 무변 — 색인은 파생이고 열 때 한 번 세운다). `paintStrokesOf`는 색인을 읽기만 한다. sigs도 면별로 캐시하고 바뀐 획만 다시 센다.
- **그림 탑(한 번 굽고 내려 쓴다)**: 면마다 **그 면이 예산 안에서 가질 수 있는 최대 단계로 한 번** 굽고, 작은 단계는 GPU 밉맵(내려 표집)으로 쓴다 — 돌리다 작아지는 것은 **재굽기가 아니다**. 다시 굽는 때는 둘뿐: 획이 바뀌었다 · 화면이 굽힌 단계보다 커졌다(줌 인 — §1의 비동기로). 65 ③ 누적(뒤에 더한 획만 굽기)은 최대 단계 캔버스 위에서 그대로 산다.
- 이 둘이 서면 §2의 동결·히스테리시스는 «줌 인»에만 남는다.
**게이트**: 편집 한 번에 훑는 획 수 == 그 면의 획 수(전체 아님 · 값) · 색인과 filter 결과 동일(반증 시험) · 단계 내림에서 bakeFaceTex 호출 0 · 밉맵 그림의 픽셀 항등은 «같은 단계에서» 잰다(내림 표집은 GPU 몫 — 65 ①의 자를 그 단계에서).

**게이트(§1 전체)**: 궤도 4초 동안 메인 스레드 최장 차단 ≤ 8ms · 프레임 p95 ≤ 16.7ms(60Hz) · 빈 프레임(칠 면이 흰 채로 그려진 프레임) 0 · Worker/분할 두 경로 해시 동일 · 65 ①·66 게이트 무회귀.

# §2 단계는 상호작용 중에 안 바뀐다

- **동결**: 손가락/펜이 닿아 있는 동안과 관성이 도는 동안(카메라 속도 > 값) `lv`·`texelQ`를 **얼린다** — bakeSig가 안 바뀌니 재굽기 0. 멈추고 150ms 뒤에 한 번 재평가.
- **히스테리시스**: 올라갈 때는 화면 크기 > 1.25×lv, 내려갈 때는 < 0.6×lv에서만 바뀐다. 경계에서 널뛰기 0.
- 67 §2의 `texelQ`는 유지하되 같은 동결 아래 둔다(무늬 굵기는 멈춘 뒤 맞으면 된다).

**게이트**: 궤도 4초 동안 bakeFaceTex 호출 0(값) · 멈춘 뒤 재굽기 ≤ 보이는 면 수 · 경계 왕복(줌 인아웃 10회)에서 재굽기 ≤ 2 · 낡은 그림 게이트(67 §2) 무회귀 — 멈춘 뒤에는 반드시 맞는 단계다.

# §3 예산은 퇴출이 아니라 «배분»이다

- 65 ⑤는 예산을 넘으면 **퇴출**한다 → 보이는 면이 예산을 넘으면 순환. 바꾼다: 보이는 (면,쪽)의 요구 단계 합이 예산을 넘으면 **화면에서 작은 면부터 단계를 한 칸 내려**(2048→1024→512) 합을 예산 안에 넣는다. 퇴출은 «안 보이는 것»에만.
- 2048은 **화면에서 실제로 그만큼 큰 면**에만(지금 규칙 그대로) — 다만 예산 배분이 우선한다.
- 예산 값을 다시 잰다: 실기기(iPad) 메모리를 가정한 값으로. 「여덟 쪽 타협」을 값으로 대체하고 원장에.

**게이트**: 보이는 칠 면 20장(픽스처)에서 퇴출 0 · 프레임마다 굽기 0 · 합 ≤ 예산 · 배분으로 내려간 면의 화면 오차(내려간 단계의 텍셀/px ≥ 0.5 — 흐림 상한 값).

# §4 열 때 — 먼저 그림, 칠은 뒤따라 온다

- 첫 프레임은 **칠 없이**(선·면·분류·두께) 그린다 — 100ms 안. 칠은 §1의 비동기 굽기로 **보이는 큰 면부터** 채운다. 진행 표식은 67 0-1의 표식 자리(구석 · 작게).
- **굽힌 그림을 기억한다**: (면, 쪽, sigs 해시, lv)를 열쇠로 굽힌 비트맵을 IndexedDB에 둔다(store.ts의 그 DB · 별도 저장소 이름 · 문서 형식 무변 — 캐시다, 정본이 아니다). 다시 열 때 열쇠가 맞으면 **굽지 않고 올린다**. 상한(예: 문서당 64MB) 넘으면 오래된 것부터 버린다. 열쇠가 안 맞으면 다시 굽는다 — 캐시가 틀린 그림을 보이는 길은 없다(해시가 열쇠다).
- 새로고침 «무한 로딩»의 실제 원인이 §0에서 다른 것으로 나오면(예: 자동 저장 크기 · IndexedDB 열기 실패 · 서비스 워커) **그것을 먼저 고치고** 이 절은 그 뒤.

**게이트**: 픽스처 열기 — 첫 상호작용 프레임 ≤ 1000ms · 칠 전부 ≤ 5000ms(캐시 없음) · ≤ 1500ms(캐시 있음) · 메인 최장 차단 ≤ 50ms · 캐시 열쇠 불일치 → 재굽기(반증) · 저장 왕복 5/5 · KEY_ORDER 무변.
