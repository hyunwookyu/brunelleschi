# §0 실기기 값 — 이것이 정본이다 (컨테이너 값을 대체한다)

무빙크패드 · Chrome · 120Hz · 54초 · 0.5초마다 읽음(영상에서 108장 판독):

```
잘 돌 때        fps 78~104 · p95 16.2~18.3ms          ← 기기도 웹도 벽이 아니다
멎음 ①          fps 1 · p95 0ms       4연속(≥2초)
기어감          fps 35 → 17 → 17 → 17 → 6 → 4 · p95 82.8 → 94.9 → 235.4 → 373.3ms   (3~4초)
멎음 ②          fps 1 · p95 0ms
그 밖           fps 12 · p95 25.8 · fps 13 · p95 283.2
열 때           열기 5,333ms · 최장 차단 15,028ms
```
- **73의 결론(㉮ 시험 기계가 임자)은 «칠 텍스처 파이프라인»에 대해서만 맞다.** 실기기에서 프레임은 충분하고, 사람이 느낀 것은 «프레임이 무겁다»가 아니라 **«가끔 몇 초씩 통째로 멎는다»**다. 성격이 다르고 자리도 다르다.
- CLOSING의 성능 게이트 분모를 **실기기(무빙크패드)**로 바꾼다. 컨테이너 fps는 게이트에서 내린다(73 §0 ㉠ 그대로 — 기계에 안 흔들리는 자만 남긴다: 호출 수 · 걸음별 ms · 바이트 · **멈춤 횟수**).
- 무빙크패드가 최소 사양의 분모다(DIRECTION — PC 구동 계획 없음 · 대상은 펜 있는 태블릿).

**계측 판의 결함 둘 — 먼저 고친다**
```
① fps 1일 때 p95가 0ms로 나온다     1초 창에 눈금이 하나뿐이라 «간격»이 없다 — 제일 나쁠 때 자가 0을 가리킨다
② 「최장 차단」이 평생 최댓값이다     15,028에 묶여 그 뒤의 멈춤을 하나도 안 보여준다(완전 정지 둘이 저 숫자 뒤에 숨었다)
```
고침: p95를 **1초 창 안 최장 간격**으로 바꾸고(이름도 「최장 간격」), 「최장 차단」을 **최근 다섯 번의 멈춤 목록**으로 바꾼다 — 각 줄은 `t=12.4s · 1,850ms · save` 꼴로 **언제 · 몇 ms · 직전에 무엇이 돌았나**. 표식(무엇)은 §1이 심는다.
**게이트**: 멈춤을 인위로 넣은 판(스크립트로 800ms 동기 루프)에서 목록에 그 줄이 뜬다 · fps 1 구간에서 「최장 간격」이 0이 아니다(반증: 옛 자는 0) · 실기기 사진.

# §1 표식을 심는다 — 멈춤에 이름을 붙인다

메인 스레드를 오래 잡을 수 있는 곳 넷에 «구간 표식»을 두른다(`performance.mark`/`measure` 또는 우리 장부 — 이름만 남으면 된다).
```
save.serialize      serializeBrnl(JSON.stringify 전량)          filepanel.ts saveNow
save.put            putDoc(IndexedDB 쓰기)
save.thumb          captureThumb(toDataURL JPEG) + putThumb
bake.commit         획 확정 뒤 bakeFaceTex
tex.upload          texSubImage2D
doc.parse           parseBrnl(열 때)
doc.build           문서 세우기(면·접합·색인)
```
멈춤이 잡히면 **그 순간 열려 있던 표식 이름**을 목록 줄에 적는다. 겹치면 가장 안쪽 것.
**게이트**: 일곱 표식이 전부 최소 한 번 목록에 나타난다(부하 픽스처) · 표식 밖에서 난 멈춤은 `?`로 적힌다(값).

# §2 반증 — 자동 저장을 끄고 같은 짓을 한다

**가설**(코드 실측 · filepanel.ts 109~152 · file.ts 118 · main.ts 338):
> 획 하나가 끝날 때마다 `app.listeners`가 `schedule()`을 부르고, 400ms(`AUTOSAVE_DEBOUNCE_MS`) 뒤 `saveNow()`가 **문서 전량을 `JSON.stringify`** 하고(칠 많은 문서는 수 MB — 상한 5MB에 70% 경고), IndexedDB에 쓰고, **`toDataURL('image/jpeg')`로 썸네일을 굽고**, 또 쓴다. 넷 다 메인 스레드 동기다. 그래서 «긋는 동안은 100fps, 손을 뗀 뒤 멎는다».

손잡이 둘을 넣는다(개발용 · `?dev=1` 밖의 URL 매개 — 69 표에 두 행 추가):
```
?nosave=1     자동 저장을 끈다(문서는 메모리에만 — 화면 구석에 «저장 꺼짐» 표식 · 실수로 남지 않게)
?nothumb=1    썸네일만 끈다
```
**재는 법**: 같은 문서 · 같은 몸짓으로 셋을 돌린다 — 그냥 / `?nothumb=1` / `?nosave=1`. 각 팔의 **멈춤 횟수 · 최장 · 합**을 값으로.
```
멈춤이 nosave에서 사라진다        → 저장이 임자다. §3으로
썸네일만 꺼도 대부분 사라진다      → toDataURL이 임자다. §3-3만 해도 된다
셋 다 비슷하다                    → 가설 반증. 목록이 가리키는 다음 표식(bake.commit · tex.upload)으로 옮기고 §3은 그것을 고친다
```
⚠ 이 절이 **73 §0 ㉠의 첫 손님**이다 — 수리 전 판에서 「멈춤 ≥ 2회」가 실제로 나오는 것을 값으로 남기고 시작한다. 안 나오면 자를 고친다.
**게이트**: 세 팔의 표(멈춤 횟수·최장·합 · 부하 픽스처 + 실기기 항목) · 지목 하나 · 반증 문면.

# §3 고친다 — §2가 지목한 것만

**3-1 저장을 메인 스레드에서 뺀다**
직렬화와 IndexedDB 쓰기를 **Worker**로 옮긴다(IndexedDB는 Worker에서 쓸 수 있다). 메인은 문서의 얕은 복제만 넘긴다(구조화 복제). 실패·성공 알림은 지금 문면 그대로.
**게이트**: 저장 중 메인 최장 차단 ≤ 50ms(실기기) · 저장 뒤 문서 바이트가 종전과 **완전히 같다**(같은 문서 → 같은 문자열 · 해시) · 저장 실패 알림 무회귀 · 저장 왕복 5/5.

**3-2 전량 직렬화를 그만둔다 — 획 단위 저장**(근본 · 열기도 같이 고쳐진다)
지금은 문서 하나가 문자열 한 덩어리(`DOCS` 저장소의 `data`)다. **획 단위 레코드**로 바꾼다: 저장소 `strokes`(열쇠 `[docId, strokeId]`) + 문서 머리(frame · faces · unit · scaleRef · …)만 따로. 새 획 하나면 **한 줄만** 쓴다. 지우기·되돌리기는 그 줄만 지운다.
- ⛔ **`.brnl` 파일 형식은 안 바뀐다.** 내보내기·불러오기는 지금의 `serializeBrnl`/`parseBrnl` 그대로다(KEY_ORDER 무변이 게이트). 바뀌는 것은 «기기 안 저장소»의 꼴뿐이다.
- 이주: 옛 `data` 문자열이 있으면 열 때 한 번 풀어 획 줄로 옮기고 `data`를 지운다. 실패하면 옛 것을 그대로 둔다(잃지 않는다).
- 열기도 파싱이 사라진다 — 커서로 읽어 바로 세운다.
**게이트**: 획 하나 더할 때 쓰는 바이트 == 그 획의 바이트(전량 아님 · 값) · 저장/열기 왕복에서 문서가 완전히 같다(획 id·차례·좌표·해시) · 옛 문서 이주 5/5 + 실패 시 무손실 · 열기 시간 전/후(실기기) · `.brnl` 내보내기 바이트 무변.

**3-3 썸네일을 저장마다 굽지 않는다**
`toDataURL`은 동기 인코딩이다. 저장에서 뗀다 — 문서를 닫을 때 · 화면이 쉴 때(`requestIdleCallback`) · 마지막 굽기에서 N초 지났을 때 중 하나. 없으면 목록에 종전대로 «그림 없음».
**게이트**: 저장 한 번에 `toDataURL` 호출 0 · 목록 그림이 여전히 뜬다(왕복) · 그림 없는 새 문서 무회귀(43의 그 자리).

**3-4 디바운스**
400ms는 획과 획 사이 쉬는 시간과 겹친다. 값을 올리고(측정해서 정한다) 쉬는 때에 붙인다. 문서를 닫거나 탭이 숨을 때는 즉시 쓴다(`flush` 그대로 — 잃지 않는다).
**게이트**: 연속으로 획 20개를 그을 때 저장 횟수(값 · 전/후) · 마지막 획이 반드시 저장된다(왕복).

# §4 열 때의 15초

§3-2가 파싱을 없앤다. 남는 것은 «칠 텍스처 전량 굽기»이고, 그것은 72 §4가 미룬 **굽힌 그림 캐시**(면·쪽·획 해시·단계를 열쇠로 IndexedDB에 비트맵)다. §3이 끝나고 시간이 남으면 여기까지, 아니면 이월하되 **열기를 세 몫으로 갈라 값만** 남긴다(파싱 / 세우기 / 굽기).
**게이트**: 실기기 열기 전/후 · 첫 상호작용 프레임 · 세 몫의 ms.
