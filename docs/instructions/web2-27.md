# web2-27 — 지평선 위에서 시작하기 · 눈 토글 · 파일 크기

## 배경

web2-25 이후 사용자가 손으로 찾은 것들 중 **모델·거동 층위**의 셋이다.
화면 문구·배치는 web2-28, 손글씨 치수는 web2-29.

이 라운드는 26 다음에 온다. 26-1(층 소유권)이 끝나지 않았으면 27-2를 시작하지 마라 —
같은 겹 구조를 만진다.

---

## 27-1 지평선 위에 그은 첫 선

**현상.** 작도를 시작할 때 첫 획을 지평선보다 **위에** 그으면 접지가 안 된다.
`pointOnGround`가 지평선 위/선상의 점에 대해 `null`을 돌려주기 때문이다.

```ts
if (r.d.y >= -1e-9) return null      // 위로 가거나 지면과 평행 — 안 만난다
```

이건 계산으로는 옳다. 위로 가는 광선은 바닥면과 안 만난다.

**사용자가 낸 규칙.** 어차피 절대좌표가 중요한 게 아니니, 지평선 위에 그은 선의 첫 시작점을
지평선 기준으로 **mirror**해서 그 반대점(지평선 아래 점)을 원점으로 삼는다.

**그 규칙의 기하학적 정체.** 눈높이를 지나는 수평면에 대해 광선을 뒤집으면, 뒤집힌 광선은
아래로 가서 바닥과 한 점 `G`에서 만난다. 그 `G`를 다시 눈높이 면에 대해 되뒤집으면

```
P = (G.x, 2 · EYE_HEIGHT, G.z)
```

즉 **원래 광선이 `y = 2·EYE_HEIGHT` 평면과 만나는 점**이다. 근사가 아니라 정확히 그 점이다.

의미도 맞는다. 눈높이보다 위에 긋는다는 건 천장에 긋는다는 뜻이고, `EYE_HEIGHT = 1.6`이므로
그 평면은 3.2m — 실제 층고에 가깝다. 임의의 값이 아니라 눈높이를 바닥에 대해 되접은 결과다.

**작업.**

1. 접지 함수에 천장 갈래를 만든다. `pointOnGround`를 고치지 말고 **위 갈래를 따로** 둬라 —
   바닥 접지는 다른 데서도 쓰이고, 거기서 `null`이 사라지면 안 된다.
   `pointOnCeiling(an, pose, s)`: `r.d.y > 1e-9`일 때 `u = (2·EYE_HEIGHT − pose.p.y) / r.d.y`.

2. `lift.ts`의 첫 선 처리에서, 두 끝점이 **모두** 지평선 위면 천장 갈래를 쓴다.

3. **걸치는 경우는 거부한다.** 한 끝은 위, 한 끝은 아래면 그 선은 무한대로 간다. 접지시키지 말고
   이유를 남겨라. 이건 실패가 아니라 정의상 불가능이다.

4. **`isFirstLine`은 그리기 순서가 아니라 lift 상태다.**
   ```ts
   const isFirstLine = lifted.size === 0 && anchorId === null
   ```
   그러므로 「위에 먼저, 아래를 나중에」 순서에서는 위 선이 먼저 자립하고, 그 다음 아래 선이
   그 위 선을 근거로 풀린다. 이 순서가 실제로 도는지 **별도 픽스처로 확인하라.**
   지금까지 아래 선만 검사해 왔다.

5. **못 풀렸을 때 이유를 말하라.** 지금은 조용히 안 풀린다. 걸치는 선, 또는 천장 갈래로도 축이
   안 정해지는 경우에 무엇이 부족한지 한 줄로 알려라. 문구는 짧게 — 「이 선만으로는 방향이 안
   정해진다」 정도. 설명 문장을 늘리지 마라 (web2-28의 규칙과 같다).

**게이트.**
- 아래에서 시작: 기존 픽스처 전부 무회귀
- 위에서 시작: 첫 선이 `y = 2·EYE_HEIGHT` 평면에 놓인다 (좌표로 검증, 눈으로 말고)
- 위 → 아래 순서: 두 선 모두 자립한다
- 걸치는 선: 접지되지 않고 이유가 남는다
- 위에서 시작한 그림을 돌렸을 때 선이 공간에서 일관되게 따라 돈다

## 27-2 눈 토글이 겹 전체를 치워야 한다

**현상.** 옐로/트레이싱지를 치우려고 눈동자 아이콘을 누르면 **거기서 그린 선만** 사라진다.
종이 자체(색조·질감)는 남는다. 사용자는 당연히 겹을 치우는 것으로 읽는다.

**작업.**
- 눈 토글 = 그 겹 **전체**(종이면 + 그 위의 획 + 결)를 화면에서 뺀다.
- 끄는 순간 그 겹이 활성 층이면, **활성 층을 한 단계 아래로 내린다.** 안 보이는 층에 그리는
  상태가 남으면 안 된다.
- 다시 켜면 겹과 그 획이 그대로 돌아온다. 활성 층은 자동으로 올리지 마라 — 사용자가 고른다.

**의존.** 26-1이 획의 소속 층을 확정한다. 그게 끝난 뒤에 하라. 순서를 바꾸면 26-1이
27-2를 다시 깨뜨린다.

**게이트.**
- 겹을 끄면 종이면·획·결이 모두 사라진다 (렌더 픽셀 비교)
- 활성 층이던 겹을 끄면 활성 층이 아래로 내려간다
- 끈 상태에서 그은 획이 안 보이는 층에 들어가지 않는다
- 다시 켜면 획 수와 좌표가 왕복한다

## 27-3 파일 크기

**현상.** 옐로 100획이 488KB. 상한의 18.6%다. 이 비율이면 380획 근처에서 경고, 540획 근처에서
실패한다. 자유 스케치를 하는 겹에서 380획은 도달하는 양이다.

**어디가 무거운가.** 옐로는 `raw`(프리핸드 원점열)가 정본 기하다(web2-23). 지울 수 없다.
줄일 수 있는 건 둘이다.

1. **좌표 자릿수.** 지금 전 자릿수를 그대로 쓰고 있으면 대부분이 무의미한 소수다.
   - 3D 좌표: 소수 3자리 (= mm). 제도 정밀도보다 이미 아래다.
   - 화면 좌표: 소수 2자리.
   자릿수는 **직렬화에서만** 자른다. 메모리 안의 값은 건드리지 마라 — 반복 편집에서 오차가 쌓인다.

2. **`raw` 단순화 — 옐로에만.** RDP로 줄이되 허용 오차를 **화면 선폭의 0.25배 아래**로 잡는다.
   그 아래면 눈에 안 보인다. 트레이싱지·종이의 획에는 적용하지 마라 (거긴 `raw`가 정본이 아니다).

**주의 — 원칙 a.** 옐로의 `raw`는 정본이다. 단순화는 정본을 고치는 것이므로 **커밋 시점에 한 번**
하고 끝내라. 저장할 때마다 다시 줄이면 획이 세대마다 조금씩 야위어 간다.

**게이트.**
- 옐로 100획의 크기가 절반 이하
- 단순화 전후의 최대 편차가 화면 선폭의 0.25배 미만 (수치로 재라)
- 저장 → 열기 → 저장을 5회 반복했을 때 크기와 좌표가 더 이상 안 변한다 (세대 손실 없음)
- 종이·트레이싱지 획은 단순화되지 않는다
