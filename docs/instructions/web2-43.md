# web2-43 — 파일: 잃지 않고, 다시 열리고, 찾을 수 있다

> 이 라운드는 **Opus**로 돈다. 그래서 갈래와 게이트를 촘촘히 적었다 — 지시문이 판단을
> 대신한다. 지시문에 없는 갈림이 나오면 임의로 정하지 말고 보고하라.

## 배경

사용자 실사용 관찰:
> 「열기가 불편하다. 보통 프로그램의 파일 탭에는 최근 문서 등이 쭉 뜨는데 그런 게 없다.
> 저장 시 최종 화면을 썸네일로 사용하는 최근 드로잉 탭이 있으면 좋겠다.」

그리고 더 무서운 것: **저장하고 다시 여는 왕복을 지금까지 한 번도 검증하지 않았는데,
그동안 저장 형식을 건드린 라운드가 넷이다** — 27-3(좌표 반올림·raw 단순화),
34-8(잰 값의 정체성 저장), 32·39·40(손글씨·치수 구조), 그리고 겹·채움 구조.
그린 것이 안 열리면 나머지 전부가 무의미하다. 다른 결함은 다시 그리면 되지만 이건 안 된다.

## §0 현황 확인 — 고치기 전에 먼저 보고하라 (D-2)

아래를 확인해서 **작업 전에** 결과를 남겨라. 이 라운드의 갈래가 여기서 정해진다.

1. **지금 저장이 어디에 어떻게 되는가.** 27-3의 「utf16 기준 상한」 언급으로 보아
   localStorage로 추정되는데, 확인하라. 상한이 실제로 몇 바이트인가.
2. **자동저장이 있는가.** 그리다가 탭을 닫으면 무엇이 남는가. 지금 이 순간
   사용자의 그림이 어떤 조건에서 사라질 수 있는지를 정확히 적어라.
3. **문서에 이름·식별자가 있는가.** 여러 문서를 구분하는 열쇠가 지금 무엇인가.
4. **다시 실행(redo)이 있는가.** 이 라운드에서 고치지 말고 확인만 — 44가 쓸 정보다.
5. 저장소에 **옛 형식의 저장 파일 픽스처**가 있는가 (하위 호환 검증에 쓴다).

## 43-1 저장 왕복 검증 ⚠ 최우선

**팔을 만들어라.** 현재 존재하는 **모든** 데이터 종류를 담은 픽스처 —
획(종이·겹·옐로 각각), 자립 3D, 치수(손글씨·수정된 것), 잰 값(정체성 저장),
축척, 채움/구멍, 장면(시점 저장), 필압 원값, 겹의 씨앗 —
를 저장 → 로드 → 재저장했을 때 **두 직렬화가 바이트로 동일**해야 한다.

- 데이터 종류 목록은 types.ts에서 **전수로** 뽑아라. 기억으로 나열하지 마라.
  빠진 종류가 있으면 그게 바로 왕복에서 조용히 사라지는 후보다
- 27-3 무회귀: 저장 → 열기 → 저장 5회 반복에서 크기와 좌표가 더는 안 변한다
  (raw 단순화는 커밋 시 한 번뿐이어야 한다 — 세대 손실 금지)
- **하위 호환**: §0-5의 옛 픽스처가 열린다. 없으면 git 이력에서 각 형식 변경 직전
  커밋의 저장물을 만들어 픽스처로 굳혀라 — 이후 라운드가 계속 쓸 재산이다

**깨진 파일 열기.** 저장물이 잘렸거나 필드가 빠졌을 때 **조용히 빈 문서를 열지 마라.**
읽을 수 있는 데까지 읽고, 무엇을 못 읽었는지 알린다. 전부 버리는 것과 조용히 일부만
여는 것 둘 다 금지다.

## 43-2 자동저장과 복구

- 커밋(획·지움·치수 등 문서가 바뀌는 모든 사건)마다 저장한다. 주기가 아니라 **사건**이다.
  성능이 걸리면 짧은 지연 병합(debounce)은 허용 — 값은 상수로
- 탭을 닫고 다시 열면 마지막 커밋 상태 그대로다
- 강제 종료(크래시) 후에도 같다 — 복구 픽스처를 실제로 만들어 검증하라
- 저장 실패(용량 초과 등)는 **그 순간 알린다.** 조용히 잃는 것이 최악이다.
  문구는 짧게(R4)

## 43-3 이름

- 문서에 이름을 준다. 기본값은 만든 날짜·시각 기반 — 「제목 없음 1」보다 낫다
- 파일 패널에서 바꾼다. 화면 문구 규칙(R4) 준수
- 이름은 식별자가 아니다 — 내부 열쇠는 별도의 불변 id로 두고, 이름 변경이
  다른 데이터를 건드리지 않는다

## 43-4 최근 드로잉과 썸네일

- **저장 시점의 화면을 썸네일로 굽는다.** UI(리본·패널) 없이 도면만 —
  화면 복사 경로가 이미 있으니 재사용하라
- 파일 패널에 최근 드로잉 목록: 썸네일 · 이름 · 마지막 수정. 최신순
- 누르면 열린다. 열기 전에 현재 문서를 자동저장한다 (잃지 않는다)
- 지우기는 확인을 거친다 (되돌릴 수 없는 것 — R4 예외 규칙대로 무엇이 지워지는지 말한다)
- **썸네일을 문서 JSON 안에 넣지 마라.** 별도 항목으로 저장한다 — 문서 크기가
  이미지 크기로 오염되면 27-3의 절감이 무의미해진다

## 43-5 저장소 — §0-1의 결과에 따라

localStorage가 맞다면: 여러 문서 + 썸네일(이미지)을 담기엔 상한이 안 맞을
가능성이 크다. 그 경우 **IndexedDB로 이전**하되:

- 기존 localStorage의 문서를 **먼저 읽어 옮기고, 성공을 확인한 뒤에만** 옛것을 지운다.
  옮기다 실패하면 옛것이 그대로 남아 있어야 한다 (이전은 복사 → 검증 → 삭제 순서다)
- 이전 후 왕복 팔(43-1)을 새 저장소에서 다시 돌린다
- 상한 근처 거동: 큰 문서 여럿일 때 무엇이 일어나는지 실제로 재라

상한이 충분하면 이전하지 마라 — 필요 없는 이주는 위험만 산다. 판단 근거를 보고에 남겨라.

## 하지 말 것

- **저장 형식을 이참에 「개선」하지 마라.** 38(장면 개명)이 키를 바꿀 예정이라
  이중 변경이 된다. 이 라운드는 왕복·안전·목록만이다
- 썸네일 화질을 올리느라 용량을 키우지 마라 — 목록에서 알아볼 크기면 된다
- 새 패널을 만들지 마라 — 파일 패널 안이다 (자리 문제, 그리고 R5)
- redo를 이 라운드에서 만들지 마라 — 44의 몫이다

## 게이트

- 왕복: 전 데이터 종류 픽스처의 저장 → 로드 → 재저장이 바이트 동일
- 세대: 5회 반복 저장에서 크기·좌표 불변
- 하위 호환: 옛 형식 픽스처가 열린다 (형식 변경 지점마다 하나씩)
- 복구: 획 → 강제 종료 → 다시 열기 → 그대로 (마지막 커밋까지)
- 썸네일: 저장 후 목록에 뜨고, 그 시점 도면과 일치하며, UI가 안 찍혀 있다
- 열기 전 자동저장: 다른 문서를 열어도 현재 문서가 안 사라진다
- 깨진 파일: 잘린 저장물이 「읽은 데까지 + 알림」으로 열린다
- (이전했다면) 이전 실패 시 옛 데이터가 살아 있다 — 실패를 실제로 일으켜 확인하라
