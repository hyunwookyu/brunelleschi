# 지시 원문 — 17차 (2026-08-19)

**이 파일은 사람이 준 지시의 원문이다.** 16차부터의 규약: 압축본이 아니라 원문을 둔다
(요약만 남기면 다음 세션이 «다섯 중 빠진 것이 있는가»를 판정할 자료가 없다 —
16차 리뷰어가 그 자리를 지적했고, 17차 리뷰어 [12]가 이 회차에 같은 지적을 했다).

⚠ 아래는 사람이 준 메시지를 **그대로** 옮긴 것이다. 들여쓰기·강조·줄바꿈을 보존한다.

```
════════════════════════════════════════
0. 버전 표시와 갱신 (첫 일)
════════════════════════════════════════

브라우저에서 업데이트가 안 돼 옛 번들이 계속 나온다.
새로고침 여러 번으로도 안 바뀌었고, 캐시를 지워야 했다.

0-1. 버전 표시
  화면 어딘가에 빌드 식별자를 둔다.
  **커밋 해시 앞 7자 + 빌드 시각**이면 충분하다.
  하단바 구석이나 정보 패널에 작게.

  빌드 시각에 주입한다 — vite define이나 빌드 스크립트에서
  git rev-parse --short HEAD를 읽어 상수로 박는다.
  package.json 버전은 수동이라 안 맞는다.

  **표시가 있어야 "업데이트가 안 된다"를 확인할 수 있다.**
  지금은 화면만 보고는 알 방법이 없다.

0-2. 서비스 워커 갱신
  **표시만으로는 안 고쳐진다.** PWA가 옛 번들을 주는 것이 원인이다.

  a. 현재 sw.js의 캐시 전략을 확인한다.
     cache-first면 새 빌드가 안 나간다.
  b. **앱 셸은 network-first 또는 stale-while-revalidate로 바꾼다.**
     오프라인은 유지하되 온라인이면 새 것을 받는다.
  c. 빌드마다 캐시 이름에 해시를 넣어 옛 캐시를 무효화한다.
  d. skipWaiting + clients.claim으로 새 워커가 즉시 인계받게 한다.
     지금은 탭을 전부 닫아야 바뀔 수 있다.

0-3. 갱신 알림
  새 버전이 있으면 화면에 알린다 — "새 버전이 있습니다. 새로고침"
  누르면 워커를 교체하고 다시 로드한다.
  이게 표준 PWA 관행이고 사용자가 캐시를 지울 일이 없어진다.

0-4. 회귀 팔
  빌드를 두 번 하고 두 번째가 실제로 나가는지 확인한다.
  e2e에서 서비스 워커 등록 후 새 빌드를 배포하고
  갱신이 걸리는지. static_deploy.spec에 붙인다.

0-5. 배포 후 확인 절차를 README에 적는다
  버전 표시를 보고 커밋 해시가 맞는지 확인하는 것.
  안 맞으면 갱신 알림을 기다리거나 캐시를 지운다.
```

## 문면 대조 (17차 항목 0 마감 시점)

| 0-1 «커밋 해시 앞 7자 + 빌드 시각» · «하단바 구석이나 정보 패널에 작게» | `git rev-parse --short=7 HEAD` + ISO 시각을 `define`으로. **하단바 오른쪽 구석**에 11px | 없음 |
| 0-1 «vite define이나 빌드 스크립트에서» · «package.json 버전은 수동이라 안 맞는다» | vite `define`. `package.json`의 `version`은 안 쓴다(기각 사유를 D-L108에) | 없음 |
| 0-2a «현재 sw.js의 캐시 전략을 확인한다. cache-first면 새 빌드가 안 나간다» | 확인했다 — **전부 cache-first였다.** 그리고 **원인이 하나 더 있었다**(판본이 파일 이름 목록의 해시라 `l.html`만 고친 배포는 `sw.js`가 바이트까지 같아진다) | 없음(지시가 짚은 것 + 하나 더) |
| 0-2b «앱 셸은 network-first 또는 stale-while-revalidate» · «오프라인은 유지» | 문서 network-first · 스크립트·스타일 SWR · 나머지 cache-first. 오프라인 팔(③)은 그대로 통과 | 없음 |
| 0-2c «빌드마다 캐시 이름에 해시를 넣어 옛 캐시를 무효화» | 판본에 **커밋·빌드 시각**을 넣었다(이름 목록만으로는 안 바뀌는 경우가 이 고장의 절반이었다). **무효화를 원장이 든다**(2차 리뷰어 [13]): ④가 재배포 전후의 `caches.keys()`를 적고, 이름이 바뀌며 하나만 남는 것을 단언한다(`sw_update.gate.result.caches_before`·`caches_after`) | 없음 — ⚠ 초판은 «`activate`가 지운다»는 **코드 독해**뿐이었다(#25). 2차에서 관측으로 바꿨다 |
| 0-2d «skipWaiting + clients.claim» | **이미 있었다** — 그대로 둔다. 그래서 `registration.waiting`이 거의 안 보이고, 그 사실이 0-3의 구현을 정했다 | 없음(이 항목이 새로 넣은 것은 아니다 — 그 사실을 적는다) |
