# §0 대기를 «문서»가 아니라 «도구»로 막는다

73 §0 ㉡이 PITFALLS에 「대기는 동시에 하나 · 20분 상한」을 박았다. 그 뒤 74에서 **또 났다** — 「Wait for ledger rerun」 둘이 각각 10시간 8분 · 9시간 58분. 문서로는 안 막힌다.

```
㉠ 대기 명령은 상한을 «자기가» 들고 있어야 한다.
   맨손 `while … sleep`, 맨손 `wait` 금지. 반드시 `timeout <초> …` 또는 tools/의 대기 도우미(상한 내장)를 쓴다
㉡ 마감 점검(selfcheck)에 grep 한 줄: 이 라운드가 실행한 명령에 상한 없는 대기가 있으면 **빨강**
㉢ 착수 표의 「도는 백그라운드 0」을 마감에서 **한 번 더** 값으로 (74는 착수에만 적었다)
```
**또 하나 — 74의 자백에서 온 규칙**: 세 팔이 굽기와 저장을 애초에 못 견줬다(팔의 창에 `bake.commit`이 0회였다 — 경쟁자가 표에 없었다). `docs/CLOSING.md`에 한 줄: **「팔을 세울 때 경쟁자가 그 창에 안 들어오면 그것은 팔이 아니다 — 각 팔의 표에 경쟁 표식의 호출 수를 같이 낸다.」**

**게이트**: 세 문면 · selfcheck가 일부러 넣은 맨손 대기를 빨강으로 잡는다(반증) · 이 라운드의 대기 전부에 상한이 붙어 있다(값).

# §1 자르는 단위를 «획»에서 «점 구간»으로 (싼 쪽 먼저)

**원인은 코드에 있다**(`render3d.ts` 1357~1363):
```
while (P.done < P.strokes.length) {
  if (… && P.done > 0 && performance.now() - t0Frame > budgetMs) break   ← 검사는 획 «앞»에서만
  appendMarkOnTex(…)                                                     ← 획 하나를 통째로 (안 쪼개진다)
  P.done++
}
```
예산(4ms/12ms)이 있어도 **최소 단위가 획 하나**라 못 끊는다. 2048 면의 긴 붓 획 하나는 도장이 수백 개고 그것이 한 덩어리다 — 74가 잰 **861.8ms**가 그것이다. 무빙크패드는 컨테이너보다 느리니 거기서 몇 배가 되고, 그것이 영상의 fps 1 구간이다.

**고침**: 획을 **점 구간**으로 나눠 얹는다. 새 기계가 아니다 — 66의 초안 경로가 이미 «새 점만» 먹이는 꼴이다(`draftFeedSeam` · `PaintRenderer.draftFeed`).
```
appendMarkSeam / appendMarkOnTex 에 «점 구간»(from, to)을 준다.
  · 이어 굽는 장부 P가 {획 차례 done, 그 획 안의 점 차례 dotDone}을 든다
  · 예산 검사를 while 안쪽(구간마다)으로 옮긴다 — 한 구간은 짧게(값으로 정한다: 도장 N개 또는 점 M개)
  · 구간 경계가 그림을 바꾸면 안 된다 — 이어 그은 것과 한 번에 그은 것의 픽셀이 같아야 한다(엔진의 층은 이미 그 성질을 갖는다 · 66이 그것으로 산다)
```
⚠ **되돌리기·지우개가 이어 굽는 중에 오면** 지금처럼 처음부터 다시 굽는다(`sliceRestarts` — 72의 그 자리). 점 구간이 되어도 그 규약은 그대로다.

**게이트**
- 단일 `bake.commit` 호출 최대 **≤ 예산 × 2**(값 · 지금 861.8ms) · 몸짓 중 멈춤 ≥200ms 횟수 전/후.
- **픽셀 항등**: 구간으로 이어 구운 면 == 한 번에 구운 면(해시 · 65 ①의 자 그대로) · 구간 크기를 1·4·전량으로 바꿔도 같은 해시(반증).
- 결정론(같은 입력 두 번 == 같은 픽셀) · 66 이동량 0 · 59 미리보기==확정본 무회귀.
- **수리 전 빨강**을 먼저 값으로(73 §0 ㉠) — 지금 판에서 「단일 최대 ≤ 예산×2」가 실제로 빨간지.

# §2 그래도 남으면 — 굽기를 Worker로 (72 §1 ㉠)

§1 뒤에도 단일 호출이 예산을 크게 넘거나 몸짓 중 멈춤이 안 사라지면 그때 간다. **§1이 게이트를 넘기면 이 절은 안 한다**(값으로 그 사실을 적고 이월).
- `Worker + OffscreenCanvas`. 엔진은 순수 TS + 캔버스 2D라 옮겨진다. 없는 환경은 §1의 시간 분할이 그대로 받는다.
- 두 경로가 **같은 함수**를 부른다 — 결과 픽셀 해시 동일이 게이트(72 §1 문면 그대로). 시드는 획 id(63).
- 굽는 동안 화면은 **직전 텍스처**를 그대로 띄운다(빈 프레임 0).

**게이트**: 72 §1의 것 그대로 + 두 경로 해시 동일 + 메인 최장 차단(몸짓 중) 값.

# §3 열기 — 굽힌 그림 캐시 (72 §4 ㉡)

열기 4,769ms 중 **4,759.8ms(99.8%)가 굽기**다. 파싱·세우기는 합쳐 9ms라 손댈 자리가 아니다(§3-2 획 단위 저장은 이 라운드에서 **안 한다** — 74가 지목 안 했다).
- (면, 쪽, 획 sigs 해시, 단계)를 열쇠로 **굽힌 비트맵**을 IndexedDB에 둔다(`store.ts`의 그 DB · 별도 저장소 · 문서 형식 무변 — 캐시다, 정본이 아니다).
- 열 때 열쇠가 맞으면 **굽지 않고 올린다**. 안 맞으면 굽는다 — 캐시가 틀린 그림을 보이는 길은 없다(해시가 열쇠).
- 상한(문서당 값)을 넘으면 오래된 것부터 버린다. 캐시가 비어도 지금과 똑같이 동작한다.

**게이트**: 열기 전/후(캐시 없음 · 있음) · 캐시로 올린 면의 픽셀 == 구운 면의 픽셀(해시) · 열쇠 불일치 → 재굽기(반증) · 캐시 지운 뒤 무회귀 · 저장 왕복 5/5 · KEY_ORDER 무변.

# §4 실기기 자리 — 만들고 넘어간다

74가 실기기 재측정을 못 해 게이트 둘이 미달로 남았다. 이 라운드도 **기다리지 않는다**. 대신 사람이 한 번 녹화하면 바로 읽히게 둔다.
- `?perf=1` 화면의 멈춤 목록에 **표식 이름**이 뜨는지 확인(74가 심었다) · 열기 세 몫도 그 화면에서 읽히게.
- 보고에 「사람이 무빙크패드에서 확인할 것」을 세 줄로: 몸짓 중 멈춤 횟수 · 열기 ms · 목록의 첫 이름.
