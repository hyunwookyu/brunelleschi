# web2-61 — 칠을 p5.brush로 옮긴다

> **Fable 5.1.** 이 라운드는 **값을 찾는 라운드가 아니다.** 엔진을 바꾸는 라운드다.

## 왜 — 사람의 물음이 옳다

> 「왜 우리가 이걸 설계해야 하는가? 프로크리에이트나 포토샵이든 다른 어떤 상용프로그램이나
> 오픈소스든 퀄리티 좋은 수많은 칠·브러시·마커 도구가 있는데 우리가 이 값을 시간 들여
> 찾아야 하나?」

**아니다.** 45·46·51·58이 브러시 엔진을 손으로 지어 왔고, 아무도 「브러시 엔진을 직접 써야
하는가」를 묻지 않았다. 브러시 엔진은 전문 분야이고 여러 해가 걸리는 일이다.

## ⛳ 그리고 더 나쁜 사실 — **좋은 엔진이 이미 저장소에 있다**

저장소에서 확인한 것이다(추측 아님).

```
선 그리기   src/app/brushlayer.ts  →  p5.brush 로 그린다 (web2-11 · 2024)
칠하기      src/core/facetex.ts    →  손으로 짠 도장 루프

사람의 불만은 «언제나 칠»이었다.
```

**좋은 렌더러가 이미 깔려 있고 배선돼 있는데 칠만 그걸 안 쓴다.**

### 확인된 사실 — 전부 저장소·패키지에서 읽었다

```
라이선스     MIT · 이미 package.json의 의존성이다 (p5.brush 2.2.2 · 2026-08 최신)
배선         이미 돼 있다 — brushlayer.ts가 standalone 빌드를 쓴다 (p5 불요 · WebGL2)
타입         src/types/p5brush.d.ts 를 «우리가 이미 썼다»
점별 압력    spline(pts: [x, y, pressure][], curvature?) — 그 d.ts에 이미 적혀 있다
             ⚠ 내가 앞서 「압력이 실시간이 아니라 못 쓴다」고 한 것은 «틀렸다».
             그리고 brushlayer는 이미 마디마다 set()+line()으로 압력을 싣고 있다
내장 브러시  2B · HB · 2H · cpencil(색연필) · charcoal · marker · pen · rotring · spray
커스텀       add(name, params) — 46이 이미 marker46 을 그렇게 만들었다
스트로크 버퍼 이미 있다 (glMask 프레임버퍼에 모아 «한 번» 합성 — 59가 손으로 만든 그것)
팁           다섯 종 · 이미지 팁 지원 (58-2가 푼 금지의 자리)
캔버스       createCanvas(w,h) · load(canvas) — 굽는 캔버스를 지정할 길이 있다
```

## 지금 자국이 왜 나쁜지 — **그려서 봤다** (2026-09-04)

라운드를 쓰기 전에 앱을 띄우고 넷을 실제로 그어 사진을 찍었다.

```
붓      브러시가 아니라 «동그라미가 줄지어 있는 것». 빗살마다 따로 도장을 찍고 안 뭉친다
마커    넷 중 유일하게 볼 만하다. 다만 성격 없는 회색 띠다
색연필  구멍이 «정사각 격자 위의 완벽한 원». 물방울 무늬로 보인다
연필    «사각 모자이크». 결이 축 정렬 정사각 격자이고 칸마다 값이 하나다
```

**넷의 뿌리가 하나다 — 결이 격자다. 게다가 칸 크기가 붓 굵기를 따라간다**
(그래서 굵게 그으면 모자이크가 커진다. 60이 사람에게 물은 「결 칸의 뜻」이 이것이고,
답은 **틀렸다**이다 — 결은 종이의 성질이라 굵기와 무관해야 한다).

⚠ **이 라운드는 그 격자를 «고치지» 않는다. 그 코드를 «버린다».**

## ⛳ 62가 «바로» 온다 — 이음매를 하나로 만들어라 (사람 지시 2026-09-04)

사람이 정했다: **61(p5.brush) 배포 → 곧바로 62(libmypaint 이식).**
p5.brush로 충분한지 «보고 나서» 정하는 것이 아니라, 둘 다 한다.

그러므로 이 라운드의 산출물에 하나가 더 붙는다.

> **칠 렌더러를 «이음매 하나»로 만들어라.**
> 들어가는 것: 점렬 + 점별 압력 + 색 + 굵기(px) + 시드 + 대상 캔버스
> 나오는 것: 그 캔버스에 그려진 자국
> **엔진은 그 뒤에 숨는다.** 62는 그 뒤만 갈아끼운다.

⚠ p5.brush의 WebGL 배선이 이음매 «밖»으로 새어 나오면 62가 그것까지 뜯게 된다.
호출하는 쪽(facetex·작업대·팔)이 p5.brush를 직접 알면 안 된다.

## 할 것

**칠 넷(붓·마커·색연필·연필)을 p5.brush로 그린다.**
`facetex.ts`의 손으로 짠 도장 루프(`stamp`·`paintMark`의 세 모드)를 대체한다.

각 도구가 어느 내장 브러시에서 출발할지는 세션이 정하되, **출발점은 내장 브러시여야 하고
새로 짓지 않는다**:

```
연필    2B · HB · 2H (등급에 따라)
색연필  cpencil
마커    marker (46의 marker46 정의가 이미 있다 — 그 자리를 잇는다)
붓      charcoal 또는 add()로 정의한 값 한 벌
```

바뀐다. `KEY_ORDER` 무변이 게이트다.

## ⚑ 재서 정할 것 — 굽는 길

p5.brush는 WebGL2로 자기 캔버스에 그린다. 우리는 **면 텍스처(2D 캔버스)**에 구워야 한다.

- `createCanvas` / `load(canvas)`로 오프스크린에 그리고 `drawImage`로 면 텍스처에 옮기는
  길이 되는가
- 모듈 전역 상태가 있으면 **면 여럿을 연달아 굽는 것**이 안전한가(순차 굽기 + 복사)
- 성능: 면 20개 · 획 40개에서 굽기 시간

**되면 그대로 가고, 안 되면 멈추고 보고하라**(사슬 멈춤 조건 ③).
⛔ 안 된다고 손으로 짠 엔진으로 돌아가지 마라 — 그때는 사람이 판단한다.

## 게이트 — **눈으로 갈리는 것을 값으로**

이 라운드의 게이트는 「지금 나쁜 것 넷이 값으로 사라졌는가」다.

```
① 격자 주기        획을 가로지르는 알파 프로파일에서 «결 칸 주기»의 진폭 → 0에 가깝다
                   (지금 연필의 모자이크가 그 주기다. 수리 전 값을 pre 원장에 갈라 남겨라)
② 도장 주기        같은 방법으로 «도장 간격 주기»의 진폭 → 0에 가깝다 (지금 붓의 점열)
③ 구멍의 규칙성    색연필 빈 픽셀의 «위치»가 격자에 안 실린다(자기상관 봉우리가 없다)
④ 굵기 무관        굵기를 2배로 해도 ①의 주기가 «안» 따라 커진다 (결이 종이의 성질임)
⑤ 넷이 갈린다      같은 압력·속도로 넷을 그어 통계가 갈린다(알파 분포·가장자리 거칠기·덮임률)
```

**그리고 ⛳ 사진을 남겨라.**

> 이 라운드는 브러시 넷 × 획 셋(직선·물결·자기교차)을 그린 **PNG를 산출물로 남긴다.**
> 파일은 `web2/shots/61-<brush>.png`. 마감 보고에 그 경로를 적어라.

**이유**: 지금까지 게이트 열두 개가 통과하는데 사람이 보면 나빴다. **재는 대상이 틀렸다**
(#87). 사진은 재는 대상을 사람의 눈에 맞춘다. 앞으로 칠·자국을 건드리는 라운드는 전부
이 산출물을 낸다.

무회귀: 50·55·56·59의 게이트 전부 · `roundtrip43` ② · 성능.

## 하지 말 것

- **값을 찾느라 시간을 쓰지 마라.** 내장 브러시에서 출발하고, 미세 조정은 사람 몫이다
- **손으로 짠 도장 루프를 «고치지» 마라 — 버려라**
- **libmypaint를 이식하지 마라** — **62가 한다.** 이 라운드는 p5.brush뿐이다
- **저장 형식·정본 구조를 바꾸지 마라**
- GPL 코드(Krita·GIMP·MyPaint 앱) · mixbox(CC BY-NC) ⛔
- 면·두께·접합·내보내기에 손대지 마라

## 작업대(58-5)는 버리지 않는다 — 역할이 바뀐다

「값을 찾는 곳」이 아니라 **「고른 브러시를 확인하고 미세 조정하는 곳」**이다.
손잡이는 p5.brush의 매개변수에 붙는다. 「값 꺼내기」·「가져온다」·「굳힌다」는 그대로 산다.
