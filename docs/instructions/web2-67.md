## 67-0-1 상한 «알림»이 멈추게 한다

`FACETEX_MAX_PX = 1024`. 사람을 멈추는 것은 상한이 아니라 **한 붓마다 뜨는 토스트**다
(59-1의 「조용히 뭉개지 마라」 — 뜻은 맞았고 «형태»가 틀렸다).

```
토스트 → 칠 패널 구석의 «작은 표식». 걸려 있는 동안 켜지고, 안 걸리면 꺼진다. 한 줄 설명은 호버에
상한 1024 → 2048. 면당 16 MB — 65의 LRU(게이트 ⑦)가 있으니 된다. 메모리 상한 값을 다시 재라
```
**게이트**: 큰 면에서 획 20개를 그어도 토스트 0회 · 표식은 걸린 동안만 · 2048에서 65 게이트 ⑦(메모리) 무회귀.

## 67-0-2 컬러피커 — 누른 영역을 떼기 전까지 «잠근다»

`main.ts` `wheelPick`: `wheelDrag`에 누른 영역(`ring`/`sv`)을 저장하고는 **안 쓴다** —
이동마다 `partAt`을 다시 계산한다. 그래서 사각형 코너에서 링으로 넘어가면 색상이 바뀐다.

```
누른 영역을 떼기 전까지 «그 영역»으로 판정한다. 좌표는 그 영역 안으로 잠근다(clamp)
사각형 밖으로 나가도 사각형의 가장자리 값이다. 링 밖으로 나가도 링의 각도다
```
**게이트**: 사각형 코너에서 시작해 링을 가로지르는 드래그에서 «색상(h)이 불변» · 반대로 링에서
시작해 사각형을 가로지르면 «채도·명도(s,v)가 불변» · 반증: 잠금을 끄면 옛 거동.

## 67-0-3 점군 → 연속

SV 사각형이 **2px 칸으로 `fillRect`**된다(`step = 2`). 사각형 ~60px → 30×30 = 색 900개.
그라디언트 둘 겹치기(색상→흰 가로 · 투명→검정 세로)로 연속으로. 링은 그대로(360 호).
휠 전체를 키워라 — 지금 136px. 프로크리에이트급 크기를 실측해서 값으로.

**게이트**: 사각형 안 서로 다른 색 수가 화면 픽셀 수와 같다(점군 아님) · 크기 값.

## 67-0-4 자리와 툴팁

옆으로 펼쳐지지 말고 **세로로, 패널 안에서** 열린다. 툴팁 없음.
**게이트**: 휠이 열려도 캔버스를 가리는 면적이 패널 폭을 안 넘는다(값) · 34-0 다시.

## 67-0-5 되돌리기·다시하기가 칠에 «실제로» 먹는가

사람 판정: 「**칠하기도 지우개나 실행취소·다시실행이 있어야지.**」

되돌리기(`btn-undo`)·다시하기는 있다. **칠 획에 먹는지는 아무도 확인 안 했다.**
칠 획도 `doc.strokes`에 있으니 원리상 먹어야 하지만, 칠 패널이 그 단추를 가리거나
칠 도구 상태에서 안 닿거나 되돌린 뒤 텍스처가 안 다시 굽히는(65의 캐시 키) 길이 있다.

**D-2**: 칠 획 셋 → 되돌리기 → 화면에서 «사라지는가»(픽셀) → 다시하기 → 돌아오는가.
칠 패널이 열린 채로 단추가 «닿는가»(elementFromPoint).
**게이트**: 되돌리기·다시하기가 칠 획에 픽셀로 먹는다 · 칠 패널이 열린 채로 닿는다 ·
되돌린 뒤 65의 픽셀 항등(누적 == 전량) 무회귀.

## 67-0-6 칠 지우개

사람이 정했다(2026-09-05): 「**지우개도 67에 넣고 한 번에 완주하도록.**」

**만드는 법 — 새 개념이 아니다.**

```
mypaint의 `eraser` 설정(0~1)이 이미 있다. 62가 이식했다 — brushmodes의 Normal_and_Eraser 경로
지우개 획 = «덮임을 빼는 획». eraser=1인 브러시로 그은 획이다
정본은 여전히 «획 목록»이다 — 지우개 획도 획이다. 굽을 때 순서대로 빼진다
```

- **저장**: 획에 지우개 표식 하나. `KEY_ORDER`에 등재(43 게이트 ②). 옛 문서는 표식 없음 = 칠
- **65의 누적과 맞물린다**: 지우개 획도 «얹기»다(빼는 얹기). 전량 재굽기가 안 필요하다.
  ⚠ «획 사이 순서»가 결과를 정하므로 65의 픽셀 항등 게이트(누적 == 전량)가 이것도 덮어야 한다
- **크기**: 슬라이더(58의 규칙 — 칠 도구다). 최대는 붓과 같다
- **부드러움**: 경도 축 하나(딱딱한 / 부드러운). 마른 매체는 딱딱한 쪽이 기본
- **자리**: 칠 패널의 즐겨찾기 옆 «고정 칸» — 지우개는 즐겨찾기가 아니라 «언제나 있는 것»이다
  (선 그리기의 지우개 둘이 트레이 밖 고정인 것과 같은 규약)
- **손가락으로 지우기는 안 한다** — 손가락은 고르기다(§1). 지우개도 «펜»이다
- **몸짓**: 뒷꼭지(eraser 버튼)가 있는 스타일러스면 그것이 지우개다 — `pointerType`·`button`으로 판별.
  없으면 패널의 지우개 칸

**게이트**
```
① 지운 자리의 덮임이 «빠진다»(알파 감소 · 값으로) · 다른 면은 무변
② 순서: 칠→지우기→칠 이 칠→칠→지우기 와 다른 결과 (순서가 실린다는 반증)
③ 되돌리기가 지우개 획에도 먹는다 (67-0-5와 같은 자)
④ 65 픽셀 항등이 지우개를 포함해 «누적 == 전량» (도구 전수 × 지우개 섞기)
⑤ 저장 왕복 — 지우개 표식이 KEY_ORDER에 · 옛 문서 이주 없음(표식 없음 = 칠)
⑥ 뒷꼭지 지우개 — 있는 기기에서 그 버튼이 지우개(값) · 없는 기기에서 패널 칸
```
**사진**: `67-eraser.png` — 칠한 면에 지우개로 글자 하나 써 놓은 것.

⚠ 68(필통)이 이 패널을 다시 짠다 — §0의 다른 항목은 «결함»만 고치고 구조는 안 건드린다.
지우개 칸의 «자리»만 68이 다시 볼 수 있다.

# §1 몸짓을 가른다 — 이 라운드의 본체

## 왜

사람 판정: 「**나는 그리려고 하는 건데 면이 선택되어버리는 문제.** 면 이어그리기는 방법을
또 찾아봐야 한다.」

**원인**: 면 고르기와 칠하기가 **같은 몸짓(펜 한 붓)**을 거리 문턱(`PAINT64_TAP_MAX_PX = 6`)
으로 나눠 쓴다. 짧은 획이 면 선택이 되고, 이어 그리려면 먼저 골라야 하는데 그 고르기가
그리기와 부딪힌다.

**답**: Feather와 같다 — 몸짓을 아예 갈라놓는다.

```
펜 한 붓          언제나 «칠»이다. 길이와 무관. 거리 문턱이 «없어진다»
손가락 탭         면을 «고른다». 또 탭하면 더해진다. 빈 곳 탭이면 풀린다
손가락 드래그      종전대로 — 한 손가락 궤도 · 두 손가락 이동 · 핀치 줌 (30-1 무변)
```

⚠ **팜 리젝션이 이미 펜과 손가락을 가르고 있다**(26). 그 배선을 쓴다. 새로 만들지 마라.

## 67-1 펜 한 붓은 언제나 칠이다

- `PAINT64_TAP_MAX_PX` 판정을 펜 입력에서 **뺀다.** 펜은 점 하나를 찍어도 칠이다
- ⚠ **마우스**(펜도 손가락도 아닌 입력)는 문턱을 «남기되» 올린다 — 6 → 12px.
  마우스는 손가락이 없으니 고르기와 그리기를 한 장치가 해야 한다. 값은 원장에
- 51의 Injector(탭으로 색 집기)가 이 문턱에 붙어 있었다면 **손가락 탭의 긴 누름**으로 옮겨라.
  ⚠ 44의 꾹 누름(잡기)·39의 꾹 누름(손글씨)은 «펜»이다 — 손가락 긴 누름은 비어 있는지
  먼저 확인하고, 비어 있지 않으면 보고하라(멈춤 조건 ③)

## 67-2 손가락 탭이 면을 고른다

- **탭**의 판정은 «움직인 거리»다(#93 — 시간이 아니다). 궤도 드래그와 갈리는 문턱을 값으로
- 칠 도구를 들었을 때만이다. 작도 중 손가락 탭은 종전대로(아무 일도 안 한다)
- 여럿 고르기·빈 곳 탭 풀기·「몇 장이 골라졌는가」 표시는 54-2의 것 그대로
- ⚠ 한 손가락 탭이 «궤도의 시작»으로 읽히면 안 된다 — 드래그가 문턱을 넘기 «전»에는
  아무것도 안 하고, 넘으면 궤도, 떼면 탭이다

## 67-3 면 이어그리기 — «이미 있는 것»으로 된다

54-2가 「고른 면 집합 안에서 획이 이어진다」를 넣어 놨다. 고르는 몸짓이 그리기와 안
부딪히는 순간 그것이 그냥 작동한다.

```
손가락으로 면 셋 탭  →  펜으로 쭉 이어 칠  →  세 면에 걸쳐 남는다
고른 면이 없으면    →  획이 시작한 면에만 (54-1 그대로)
```

⛔ **획을 면별 조각으로 쪼개지 마라**(3D 페인팅 앱 방식). 정본 구조와 저장이 바뀌는 큰 일이고,
위 방법으로 필요가 없어졌다. 나중에 필요해지면 그때 따로 연다.

**착수 전 확인(D-2)**: 54-2의 집합 안 이어그리기가 지금 «실제로» 도는지. 안 돌면 그것부터.

## 게이트

```
① 펜 점 하나가 칠이다        펜으로 «찍기»만 해도 자국이 남고 면은 안 골라진다 (전 도구)
② 손가락 탭이 면을 고른다     한 번 → 하나 · 또 → 더해짐 · 빈 곳 → 풀림 (값으로)
③ 궤도가 안 깨진다           손가락 드래그는 종전대로 궤도 · 탭과 갈리는 문턱 양쪽에서
④ 이어그리기                 면 셋을 고르고 한 획으로 가로지르면 «셋 다»에 남고 넷째는 0
⑤ 작도 중 무변               작도 도구에서 손가락 탭은 아무 일도 안 한다
⑥ 마우스 경로                 마우스는 문턱(12px)으로 종전 거동 · 값으로
⑦ 반증(D-3)                  펜/손가락 판별을 끄면 옛 충돌이 돌아온다
⑧ 34-0 다시                  몸짓 표가 바뀐다 — R1~R8 + 몸짓 줄 전수
```

**⛳ 사진**: `web2/shots/67-gestures.png` — 펜 점 / 손가락 탭 / 이어 칠한 셋 면.

# §2 낡은 그림 — 65가 남긴 회귀

65 보고: 「재료 면의 «줌 뒤 낡은 그림» — 갈림 자체는 수리 전과 같지만 **지속은 65가 바꿨다**
(pre는 다음 편집에서 나았고 post는 안 낫는다).」

**이건 65 게이트 ⑤(무회귀 트리거가 산다)가 새어나간 것이다.** 재료(rep)·계열(famBits) 경로가
새 캐시 키에 안 물렸다.

- **D-2**: 재료를 준 면에서 줌을 크게 바꾼 뒤 그림이 낡은 채 남는지 재현. 어느 트리거가 빠졌는지 값으로
- 고친다 — 재료·계열·해칭 변경이 그 (면,쪽)의 캐시 키에 «들어간다»
- **게이트**: 재료·해칭·줌 단계 변경 각각에서 «다시 굽는다» · 65 게이트 ①(픽셀 항등) 무회귀

⚠ 이 절은 §1과 다른 코드다. §1 먼저, 이건 뒤에.
