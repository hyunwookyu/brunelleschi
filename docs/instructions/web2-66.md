# §1 도장을 «다시» 찍지 않는다 — 이 라운드의 본체

## 진단 — 코드에서 확인했다 (추측 아님)

`app/render3d.ts`의 `applyPaintDraft`가 **포인터가 움직이는 매 프레임마다** 이렇게 한다.

```js
g.drawImage(e.base, 0, 0)                      // ① 1024² 캔버스를 통째로 복사
drawDraftOnTex(e.canvas, rf, e.box, e.level, mine, ...)  // ② 획을 «처음부터» 다시 그린다
e.tex.needsUpdate = true                       // ③ 1024² RGBA를 «전부» 업로드 (4 MB)
```

**증상 셋이 전부 여기서 나온다.**

```
초 단위 지연            ①+②+③이 매 프레임. ②는 획이 길어질수록 커진다
도장이 움직인다          ②가 매 프레임 «처음부터» 그리는데, 새 점이 들어오면 곡선 맞춤이
                       다시 되므로 «이미 지나간 자리»의 도장이 다른 자리에 다시 찍힌다
bbox만 알파가 뜬다      ①의 복사 + ②의 덧그리기가 그 사각에서만 다르게 끝난다
```

⚠ **도장 방식 자체는 바꾸지 않는다.** 질감 매체는 프로크리에이트·포토샵·MyPaint·크리타가
전부 도장이고, 외곽 폴리곤 방식은 결이 안 생긴다. **문제는 도장이 아니라 «다시 찍는 것»이다.**

## ⚠ 착수 전 — D-2로 값을 먼저 낸다

획을 **짧게 · 중간 · 길게**(점 20 · 100 · 400) 그으면서 값으로 재라.

```
(a) 프레임 시간(ms)                    획 길이에 비례하는가
(b) 프레임마다 «그린 도장 수»           새 도장만인가, 전부인가
(c) ⛳ 프레임 n → n+1에서 «이미 그려진» 도장의 위치 이동량(px)
       — 이것이 ④의 자다. 지금은 0이 아닐 것이다
(d) 업로드 바이트                      전체인가 부분인가
(e) 그리는 중 draft bbox 사각이 화면에서 보이는가(픽셀 대비)
```

**이 값이 pre 원장이고 게이트가 그것과 대조한다.**

## 고칠 것 셋

### ㉠ 경로를 얼린다 — 확정 구간과 잠정 구간

```
확정 구간   점 n-2까지. 도장이 «이미 놓였고 다시는 안 움직인다»
잠정 구간   마지막 두세 점. 이 부분만 매 프레임 다시 그린다
```

- 새 점이 들어와도 **확정 구간의 도장 위치·시드·압력이 바뀌지 않는다**
- 그래서 매 프레임 그리는 것은 **새 도장 몇 개**뿐이다

⚠ **곡선 맞춤은 «국소 지지»를 가진 것을 써라.** 새 점이 앞쪽 곡선을 바꾸면 얼릴 수가 없다.
Open Brush 개발 문서가 이 함정을 이름으로 적어 뒀다 — *「각 매듭이 국소 지지를 안 가지면
획 전체를 매번 다시 만들어야 한다」*. centripetal Catmull-Rom(α=0.5)은 네 점만 보므로
n-2까지가 확정이다.

⚠ **시드도 얼려라.** 도장의 난수(흔들림·결)가 프레임마다 다시 뽑히면 위치가 같아도 자국이
떨린다. 도장마다 «그 도장의 순번»으로 결정되는 시드여야 한다.

### ㉡ 획 버퍼 — 그리는 중인 획만 담는 «작은» 텍스처

```
크기      획의 bbox(자라면 키운다). 1024²가 아니다
합성      면 텍스처 = 확정본 + 획 버퍼.  뗄 때 한 번 구워 넣는다
```

- **1024² 복사(①)가 사라진다**
- ⚠ 62의 「획 버퍼 → over」 2단 합성과 **같은 것**이다. 새 개념이 아니다 —
  62는 그것을 «획 안 누적»을 막으려고 썼고, 여기서는 «비용»을 위해 같은 구조를 쓴다
- ⚠ **59의 「미리보기 == 확정본」을 깨지 마라.** 그리는 중 보이는 것과 뗄 때 구워지는 것이
  같아야 한다 — 게이트 ⑤가 그것을 잰다

### ㉢ 부분 업로드

새로 그려진 사각만 올린다. **65가 커밋 경로에 넣은 그 기제를 draft 경로에도** 넣는다.

⚠ 65가 three의 함정 둘에 걸렸다(#110) — `UNPACK_SKIP_*` × `FLIP_Y`, 그리고 `texStorage2D`가
텍스처를 첫 크기에 굳히는 것. **획 버퍼가 자라면 그 두 번째를 다시 밟는다.** 미리 막아라.

   프레임 n과 n+1에서 «확정 구간» 도장의 위치·시드가 «동일»하다. 이동량 0 (값으로)

# §3 작은 것 둘

## 66-3 칠 사양이 도구마다 나뉘어야 한다

사람 판정: 「**칠할 때 색이나 크기 등 사양값을 모든 칠 도구들이 공유하는 문제**
(도구별로 따로 저장되어 있어야지)」

지금은 브러시만 슬롯에 물리고 **색·크기·불투명도는 전역**이다.

```
뒤    즐겨찾기 슬롯마다 한 벌 — { 브러시, 색, 크기, 불투명도 }
      슬롯을 바꾸면 그 슬롯이 기억하던 값이 «같이» 온다
```

프로크리에이트가 브러시마다 크기를 기억하는 그것이다.
**기기에 남긴다**(문서가 아니다 — 52 프리셋의 그 자리). 저장 형식은 안 바뀐다.

**게이트**: 슬롯 A에서 색·크기를 바꾸고 B로 갔다가 A로 돌아오면 A의 값이다(전수) ·
새로 고쳐도 산다 · `KEY_ORDER` 무변.

## 66-4 「접는다」의 기준을 고친다 — R3 정정

사람 판정: 「면 자동 찾기 하려면 면 아이콘을 누르고 나서 자동찾기 누르면 **찾기 관련 패널이
사라져버려서 면 아이콘을 다시 눌러야 하는 번거로움**이 생긴다. 아마 이전에 **동작 하나
선택하면 그 패널을 접어버리라는 명령을 곧이곧대로 적용한 결과**인 듯」

**정확한 진단이다.** R3(「명령은 통을 접고, 상태 토글은 안 접는다」)의 뜻은 「끝났으면
치운다」인데, **자동찾기는 연달아 쓰는 명령**이다.

> **R3 정정 — 접는 기준은 「명령이냐」가 아니라 «그 뒤에 그 통을 또 쓸 것 같은가»다.**
> 연달아 쓰는 명령은 안 접는다.

- **34-0 대조표에 이 정정을 값으로 적어라**
- **연달아 쓰는 명령을 전수로 훑어라** — 자동찾기 말고도 있다.
  판별: 「이 명령을 두 번 연달아 쓰는 것이 자연스러운가」

**게이트**: 자동찾기를 연달아 세 번 눌러도 통이 열려 있다 · 한 번 쓰고 마는 명령은 종전대로
접힌다(전수 · 반증 포함) · 34-0 표 다시.
