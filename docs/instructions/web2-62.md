## ⛳ 합성 — 이 라운드의 제일 중요한 절

사람의 요구: **「겹쳤을 때 똑같이 합성 문제 발생하면 안 된다.」**
흰 테는 물성 문제가 아니라 **알파 처리 버그**다. 원인이 특정됐다.

### 흰 테가 생기는 이유 (제일 흔한 순)

```
① straight 알파 자료를 premultiplied인 것처럼 블렌드   ← 거의 확실히 이것이다
   (1,1,1,0) «투명한 흰색»을 ONE, ONE_MINUS_SRC_ALPHA로 섞으면
   ONE이 알파 0과 무관하게 흰 RGB를 «더한다». 즉시 흰 테
② gl.clearColor(1,1,1,0)                    ⛔ 언제나 (0,0,0,0)이다
③ 투명 텍셀을 가로지르는 이중선형 보간        PNG는 투명 부분에 흰색을 채운다
④ 같은 자료의 밉맵                           ⛔ straight 알파에 밉맵 만들지 마라
⑤ getImageData → 고침 → putImageData 왕복    알파 1/255에서 RGB 오차가 폭발한다
                                             ⛔ 합성 경로에서 ImageData를 왕복하지 마라
⑥ 감마 공간에서 un-premultiply               ⛔ 선형광에서만 나눈다
⑦ 이중 합성 · ⑧ 알파 0 근처의 스펙트럼 혼합
```

### 규약 — 이 라운드가 세우고 앞으로 안 깬다

```
· 전 구간 «선형광 premultiplied RGBA float». sRGB 변환은 «화면에 낼 때만»
· gl.clearColor(0,0,0,0) 예외 없음
· UNPACK_PREMULTIPLY_ALPHA_WEBGL = true 로 올린다 (PNG는 straight다)
· un-premultiply는 딱 두 곳에서만 — 안료 혼합, 파일 내보내기
· ⛳ 디버그 단언: 모든 텍셀에서 rgb ≤ a.   «이 한 줄이 이 버그를 처음부터 잡았을 것이다»
```

### 획 버퍼 — 획 «안»은 안 쌓이고 획 «사이»는 쌓인다

```
1단계  획 전용 버퍼에 도장을 모은다 (획 시작에 (0,0,0,0)으로 비운다)
       gl.blendFunc(gl.ONE_MINUS_DST_ALPHA, gl.ONE)
       → 아직 안 덮인 곳만 채운다. 알파가 1을 못 넘는다
       (p5.brush가 실제로 쓰는 그 조합이다 — 우리 발명이 아니다)
2단계  다 그은 획을 캔버스에 «한 번» 얹는다
       gl.blendFunc(gl.ONE, gl.ONE_MINUS_SRC_ALPHA)   premultiplied over
       → 획 사이 쌓임은 저절로 생긴다
⚠ 스머지가 표집하기 «전»에 반드시 1단계를 흘려보내라 — 안 그러면 붓이 자기 젖은 자국을
  물어서 획이 스스로 오염된다 (libmypaint가 get_color 전에 process_tile 하는 그 이유)
```

### 덮임(alpha)과 안료 농도는 «다른 것»이다 — 이게 핵심이다

```
알파   = 덮임.   이 픽셀의 몇 %를 새 물감이 닿았나. 기하다. over를 지배한다
혼합비 = 농도.   둘 다 있을 때 어떤 비율로 섞이나. Kubelka-Munk를 지배한다
```

**알파를 안료 농도로 먹이면 옅은 가장자리가 터진다.** libmypaint에 정답이 ISC로 있다
(`brushmodes.c` L333-410 · `draw_dab_pixels_BlendMode_Normal_and_Eraser_Paint`):

```
opa_out = opa_a2 + opa_b * dst.a       ← 그냥 Porter-Duff over. 안료가 «절대» 안 건드린다
fac_a   = opa_a / (opa_a + opa_b*dst.a) * srcA     ← 혼합비는 «밑에 실제로 있는 안료»로 정규화
dst.a == 0 이면 스펙트럼 경로를 «건너뛴다»          ← 저알파 흰 테가 여기서 대부분 사라진다
un-premultiply(선형) → 섞는다 → opa_out으로 다시 premultiply
그리고 저알파 보호막: spectral_blend_factor(dst.a)로 가산↔스펙트럼을 매끄럽게 섞는다
```

⛳ **libmypaint 저자들이 바로 그 「어두운 테」를 죽이려고 쓴 코드다. 그대로 옮겨라.**

기본 합성 연산은 **raphlinus/kubelka(MIT, 6줄)**로 시작한다 — 결합적이고, `t=0`에서
배경을 «정확히» 돌려주므로 흰 테가 구조적으로 불가능하다. 그 위에 `paint_mode` 브러시의
스펙트럼 경로를 얹는다.
