════════════════════════════════════════
web2-11 — 손을 그대로 받고, 종이처럼 그린다
════════════════════════════════════════
착수와 완료 시 화면에 한 줄 출력한다.
사람이 정한 것: 「화면 표현과 쓸 때의 감각(실제 종이에서 그리는 느낌)이 더 중요하다. 먼저 무겁더라도 좋은 걸 해봐야, 불편했을 때 고칠 수 있다.」 → 무게보다 느낌을 먼저 본다. 다만 되돌릴 수 있게 만든다.
⚠ 실기기는 Wacom MovinkPad Pro 14 — 안드로이드 15 · 14" OLED 2880×1800 · 120Hz · Wacom Pro Pen 3(EMR · 필압 8192 · 기울기 60°). 전용 지우개 펜(3E)이 곧 도착한다.
배포 지점 둘. 1부(입력)가 끝나면 배포하고, 2부(brush.js)가 끝나면 또 배포한다. 2부가 안 되더라도 1부는 사람 손에 있어야 한다.

════════════════════════════════════════
1부 — 입력 계층 (화면은 그대로여야 한다)
════════════════════════════════════════
⚠⚠ 1부의 검증 기준은 「화면이 지금과 같은가」다. 데이터만 더 받는다. 픽셀 팔이 그것을 지킨다. 화면이 달라졌으면 1부의 실패다.
왜 2부보다 먼저인가: 지금 필압은 획당 평균 하나(`mat.press`)다. 그 상태로 brush.js 를 얹으면 질감은 나와도 누르는 세기에 선이 반응하지 않는다 — 종이 느낌의 절반이 빠진 채로 보게 되고, brush.js 를 제대로 시험한 것이 아니게 된다.

1-a. `getCoalescedEvents()`
120Hz 에 EMR 펜이면 한 프레임에 이벤트가 여러 개 온다. 지금 안 써서 중간 점을 버린다.
* 없는 브라우저는 `[e]` 로 떨어진다.
* 버려지던 점 수를 실측해 원장에 남긴다(마우스·펜·손가락 각각).
* 반증(D-3): 끄면 그 수가 1로 떨어지는가. 실제로 꺼서 확인한다.

1-b. 기울기 — 지금은 아예 안 받는다
`input.ts` 에 `tiltX`/`tiltY` 가 없다. 그런데 펜은 기울기 60°를 올려 보낸다. ⚠ 연필을 연필처럼 만드는 가장 큰 신호가 기울기다 — 필압보다 크다.
* `tiltX`/`tiltY`, 오면 `twist` 도 수집한다.
* ⚠ 기울기가 안 오는 입력에서 무엇이 오는지 적는다 — `0` 인가 `undefined` 인가 `90` 인가. 2부의 폴백이 이 관측에서 나온다. 가정하면 마우스 사용자의 선이 이상해진다.

1-c. 필압을 점별로
`Stroke.raw?: Pt[]` 가 이미 있다. 여기에 점별 필압·기울기를 나란히 붙인다.
* 방법은 스스로 정한다(평행 배열이든 확장 점이든). ⚠ `Pt` 타입을 바꾸면 파급이 크다 — `vec.ts` 의 `Pt` 는 기하 전체가 쓴다. 파급 범위를 먼저 세고 근거를 NOTES 에 적는다.
* `mat.press` 는 남긴다 — 옛 파일과 현재 렌더가 본다(A-4).
* ⚠ 파일이 커진다. 양자화 정밀도를 정하고 근거를 적는다. 같은 그림의 저장 크기를 수리 전/후로 실측해 원장에 남긴다. 자동저장은 localStorage 다 — `autosaveWarned` 경로가 더 자주 도는지 본다.

1-d. 지우개 끝 감지 — 띄우기만 한다
전용 지우개 펜이 곧 온다. 기능을 대체하지 않는다 — 일반 스타일러스 경로는 그대로 남고 전용 지우개가 있으면 더 섬세해질 뿐이다. 명세 역사상 스타일러스 지우개는 별도 `pointerType` 이 아니라 버튼 상태로 온다 (`pointerType: 'pen'` + `button 5` / `buttons & 32`). ⚠⚠ 확인 대상이지 결론이 아니다(D-4). 가정하고 짜지 마라 — 감지해서 진단에 날값만 띄우고 도구를 자동으로 바꾸지 않는다. 틀린 가정으로 자동 전환을 켜면 그리다가 지워진다.

1-e. `.brnl` 하위호환
새 필드는 전부 선택(optional). 없으면 지금과 똑같이 동작한다.
* 옛 파일이 열리는가를 팔이 잰다(web2-10 이전 실제 파일로).
* 새 파일이 옛 앱에서 어떻게 되는가도 적는다 — 배포된 PWA 는 사람마다 갱신 시점이 다르다.
* 반증(D-3): 새 필드를 손으로 지운 파일이 정상으로 열리는가.

1-f. 진단 패널을 늘린다
web2-10 이 만든 우하단 패널이 DEFERRED 의 실기기 측정 도구다. 여기 얹는다.
* `pointerType`·`button`·`buttons`·`pressure`·`tiltX/Y`·`twist` 날값
* coalesced 로 더 받은 점 수(최근 획)
* 필압 실제 단계 수 — 펜은 8192 를 준다는데 브라우저가 몇 단계로 넘기는지 안 봤다
* 최근 획의 점 개수와 `.brnl` 바이트

2부 — brush.js 로 획을 그린다
════════════════════════════════════════
사람이 고른 것: `p5.brush` 의 표준 빌드(`dist/brush.js`). p5.js 가 필요 없다(WebGL2 만 필요). MIT. 고른 이유: 내장 브러시가 2B · HB · 2H · cpencil · pen · rotring · charcoal · marker · spray · hatch_brush 로, 이 앱의 `GRADES`(2H·H·F·HB·B·2B·INK)와 거의 겹친다. `rotring` 이 INK 자리의 제도펜이고, `hatch_brush` 는 나중 포셰·재료 표기의 자리다.
⚠ 라이선스: MIT 다. §3 규약대로 저작권 표기를 LICENSE 에 남긴다. 버전을 고정하고(package.json), 어느 빌드를 쓰는지 NOTES 에 적는다.

2-a. 범위 — 어디를 바꾸고 어디를 안 바꾸나
* ✅ 2D 오버레이의 «획 그리기»만 바꾼다.
* ⛔ 3D(`Line2`)는 안 건드린다. 「2D는 내가 그린 것, 3D는 확정된 기하」다. 이 갈림 자체를 DECISIONS 에 결정으로 남긴다.
* ⛔ 작도선·지평선·소실점 ✕·오스냅 기호·면·치수는 안 바꾼다. 획만이다.
* ⛔ 지우개 강도·트레이스 층은 다음 회차다.

2-b. ⚠⚠ 되돌릴 수 있게 만든다 — 이 회차에서 가장 중요한 조항
사람이 「무겁더라도 좋은 걸 먼저 보고, 불편하면 고친다」고 했다. 「고친다」가 가능하려면 옛 경로가 살아 있어야 한다.
* 기존 획 렌더 경로를 지우지 않는다(A-4 「폐기 코드를 지우기 전에 게이트를 통과시킨다」).
* 런타임 토글로 둘을 오간다. 사람이 태블릿에서 직접 전환해 비교할 수 있어야 한다. 자리는 스스로 정하되 설정 깊숙이 묻지 마라 — 비교가 목적이다.
* 진단 패널에 지금 어느 렌더러인지 띄운다.
* e2e 가 두 경로 다 돈다.

2-c. 브러시 매핑
`GRADES` → brush.js 브러시. 2H·HB·2B·INK(→`rotring`)는 이름이 그대로 있다. ⚠ H 와 F 는 내장에 없다. `brush.add()` 로 만들거나 사이를 보간한다 — 어느 쪽이든 근거를 적는다. 경도가 2H→2B로 단조 증가하는 성질(`MAT` 표)이 유지되는가.
* `MAT` 표의 `alpha`·`width`·`grain` 이 brush.js 로 어떻게 옮겨가는지 대조표를 NOTES 에 낸다.

2-d. 지켜야 할 계약 셋
1. 화면 고정 굵기(원칙 e) — 줌해도 굵기가 안 변한다. `is = 1/v.s` 가 brush 쪽에도 들어가야 한다.
2. `widthOfMat` 이 굵기의 단일 출처(PITFALLS #54, 정적 검사가 강제). brush 에 넘기는 굵기도 여기서 나온다. 계약이 깨지면 정적 검사가 잡아야 한다.
3. 결정론 — §5 가 「시드에 `Math.random` 을 쓰지 않는다」를 규약으로 두고 `selfcheck.py` 가 정적으로 잡는다. 그리고 e2e 픽셀 팔(잉크량·채도)이 같은 입력 → 같은 픽셀에 기대고 있다. ⚠ brush.js 는 시드를 받는다(p5 빌드는 `randomSeed()` 에 물린다). 표준 빌드의 시드 API 를 찾아 획 id 로 고정한다 — 지금 `grain()` 이 `rng32(s.id)` 로 하는 것과 같은 방식이다. ⚠⚠ 못 하면 멈추고 적는다. 픽셀 팔을 어떻게 할지 정하지 않은 채 넘어가지 않는다.

2-e. 기존 `grain()`
brush.js 가 질감을 주면 중복이다. 끄되 지우지 않는다(2-b 와 같은 이유).

2-f. 재는 것 — 사람이 「이건 왜 이상하지」 할 때 원인을 찾을 수 있게
⚠ 지연도 「느낌」이다. 120Hz 에 EMR 펜이면, 선이 펜 끝을 못 따라오는 순간 질감이 아무리 좋아도 종이 같지 않다. 그래서 무게를 «성능»이 아니라 «느낌»으로 잰다.
* 펜 다운 → 첫 픽셀까지의 시간, 그리는 중 프레임 시간(중앙·최악)
* 옛 경로와 새 경로를 나란히 잰다. 원장(stage0/out)에 JSON 으로 남긴다
* 획 수를 늘려가며 잰다(10·100·500) — 오래 그릴수록 느려지는지
* WebGL2 컨텍스트가 하나 더 붙는다(지금 three.js WebGL + Canvas 2D). 메모리도 적는다
* 번들 크기와 `sw.js` — 오프라인이 유지되는가

진행 규칙
════════════════════════════════════════
각 항목은 브라우저에서 열리는 상태로 커밋한다. 새로 만든 검사에는 D-3대로 반증 조건을 따로 붙이고 실제로 실패시켜 본다. 헤드리스에서 잴 수 있는 것과 실기기에서만 보이는 것을 갈라 적는다.
⚠⚠ 이 회차의 최종 판정자는 사람의 손이다. 「종이 같은가」는 헤드리스가 못 잰다. 세션이 재는 것은 지연·프레임·크기·결정론이고, 그것은 「왜 이상한지」를 찾는 도구다. 수치가 좋다고 「통과」라고 적지 않는다. 실기기 판정 항목을 DEFERRED 에 표로 남긴다: 선이 펜을 따라오는가 · 흑연이 종이처럼 보이는가 · 경도 차가 손에 읽히는가 · 줌해도 이상하지 않은가 · 오래 그려도 느려지지 않는가.
팔·스윕을 더하면 비용을 원장에 남긴다(npm run test:cost). 방법은 스스로 정하고 근거를 NOTES에 적는다. 컨텍스트가 차면 web2/HANDOFF.md 를 갱신하고 종료한다 — 어디까지 배포됐는지 첫 줄에. §D 진단 규약을 따른다.
