════════════════════════════════════════
web2-19 — 제도판
════════════════════════════════════════
착수와 완료 시 화면에 한 줄 출력한다.
web2-18 은 배포 ② `e56b4ed` 까지 확인됐고 사람이 만족을 판정했다.

```
1부  획은 흑연이다 — 소실점 정의선의 컬러 몸체를 없앤다
2부  종이 탭 — 명명된 뷰가 「종이」가 된다          ← 게이트
3부  띠를 넷으로 가른다 · 전체 화면
4부  아이콘 — 대응표·정본을 옮긴다                → 배포 (회차 끝 한 번)
```

════════════════════════════════════════
⛳ 배포 정책 — 끝에 한 번만
════════════════════════════════════════
사람이 정했다: 「어차피 중간에 체크 안 하고 나는 잘 텐데 중간에 배포할 필요 없지
않나?」 중간 배포는 사람이 기기에서 판정하려고 둔 것이고, 판정할 사람이 없으면 값이 없다.

- **게이트는 그대로 둔다.** 게이트는 배포가 아니라 **판정**이다.
- **배포는 회차 끝에 한 번.** `main` 병합·푸시 → `deploy:check` → 화면 빌드 식별자.
- ⚠⚠ **예외: 게이트에서 멈추거나 컨텍스트가 차서 세션을 넘길 때는 그 자리에서 배포한다.**
  갈래에만 두고 멈추면 사람 손에 옛 앱이 남는다(#58).
- 갈래 커밋은 종전대로 잘게. 바뀌는 것은 `main` 푸시 횟수뿐이다.

════════════════════════════════════════════════════════
1부 — 획은 흑연이다
════════════════════════════════════════════════════════
사람의 관측: 「화면상 수직수평선 그을 때 여전히 컬러 선이 나타나는 거 수정하자.
**획은 모두 흑연으로 하기로 하지 않았는가.**」

### 1-a. 원인 (후보 — D-4. 표식이 먼저다)
`render2d` 의 색 규칙 정본은 「색을 갖는 것은 그리는 중의 상태 예고 둘뿐」이고 그중
하나가 작도 안내 파랑(`COL.preview` = `#1a6ac2`)이다. 조건이
`constructing = draft.label === 'horizon' || draft.label === 'vp'` 이고 `draftBrushed`
도 같은 둘을 흑연에서 뺀다. **web2-17 이 그 규칙을 낡게 만들었다** — 'horizon' 은
없어졌고 남은 'vp' 는 이제 **진짜 모서리**다(방 실루엣의 후퇴선은 벽 모서리이면서
동시에 소실점을 만든다).

### 1-b. 답 — 몸체는 언제나 흑연, 예고는 표식으로
- `constructing` 갈래를 **없앤다.** 몸체는 언제나 재료색이고 brush 겹이 그린다.
  `draftBrushed` 의 'horizon'·'vp' 제외도 없앤다. ⚠ 'horizon' 은 **죽은 가지**다 — 지운다.
- 「이 획이 소실점을 만든다」는 **그 소실점이 생길 자리**에 **파선 ✕**(확정 소실점 ✕와
  같은 형태·같은 색 `COL.vpMark`). 어법은 web2-16 3-a 그대로 — 파선 = 아직/숨은.
- ⚠ 면 미리보기의 색은 그대로 둔다(탭하면 무엇이 되는가의 예고이지 획의 몸체가 아니다).

### 1-c. 분류가 실제로 틀렸는지는 **별개 물음** — 재기만 한다
- `C.PARALLEL_PX = 1.5` 는 손 허용보다 훨씬 작다. 손으로 그은 「수평선」의 처짐이 그보다
  크면 소실점 갈래로 떨어진다.
- **재기만 한다**(D-2): 손 오차를 태운 획(#68)의 처짐 분포와, 그중 몇 %가 소실점 갈래로
  떨어지는지. 화면 수직도 같이(`SCREEN_PARALLEL_RATIO = 0.05` 가 먼저 잡는지).
- ⚠⚠ **임계를 즉흥으로 올리지 마라.** web2-17 이 「따라긋기 8px 대역」에서 이미 이 근처를
  건드렸고 경계 플립을 실측했다. **표를 내고 다음 회차 판단으로 넘긴다.**

회귀 팔: ① 몸체가 흑연(파랑 픽셀 0) ② 파선 ✕가 예상 자리에(좌표 값으로) ③ 떼는 순간
몸체 무변화 ④ 면 미리보기 색 그대로 ⑤ 1-c 분포표.
반증(D-3): `constructing` 을 되살리면 ①이 실패하는가.

════════════════════════════════════════════════════════
2부 — 종이 탭
════════════════════════════════════════════════════════
사람의 관측: 「명명된 뷰 각각은 아예 다른 장면이니까, 현실 작도에서는 **아예 새 종이를
꺼내는 것**과 마찬가지 … 크롬 탭처럼, 제목을 설정할 수 있는.」

확인된 것 셋(사람이 답했다):
1. **종이가 늘어도 3D 는 하나다.** 새 종이에 그린 선이 옛 종이에도 나타난다 — 의도한 바다.
2. **작도 종이는 첫 장이고 못 지운다.** 이름은 바꿀 수 있다.
3. **「+」는 각도를 찾은 뒤 저장하는 것**이다. 빈 장을 먼저 만들지 않는다.

### 2-a. 층위 — 셋이고 이 회차는 가운데다
```
파일(.brnl)   = 대상 하나. 3D 하나, 작도 시점 하나.
종이(탭)      = 그 대상을 그린 한 장. 하나만 활성.   ← 이 회차
겹(종속 탭)   = 그 종이 위에 얹은 것. 여럿 동시.     ← web2-20
```
비유의 눈금은 **스케치북이 아니라 도면집**이다 — 여러 장인데 건물은 하나다.

### 2-b. 자료 구조
```ts
export interface Sheet {
  id: number
  name: string
  /** 없으면 **작도 종이** — 포즈는 DRAW_POSE, 뷰는 drawView(web2-17). */
  pose?: CamPose
  view?: ViewOffset
  thumb?: string
}
```
- **`Doc.sheets: Sheet[]`** — `savedViews` 를 대신한다. **배열 0 이 작도 종이**이고
  `pose`·`view` 가 없다. 늘 있고 못 지운다. 이름은 바꿀 수 있다.
  ⚠ 작도 시점의 정본은 `DRAW_POSE` 와 `drawView` 하나씩이다. 여기 또 담으면 출처가 둘(#54).
- ⚠⚠ **`BrnlData` 가 아니라 `Doc` 에 둔다.** 다음 회차의 겹이 종이를 가리키고 겹은 획을
  소유한다 — 종이가 문서 밖에 있으면 그 참조가 문서 경계를 넘는다. `drawView` 는 지금
  자리에 그대로(구도이지 구조가 아니다).
- id 는 획·면·겹과 **한 통** — `nextId` 하나.
- `.brnl` **version 4**. 1~3 을 다 받는다. v3 이하의 `savedViews[i]` → `sheets[i+1]`,
  이름 「종이 2」…. 작도 종이는 마이그레이션이 만든다(이름 「작도」). 모양이 틀리면
  **그 종이만 버린다**(문서를 거부하지 않는다).

### 2-c. 화면 — 위쪽 얇은 띠
- **늘 떠 있다.** 「지금 어느 장인가」는 상태 표시이고 팝업은 열어야 안다.
- 높이는 얇게(초안 28px). 썸네일은 **길게 눌러야** 뜬다.
- 이름 편집: 탭 두 번 누르기 또는 길게 눌러 이름 항목.
- **「+」 = 지금 보고 있는 포즈·뷰를 새 종이로 저장.** 기본 이름 「종이 N」, 바로 편집 가능.
- 삭제: 작도 종이 빼고 가능. **실행취소 대상이 아니다**(web2-12 `deleteView` 규약).
  ⚠⚠ **다음 회차에 이 규약이 바뀐다** — 겹이 종이에 붙으면 종이를 지우는 것이 획을
  지우는 일이 된다. `DEFERRED.md` 에 지금 올린다.
- ⚠⚠ **web2-20 이 이 띠 **아래**에 종속 탭 줄을 붙인다.** 자리를 막지 마라 — 띠의
  아래 가장자리에 다른 줄이 붙을 수 있는 구조로 짠다(고정 높이를 하드코딩하지 않는다).
- ⚠ `#notice` 가 상단 z-index 10 에 fixed 다. 알림은 오류가 있을 때만 뜨므로 **띠 위에
  겹쳐 뜨는** 쪽이 맞다. 정하고 적는다.

### 2-d. 회귀 팔
① v3 파일을 열면 명명된 뷰가 종이가 되고 작도 종이가 앞에 선다(개수·이름 값으로)
② 왕복에서 이름·순서·포즈가 같다 ③ 「+」가 지금 포즈·뷰를 담는다(값으로)
④ 탭을 누르면 그 포즈로. 작도 종이는 `DRAW_POSE` + `drawView`
⑤ 종이를 지워도 **획이 안 지워진다**(획 수 전후 동일) ⑥ 작도 종이는 못 지운다
⑦ 이름 변경이 왕복에서 남는다.
반증(D-3): 작도 종이에 `pose` 를 담으면 ④가 어긋나는가(실제로 담아 확인).

서면 **배포하지 말고 그대로 3부로**. 못 서면 **여기서 배포하고 사유를 적고 끝낸다.**

════════════════════════════════════════════════════════
3부 — 띠를 넷으로 가른다 · 전체 화면
════════════════════════════════════════════════════════
사람이 물었다: 「그리기 도구나 스냅 등 기능적 도구, 파일 등 시스템 도구로 직관적으로
UX에서 잘 구분되어 있는 상태인가?」 **아니다.** 지금 오른쪽 막대에 다섯 층위가 한 줄로
쌓여 있고 가르는 채널이 **공백(`.bar-gap`) 하나**뿐이다.

진단(이 회차가 고치는 것):
- **분류가 자리 때문에 섞였다** — 치수가 시점 묶음(`#viewbar`) 안에 있다. 코드 주석이
  사정을 적어 뒀다(「종전 둘째 열에서 들어왔다」). 의미가 아니라 자리 때문이다.
- **설정이 세 종류를 담은 자루다** — 오스냅(기능 도구) · 표시(보기) · 렌더러·3D 경로(깃발).
- ⚠⚠ **「기능적 도구」 층위가 화면에 자리를 안 갖고 있다.** 축 스냅은 어디에도 없고
  (항상 켜져 있고 끌 수 없다 — 대응표 §4), 오스냅은 설정 안쪽에 접혀 있다.

### 3-a. 네 자리 — 은유가 정한다

| 자리 | 무엇 | 왜 |
|---|---|---|
| **위 왼쪽** | **종이** — 탭(2부) + 종속 탭 자리(web2-20) | 어느 장인가 |
| **위 오른쪽** | **눈** — 작도 시점으로 · 전체 화면 · 표시(지평선 · 지면 격자 · 「다른 각도에서는 숨긴다」) | 「이 종이를 어떻게 보는가」는 종이 옆이 제자리다 |
| **오른쪽 세로** | **손** — 자(스냅) · **연필(접힘)** · 펜 · 지우개 둘 · 면 · 굵기 · 치수 | 매 획마다 쓴다. 펜이 닿는 쪽 |
| **오른쪽 맨 아래(접힘)** | **서랍** — 파일 · 종이 질감 · 진단 | 가끔 연다 |

- **되돌리기·다시실행**은 은유가 없다(제도판에서는 지우개가 그 역할이었다). **손 띠의
  맨 위**에 두되 도구와 **시각적으로 가른다**(구분선 또는 다른 크기). 서랍은 너무 멀다.
- **치수**는 시점 묶음에서 나와 **손 띠**로 간다 — 그린 선에 값을 주는 일이므로 도구다.
  리본 패널은 그대로, 트리거만 옮긴다.
- **표시 토글 셋**은 설정에서 나와 **눈**으로 간다.
- **`own3d` 깃발은 진단 패널로**(대응표 §3). ⚠ **없애지 마라** — A-4 로 옛 경로를
  유지하는 깃발이다. localStorage 열쇠 그대로.

### 3-b. ⚠⚠ 자(스냅)가 손 띠에 자리를 얻는다 — 이 회차의 핵심

**삼각자 아이콘 = 스냅 묶음의 입구.** 누르면 오스냅 종류·반경이 거기서 열린다(설정
자루에서 나온다). 이것으로 「기능적 도구」 층위가 처음으로 화면에 존재하게 된다.

- ⚠ **축 스냅을 끄는 토글은 이 회차에서 만들지 않는다.** 「자를 치운 상태」는 그 획이
  3D 로 안 올라가는 갈래를 열므로 혼자 한 회차짜리다(대응표 §4 · `DEFERRED`).
  묶음 안에 **자리만 비워 둔다** — 나중에 그 자리에 붙는다.
- ⚠ 아이콘이 실물이면 동작도 실물이어야 한다(대응표 규칙 하나). 삼각자를 그려 놓고
  치울 수 없는 어긋남을 **`DEFERRED.md` 에 대응표 §4 를 인용해** 적는다.

### 3-b′. ⚠⚠ 연필통을 접는다 — 손 띠의 폭이 이걸로 정렬된다

사람이 정했다: 「**옛 연필 아이콘을 기본으로 보여주고 그걸 누르면 연필통을 펼치자.**
펜은 하나뿐이니까 옛 아이콘 하나만 누르면 되도록. … 펼쳤을 때 나오는 연필 아이콘은
좀더 연필스럽게 **앞을 뾰족하게**.」 그리고 「**접힌 아이콘에 경도는 있어야 한다.**」

- **평소에는 연필 아이콘 하나**만 보인다(세로 연필 · 경도 각인 유지 · 앞이 뾰족).
  누르면 그 자리에서 **연필통 여섯 줄이 펼쳐진다.** 다시 누르거나 하나를 고르면 접힌다.
- **접힌 아이콘의 경도 문자와 심 색은 지금 경도를 따른다.** 배선은 `#oldtools` 의
  `btn-pencil-old`(`lead-text`·`lead`)가 이미 갖고 있던 것이다 — 그 경로를 되살려 쓴다.
  ⚠ 값의 출처는 `MAT` 하나다(#54). 색 목록을 여기 복제하지 마라.
- **펜은 접기가 없다** — 하나뿐이다. **연필통에서 펜 줄이 빠진다**(지금은 트레이 안에 있다).
  니브 굵기는 종전대로 `#thick` 막대가 맡는다(펜이 활성일 때만 뜬다).
- **연필통 줄의 앞을 원뿔로 깎는다.** 종전 줄은 가운데를 잘라 단면에 심 색을 보였는데,
  깎은 끝은 그 단면이 **노출된 심**이 되므로 채널을 안 잃고 그림만 나아진다.
  SVG 는 `docs/instrument-icons.md` 의 「실물 도구 — 연필만 바뀐다」가 정본이다.
- ⚠⚠ **이것이 손 띠의 폭 불일치를 푼다.** 연필통 줄은 96×24 이고 나머지 버튼은 39×39 라
  띠 안에서 폭이 둘이었다. 접어 두면 **평소에는 39px 정사각만 남고** 사용자가 연 동안만
  넓어진다 — 어긋남이 아니라 방금 연 것으로 읽힌다.
- ⚠ **홀더펜으로 바꾸지 마라.** 기각 사유 셋이 `docs/instrument-icons.md` 에 적혀 있다.
  `#oldtools` 의 「4-e 홀더펜 슬라이더」가 이미 한 번 지나간 길이다.
- ⚠ `TRAY` 상수와 `#oldtools` 는 **되돌리기 손잡이**다(A-4). 지우지 말고 그대로 둔다.

### 3-c. 가르는 채널을 공백에서 바꾼다
은유가 답을 준다 — **도구는 종이 위에 놓여 있고(배경 없이 떠 있다), 서랍은 닫혀 있고
(`<details>` 그대로), 종이 띠는 종이의 가장자리다.** 세 자리가 각각 다른 처리를 가지면
공백에 기댈 필요가 없다. 구체는 세션이 정하고 근거를 적는다.

### 3-d. 전체 화면
- 크롬을 전부 숨긴다: 종이 띠 · 눈 · 손 · 서랍.
- ⚠⚠ **지평선 · 소실점 ✕ · 바닥 눈금은 남는다.** 크롬이 아니라 **작도의 뼈대**다.
- **나가는 길이 보여야 한다** — 우하단에 작은 손잡이 하나. ⚠ 제스처를 새로 만들지 마라
  (손가락 하나가 궤도, 둘이 줌·팬이라 이미 빡빡하다). 나가는 길이 안 보이면 고장으로 읽힌다.
- 상태는 저장하지 않는다(세션 한정).

### 3-e. 회귀 팔
① 네 자리의 요소가 정확히 표대로다(각 자리의 id 목록을 값으로 적는다)
①' **연필이 접혀 있다** — 평소 손 띠의 모든 버튼이 39px 폭이다(값으로).
   연필을 누르면 연필통 여섯 줄이 펼쳐지고, 하나를 고르면 접힌다.
   접힌 아이콘의 경도 문자·심 색이 고른 경도를 따른다(2H·2B 로 왕복해 값 확인).
   펜은 접기가 없고 연필통에 펜 줄이 없다.
② 치수 트리거가 손 띠에 있고 리본이 종전대로 열린다
③ 표시 토글 셋이 눈에 있고 **동작은 그대로**(각각 켰다 끄기 왕복)
④ 자 아이콘을 누르면 오스냅 종류·반경이 열리고 **동작은 그대로**
⑤ `own3d` 가 설정에 없고 진단에 있으며 동작 그대로(왕복)
⑥ 전체 화면: 크롬 픽셀 0 · 지평선/소실점 픽셀은 그대로 · 손잡이로 나온다 ·
   그리기·궤도·지우기가 된다 · 새로 고치면 꺼져 있다
⑦ 종이 띠 아래에 **다른 줄이 붙을 수 있다**(고정 높이가 하드코딩되지 않았다 — 20 을 위한 조건)
