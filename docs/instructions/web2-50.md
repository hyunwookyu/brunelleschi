# web2-50 — 자국의 뿌리: 면마다 텍스처

> **Fable.** 방법은 맡긴다 — 무엇을 지키고 무엇을 잴지만 적는다.
> **HANDOFF §2를 50=자국의 뿌리 · 51=자국의 질 · 52=재료 · 53=내보내기와 별칭으로 갱신하라.**

## 왜

사용자가 칠하기를 실제로 쓰고 내린 판정: **「있으니만 못하다.」**

증상 여섯이 나왔는데 **전부 한 뿌리다.** 지금은 2D 스탬프를 3D 면 위에 얹으려 하고 있고,
합성이 그 사이에서 무너진다.

```
① 부드러운 가장자리가 하얗게 뜬다        ← 알파 합성
② 면·선과 블렌드가 안 된다                ← 합성 트리 (#73 계열)
③ 돌리는 동안 칠이 전부 사라진다          ← 굽기 캐시
④ 원근을 제대로 안 받는다
⑤ 개구부가 생기면 깨진다
⑥ 면의 한쪽에만 붙지 않는다 (48-5)
```

**구조를 바꾸면 여섯이 같이 사라진다.**

> **면 하나마다 자기 텍스처를 하나(앞·뒤 둘) 갖는다.**
> **칠은 그 텍스처에 그린다. 텍스처를 입은 면이 3D에 놓인다.**

3D 페인팅 도구들이 실제로 쓰는 구조다. 합성이 2D 캔버스 안으로 들어가므로 통제가 쉽고,
면이 3D에 있으므로 원근·깊이·회전이 전부 공짜로 맞는다.

## 정본과 파생 — 원칙 b

```
정본   획 목록 — 면 id · 앞/뒤 · 브러시 · 색 · 압력 · 면 위 좌표
파생   텍스처 — 획 목록에서 굽는다. 저장하지 않는다
```

면 경계가 바뀌면(개구부를 뚫으면) 텍스처를 다시 굽는다. 파일에는 획만 들어간다.

## 이번 회차의 범위 — **오직 구조만**

**기존 브러시를 그대로 옮기기만 한다.** 브러시의 질·재료·무늬·팔레트는 전부 51·52의 몫이다.
자국이 예쁘지 않아도 좋다. **여섯 증상이 사라지는 것**만 본다.

⚠ 여기서 손을 넓히면 이 라운드가 무엇을 고쳤는지 알 수 없게 된다.

## 지금 칠한 것은 버려도 된다

**사용자 확정: 「잃어도 상관없다.」**
마이그레이션을 만들지 마라. 옛 칠 데이터는 버리고 새 구조로 깨끗하게 간다.
다만 **버린다는 사실이 조용하면 안 된다** — 옛 데이터를 가진 문서를 열 때 무엇이 사라졌는지
한 줄로 알려라 (43-1의 「조용히 빈 문서를 열지 마라」와 같은 규칙).

## 지켜야 할 것

- **텍스처를 면에 곱하기로 입힌다.** 아래 선이 비쳐야 한다. 덮어 버리면 안 된다
- **앞/뒤는 카메라가 있는 쪽이 정한다.** 칠할 때 보고 있는 쪽에 붙고, 반대쪽에서는 안 보인다
  (48-5. 나중에 두께를 주면 앞면 칠이 바깥 표면, 뒷면 칠이 안쪽 표면으로 간다 —
  그 이어짐을 깨뜨리지 않는 꼴로 저장하라)
- **칠한 면은 불투명하다** — 뒤를 가린다. 안 칠한 면은 안 가린다 (48-9)
- **면은 평소에 안 보인다.** 칠 도구를 들었을 때만 (48-9)
- **화면 고정 도면 해칭은 텍스처가 아니다.** 그건 화면 층에 그대로 남는다.
  49가 만든 두 판 중 **면 고정 판만** 텍스처로 옮긴다
- 원칙 e — 선폭은 화면 고정이다. 칠의 굵기가 그것과 어떻게 다른지 정하고 원장에 남겨라

## ⚑ 재서 정할 것 — 텍스처 해상도

면마다 텍스처를 들면 면이 많을 때 메모리를 먹는다.
**면의 실제 크기와 화면에서 차지하는 크기**로 해상도를 정하고 상한을 둬라.
멀거나 작은 면은 낮게. 값은 재서 고르고 근거를 원장에 남겨라.

획 40개 · 면 20개 이상의 장면에서 메모리와 프레임을 재라.

## 게이트

- **여섯 증상이 각각 사라진다.** 하나씩 따로 재라 —
  가장자리 픽셀의 알파-RGB 관계 / 아래 선이 비치는가 / 회전 중 유지 /
  원근에 따라 줄어드는가 / 개구부를 뚫었을 때 따라 잘리는가 / 반대쪽에서 안 보이는가
- **①은 픽셀 램프로 확정하라.** 획 하나를 긋고 가장자리를 가로질러 알파와 RGB를 뽑아,
  알파가 떨어질 때 RGB가 흰색으로 가지 않는 것을 수치로 보여라
- 텍스처를 지우고 획 목록에서 다시 구웠을 때 픽셀이 같다 (파생임을 증명)
- 저장 왕복 — 43의 전수 목록을 갱신하라. **텍스처가 파일에 안 들어간다**
- 성능: 면 20개 장면의 프레임·메모리. 회전 중 프레임
- 49의 무늬 생성기가 살아 있다 — 그리는 자리만 바뀌고 생성 코드는 그대로
- 기존 전부 무회귀
