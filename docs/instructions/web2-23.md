════════════════════════════════════════
0. 사람이 정한 것 — 원문
════════════════════════════════════════
> 「**기본적으로 make2d 하는 선을 사용한다.** 하지만 와이어프레임이 모두 똑같이 보이는
> 경우, 나는 벽이나 바닥을 의도하고 그린 곳의 이면, **즉 실제로는 면으로 가려진 부분이
> 모두 드러나 보이는 문제**가 생긴다. 따라서 여기서 면 생성 기능이 개입하여, 뒷면을
> 가려줄 필요가 있다. **가린 선은 옵션에 따라 은선으로 취급하여 h 계열 선으로 치환하고
> 보이는 선은 f 나 b 계열로 치환**하면 되지 않을까.」

> 「**면 생성이 옐로페이퍼와 별개로 작동해야 할 것 같다. 옐로우 올리기 전에 면을 먼저
> 필요한 곳에 다 세워놓는 것이다.**」

> (면 위에 그릴 것인가는) **면은 깨끗한 지오메트리로만 남기고 옐로페이퍼에서 소묘하듯** —
> 2026-08-27 합의. 근거 셋: ① 「투시도는 면에 의해 스냅되거나 정의되는 경우 자체가 없다」
> (`HANDOFF.md` 「면은 스냅 대상이 아니다」) ② 면 위에 그린 획은 그 면에 **종속**된다 —
> 사람이 창문 논의에서 거부한 구조 ③ 그건 텍스처링이지 제도가 아니다.

0부 — ⛔⛔ 게이트
════════════════════════════════════════════════════════
`web2/HANDOFF.md` 첫 줄의 **web2-21 1-a 갈래**를 읽는다.

- 「**23 게이트 통과**」(개구부가 3D 로 올라간다) → 1부로 간다.
- 「**23 게이트 미통과**」 → ⛔ **시작하지 않는다.** `HANDOFF.md` 에 그 사실과 이유를
  적고 끝낸다. 사람에게 넘긴다.

근거: 창틀이 3D 로 안 올라가면 면의 경계로 못 쓰고 → 개구부가 안 생기고 → 벽이 통짜가
되어 **창 너머가 전부 가려진다.** 그러면 make2d 결과가 쓸모없다. 만들고 나서 알면
회차가 통째로 헛돈다.

1부 — 굽기 ⚠⚠ **한 번만 돈다**
════════════════════════════════════════════════════════
사람의 말 안에 싸게 만드는 조건이 이미 있다 — **「눌러놓은 선」**. 옐로를 얹는 **그 순간
한 번** 계산하고 그 뒤로는 그림이다. **프레임마다 안 돈다.**

### 1-a. 무엇을 굽는가
그 종이의 시점에서:
1. 켜진 겹의 **3D 선분 전부**를 화면으로 사영한다(`projectSeg` — 출처는 카메라 하나).
2. `app.faces` 의 각 면을 화면 다각형으로 사영한다.
3. 각 선분을 각 면 다각형과 **클리핑**해 조각으로 나눈다.
4. 조각마다 **중점에서 깊이를 비교**해 `visible` / `hidden` 을 정한다.
5. 결과 = **2D 폴리라인 목록 + 깃발 하나**.

- ⚠ **법선은 필요 없다.** 가림은 「이 조각이 이 면보다 뒤인가」이지 면이 어느 쪽을 보는가가
  아니다. 법선은 그림자를 할 때 필요하고 그건 이 회차 밖이다.
- ⚠ **화면 표시 규약을 건드리지 마라.** 면은 지금대로 `depthTest:false` 의 옅은 채색이다
  (AS-C19). 깊이는 **이 굽기 안에서만** 쓴다. 이 갈림을 `DECISIONS.md` 에 적는다 —
  「면끼리 안 가린다」를 결함으로 읽고 고치려 드는 다음 사람을 막는다.
- ⚠ **옐로 겹 자신의 획은 굽는 대상이 아니다**(2D 다). 그 아래 3D 만이다.

### 1-b. 비용
획 200 · 면 20 이면 클리핑 4000 번, 한 번 굽는 데 수십 ms 로 예상된다. **버튼 한 번의
비용이라 감당한다.** 그래도 **재서 원장에 적는다**(#38 규율) — 획 50·100·200·400 ×
면 5·10·20·40. 신설 `cost23_web2.json`.
- ⚠ 프레임 예산과 견주지 마라. 이것은 **한 번 도는 비용**이고 기준이 다르다. 「사람이
  기다릴 만한가」로 잰다. 초안 상한 **500ms**, 넘으면 진행 표시를 띄운다.

### 1-c. ⚠ 굽기가 실패할 수 있는 자리
- **면이 하나도 없다** → 전부 `visible`. 3부가 안내한다.
- **선분이 면과 정확히 같은 평면에 있다**(벽의 모서리는 벽 면 위에 있다) → 깊이 비교가
  퇴화한다. **같은 평면의 면과는 비교하지 않는다**(`C.PLANAR_RATIO` 와 같은 물음).
  ⚠ 이 조항을 빼면 벽 모서리가 자기 벽에 가려 사라진다. **팔이 지킨다.**
- **카메라 뒤로 넘어가는 선분** → `projectSeg` 가 이미 잘라낸다(그 규약을 그대로 쓴다).

회귀 팔: ① 벽 뒤의 선이 `hidden` 이 된다(조각 수·좌표 값으로) ② 벽 자신의 모서리는
`visible` 로 남는다(같은 평면 조항) ③ 개구부 너머의 선이 `visible` 이다(창이 뚫려 있다)
④ 면이 없으면 전부 `visible` ⑤ 옐로 자신의 획은 굽기에 안 든다 ⑥ 비용 표.
반증(D-3): 같은 평면 조항을 빼면 ②가 실패하는가 · 깊이 비교를 뒤집으면 ①이 뒤집히는가.
**둘 다 실제로 돌린다.**

2부 — 표현과 저장
════════════════════════════════════════════════════════

### 2-a. 경도 치환 — 제도 관행 그대로
사람이 정했다: 「가린 선은 **h 계열**, 보이는 선은 **f 나 b 계열**」.
- **보이는 선 → `F`**(기본). **가린 선 → `H`**(기본).
- **가린 선을 아예 빼는 옵션**을 하나 둔다(사람의 문면 「옵션에 따라」). 기본은 **H 로 표시**다 —
  은선이 보이는 편이 제도에 가깝고, 빼는 것은 정리된 그림을 원할 때다.
- ⚠ **`MAT` 를 그대로 쓴다.** 새 색·새 굵기를 만들지 마라(#54 — 출처가 둘이 되면 안 된다).
- ⚠ 은선을 **파선으로 만들지 마라.** 이 앱에서 파선은 이미 「대기」의 채널이다
  (web2-16 3-a). 은선은 **경도로만** 가른다 — 채널이 겹치면 둘 다 안 읽힌다.
  이 근거를 적는다.

### 2-b. 저장 — `.brnl` v6
사람이 「다시 뜨기」를 폐기했으므로(web2-22 1-e) **밑그림은 저장해야 한다.** 안 저장하고
열 때 다시 계산하면 그것이 곧 자동으로 다시 뜨는 것이고, 사람이 거부한 동작이다.

```ts
/** 옐로 겹의 밑그림 — 얹는 순간 구운 make2d. **사건의 기록**이지 파생이 아니다
 *  (`own3` 와 같은 급). 다시 굽지 않는다. */
export interface Underlay {
  layer: number                       // 어느 겹의 것인가
  segs: { a: Pt; b: Pt; hidden: boolean }[]
}
```
- **`Doc.underlays: Underlay[]`**. `.brnl` **version 6**, 1~5 를 다 받는다.
- 모양이 틀리면 **그 밑그림만 버린다**(겹은 남는다 — 썸네일의 선례). 문서를 거부하지 않는다.
- ⚠ **파일이 커진다.** 획 수만큼 선분이 늘고 조각으로 쪼개져 더 는다. **web2-22 3부의
  크기 경고가 여기서 실제로 걸릴 것이다** — 굽기 전후의 바이트를 재서 적는다.
- ⚠ 겹을 지우면 그 밑그림도 간다. 실행취소로 같이 돌아온다.

### 2-c. 언제 굽는가
- **옐로 겹을 얹는 그 순간.** 다른 계기는 없다.
- ⛔ **「다시 뜨기」 버튼을 만들지 마라**(사람이 정했다 — 실제 제도에서 못 한다).
  아래를 고쳤으면 새 옐로를 한 장 더 얹으면 되고, 그러면 쌓인 순서가 곧 작업 이력이다.
- ⚠ 트레이싱지는 밑그림을 안 굽는다 — 3D 가 살아 있어 그냥 보인다.

회귀 팔: ① 보이는 선이 `F`, 가린 선이 `H` 로 그려진다(픽셀 대역 값으로) ② 「가린 선 빼기」
옵션이 돈다 ③ 은선이 **파선이 아니다**(파선 픽셀 0) ④ v5·v6 왕복에서 밑그림이 같다
⑤ 겹 삭제 → 실행취소로 밑그림이 돌아온다 ⑥ 밑그림이 깨진 파일이 **겹은 살린 채** 열린다
⑦ 굽기 전후 파일 바이트(22 3부의 % 와 함께).

3부 — 면이 없을 때
════════════════════════════════════════════════════════
면이 하나도 없는 채로 옐로를 얹으면 와이어프레임이 다 보이는 그 문제가 그대로 난다.

- **막지 않는다.** 그것도 하나의 선택이다(밑그림 없이 자유 스케치만 할 수도 있다).
- **한 줄 안내**: 「면이 없어 뒤엣선이 다 보인다」. 그리고 **면 일괄(web2-21 4부)로 가는
  길**을 그 안내에서 바로 열어 준다.
- ⚠ 안내는 **한 번만** 뜬다. 매번 뜨면 잔소리가 된다.

회귀 팔: ① 면 0 에서 안내가 뜨고 굽기는 정상으로 끝난다 ② 면이 있으면 안 뜬다
③ 안내에서 일괄로 갈 수 있다 ④ 두 번째 옐로에서는 안 뜬다.

4. 안 하는 것
════════════════════════════════════════
⛔ **면 위에 직접 그리기를 만들지 않는다.** 근거 셋이 0 절에 있다. 3D 스케치 앱의 그
   기능은 텍스처링이고 이 도구가 하는 일이 아니다.
⛔ **면끼리 가리게 만들지 않는다.** AS-C19 는 **화면의 규약**이고 은선은 다른 계산이다(1-a).
⛔ **「다시 뜨기」를 만들지 않는다**(2-c).
⛔ **은선을 파선으로 만들지 않는다**(2-a — 파선은 「대기」의 채널이다).
⛔ **그림자를 넣지 않는다.** 법선이 필요해지고 값이 는다. 사람이 「그림자 정도만 렌더링할
   수는 있겠다만」이라 했으나 **이 회차 밖**이다 — `DEFERRED` 에 조건과 함께 올린다.
⛔ 내보내기(SVG·DXF·3DM) — 아직 설계를 안 했다.
⛔ 범위를 넓히지 않는다.
