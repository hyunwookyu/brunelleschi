# web2-28 — 화면 다듬기

## 배경

사용자가 손으로 찾은 것들 중 **화면 층위**의 넷. 거동을 바꾸지 않는다.
27이 끝난 뒤에 한다 (27-2가 겹의 표시 규칙을 바꾸므로 배치보다 먼저다).

이 라운드에는 **관통하는 규칙 하나**가 있다.

> 화면의 말은 **이름이거나 짧은 동사구**다. 설명은 툴팁으로 옮긴다.

---

## 28-1 명령을 실행하면 패널이 접힌다

**현상.** 파일 아이콘처럼 눌러서 패널이 펴지는 것들에서, 안의 명령(예: 비우기)을 실행해도
패널이 그대로 펴져 있다. 볼일이 끝났는데 화면을 덮고 있다.

**가르는 기준.** 무엇을 눌렀느냐가 아니라 **그것이 상태인가 명령인가**다.

| | 접히는가 |
|---|---|
| 명령 버튼 (비우기, 내보내기, 불러오기, 면 찾기 …) | **접힌다** |
| 상태 토글 (체크박스, 스위치) | 안 접힌다 |
| 연속값 (슬라이더) | 안 접힌다 |

오스냅은 한 번에 여러 개를 켜고 끄는 자리다. 절대 접지 마라.
연필통도 등급을 고르는 곳이지만 **하나를 고르면 끝나는 선택**이므로 접힌다.

**작업.** 패널 항목마다 「명령」/「상태」를 명시적으로 표시하고, 접힘은 그 표시만 보게 하라.
버튼 종류를 그때그때 추측하는 코드를 만들지 마라 — 항목이 늘 때마다 틀린다.

**게이트.** 명령 항목 전수에 대해 실행 후 패널이 닫힌다. 상태 항목 전수에 대해 안 닫힌다.

---

## 28-2 툴팁

**작업.**
- 펜을 버튼 위에 **약 600ms** 머무르면 그게 무엇인지 뜬다.
- 문구는 **이미 있는 `title` / `aria-label`을 읽는다.** 새 문자열 테이블을 만들지 마라 —
  두 벌이 되면 갈라진다.
- **펜에서만.** 손가락에는 호버가 없다. 손가락 접촉으로 뜨게 하면 누를 때마다 방해가 된다.
- 그리는 중에는 뜨지 않는다. 획이 시작되면 즉시 사라진다.
- 화면 밖으로 넘치면 안쪽으로 뒤집는다.

**게이트.** 리본·패널의 모든 버튼에 문구가 있다 (빈 `title` 없음). 그리는 중 안 뜬다.
손가락으로 안 뜬다.

---

## 28-3 화면 문구 정리

**규칙(위의 그것).** 화면의 말은 이름이거나 짧은 동사구다. 설명은 툴팁으로.

**사용자가 든 예.**
- 내보내기 뒤의 「나가기만 한다」 — 지운다
- 「지운다, 같이 간다」 — 지운다
- 「종이 질감」 — 종이 안에 있으므로 「질감」

**작업.**
1. 화면에 나가는 문자열을 전수로 뽑아라.
2. 각각을 셋 중 하나로 판정: **이름** / **짧은 동사구** / **설명**.
3. 설명은 화면에서 빼고, 필요하면 그 버튼의 `title`로 옮긴다(28-2가 읽는다).
4. 상위 항목이 이미 말하고 있는 낱말은 뺀다 (종이 안의 「종이」).

**손대지 말 것 — 이건 web2-25에서 이미 정리했다.**
전문 용어는 그대로 둔다. 「오스냅」·「축 스냅」·「소실점」 등은 건축가들이 아는 말이다.
순화하지 마라. 이 항목은 **길이**의 문제지 **어휘**의 문제가 아니다.

**게이트.** 화면 문자열 전수 표를 만들어 보고하라. 각 행에 「바꿈/그대로」와 이유 한 줄.
사용자가 그 표를 읽고 판단한다.

---

## 28-4 손 리본 배치

**바꿀 것.** 면 찾기를 롤·자보다 **아래로** 내린다. 쓰는 빈도가 낮고, 무엇보다 작도 도구가 아니다.

**최종 순서 (위 → 아래).**

```
자 → 연필 → 펜 → 지우개 둘 → 치수 → 롤 둘 → 면 · 면 찾기
```

근거: 위쪽이 손이 자주 가는 자리다. 늘 쓰는 작도 도구가 위, 가끔 쓰는 것이 아래,
작도가 아닌 것이 맨 아래.

**손대지 말 것.** 아이콘 자체는 확정본이다 (`docs/instrument-icons.md`). 다시 그리지 마라.
네 띠 구조(web2-19)도 그대로다. 이 항목은 한 띠 **안의 순서**만 바꾼다.

**게이트.** 순서가 위와 정확히 일치. 손가락 표적 크기 무회귀(실기기에서 통과한 항목이다).
