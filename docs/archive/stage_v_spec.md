## 1. 아키텍처 전환

### 1.1 현재 구조의 문제

```
iPad(capture) → 서버(파서) → Rhino 코드 생성 → PC에서 실행 → 확인
```

왕복이 길고 기기가 둘이다. §1이 줄이려던 지연 그 자체다.

### 1.2 목표 구조

```
iPad 한 화면:
  [캡처 캔버스]  ←→  [Three.js 뷰]
        ↓                 ↑
    스트로크 → 파서 → IR → 씬 빌더
                        ↓
                  Rhino 익스포트 (버튼, 선택)
```

### 1.3 파서 실행 위치

두 안 중 **B를 채택한다.**

**A. 서버 유지** — 기존 Python 파서를 그대로 쓰고 WebSocket으로 왕복.
장점: 코드 재사용 100%. 단점: 네트워크 지연이 A 기준(150ms)을 위협.

**B. 브라우저 이식** — 파서를 TypeScript로 포팅.
장점: 지연 0, 오프라인 동작, 기기 하나. 단점: 포팅 비용.

**B를 택하는 이유**: 파서가 결정론적이고 규모가 작다(DP + PaleoSketch + 축 클러스터링 + 스냅 + 제약 추론). SolveSpace 바인딩이 유일한 난점인데, v1 파서에서 솔버가 하는 일은 직교 스냅 후 폴리곤 폐합이라 자체 구현으로 대체 가능하다.

**단, Python 파서를 참조 구현으로 유지한다.** 두 구현의 출력이 같은지 검증하는 테스트를 두고, 어긋나면 TS 쪽이 틀린 것으로 본다.

### 1.4 포팅 범위

| 모듈 | 이식 | 비고 |
|---|---|---|
| 스트로크 정규화 (DP, 리샘플링) | ○ | 단순 |
| PaleoSketch 프리미티브 인식 | ○ | 가우시안 평활 포함, 핵심 |
| 축 클러스터링 | ○ | |
| 직교 스냅 | ○ | |
| 제약 추론 | ○ | |
| 폴리곤 폐합 | ○ | SolveSpace 대체 |
| 볼륨 다중화 (union-find) | ○ | |
| 관계 추론 (기하) | ○ | |
| 카메라 정합 (호모그래피+PnP) | ○ | 아래 1.5 |
| 발화 번역 (7문법) | △ | 규칙 폴백만 이식, LLM은 서버 |
| Whisper | × | 서버 |
| Rhino 코드 생성 | × | 서버, 익스포트 시에만 |
| SketchGraphs 검증 하네스 | × | 개발용, 서버 유지 |

### 1.5 브라우저 카메라 정합

OpenCV 없이 구현한다. 4점 대응 호모그래피와 PnP는 수십 줄이다.

- `findHomography`: DLT (8×9 행렬 SVD). `numeric.js` 또는 자체 Jacobi SVD
- `solvePnP`: 평면 대상이므로 호모그래피 분해로 충분. K를 가정하고 R,t 추출 후 정규직교화
- 8-way 대응 전수 탐색은 그대로

**검증**: Python 구현과 동일 입력에 대해 fit_error 차이 < 1e-6.

## 2. 실시간 파이프라인

### 2.1 증분 갱신

전체 재파싱하지 않는다. 획이 추가될 때 영향 범위만 다시 푼다.

```
새 획 도착
  → 공간 인덱스로 영향 볼륨 후보 조회 (bbox 교차 + 근접)
  → 해당 볼륨의 획 집합만 재파싱
  → IR 부분 갱신
  → 씬 diff 적용 (전체 재빌드 금지)
```

**디바운스**: 획 종료(pen-up) 후 80ms. 연속 획을 묶어 처리한다.
**중단**: 파싱 중 새 획이 오면 진행 중 작업을 버리고 재시작.

### 2.2 씬 diff

Three.js 오브젝트를 매번 새로 만들면 GC가 프레임을 먹는다.

- 볼륨 id → Mesh 매핑 유지
- 변경: geometry만 교체 (`dispose()` 필수)
- 추가/삭제: 오브젝트 풀에서 대여/반납
- 라벨: CSS2DRenderer 또는 스프라이트, 볼륨과 같은 생명주기

### 2.3 워커

파싱이 메인 스레드를 막으면 그리기가 끊긴다.

- 파서를 Web Worker로 분리
- 스트로크는 Transferable(ArrayBuffer)로 전달
- IR은 구조적 복제로 회신
- 워커 응답 대기 중에도 잉크는 계속 그려진다

## 3. 화면

### 3.1 레이아웃

iPad 가로 기준.

```
┌─────────────────────┬──────────────────┐
│                     │                  │
│   캡처 캔버스        │   3D 뷰          │
│   (잉크)            │   (Three.js)     │
│                     │                  │
├─────────────────────┴──────────────────┤
│ [평면][투시] [🎤] [실행취소] [내보내기]  │
└────────────────────────────────────────┘
```

- 분할 비율 드래그 조정, 6:4 기본
- 전체화면 토글 (각 패널 단독)
- 세로 방향은 상하 분할

### 3.2 프레임

§4.3 펜 채널과 별개로, 캔버스에 프레임을 둔다.

- **평면 프레임** / **투시 프레임** 탭 전환
- 각 프레임은 독립 좌표계, 같은 IR을 공유
- 투시 프레임에는 평면에서 확정된 바닥 폴리곤의 예상 투영이 옅게 표시 (정합 힌트)

### 3.3 3D 뷰 조작

- 1지 드래그: 궤도 회전
- 2지: 팬/줌
- **[시점 복귀] 버튼**: 정합된 카메라로 되돌린다. 이게 핵심 기능이다
- **[탑뷰] 버튼**: 평면 확인

### 3.4 오버레이

투시 프레임에서 정합이 성공하면:

- 3D 뷰 배경에 그린 투시 이미지를 깐다
- 모델을 반투명 와이어프레임으로 겹친다
- 배경 투명도 슬라이더
- 어긋난 선을 다른 색으로 (재투영 오차 임계 초과분)

### 3.5 confidence 표시 (§3.5 확장)

| confidence | 표시 |
|---|---|
| ≥ 0.8 | 불투명 면 + 실선 엣지 |
| 0.5~0.8 | 반투명 면(0.5) + 실선 엣지 |
| < 0.5 | 면 없음, 파선 와이어프레임만 |

**이게 완료 판정 D를 만족시키는 장치다.** 30% 완성 시점에 파선 상자가 보여야 한다.

낮은 confidence 볼륨이 사라져도 시각적으로 자연스럽다 — 원래 확정된 적이 없기 때문.

### 3.6 치수 표시 (§3.5)

- 명시 치수: 실선 치수선 + 숫자
- 범위 내 확정: 실선 + `~12.0m`
- 비례 전파: 파선 치수선

3D 뷰에서 볼륨 선택 시 해당 볼륨의 치수만 표시.

- 세션 종료 시 전체를 다시 읽어 덮어쓴다 (뒤 발화가 앞을 고치므로)

## 5. 잉크 캡처 보강

### 5.1 현재 확인 필요

기존 `stage1/capture/index.html`이 Pointer Events를 쓰고 있는지, `pressure`/`tiltX`를 저장하는지 확인하고 없으면 추가한다.

### 5.2 필수 처리

- **팜 리젝션**: `pointerType === 'pen'`만 잉크로. touch는 제스처로
- **Coalesced events**: `getCoalescedEvents()`로 고주파 샘플 확보. 안 쓰면 60Hz로 떨어져 획 품질이 나빠진다
- **Predicted events**: `getPredictedEvents()`로 렌더 지연 보정 (선택)
- **더블탭 방지**: `touch-action: none`, 확대 차단
- **화면 꺼짐 방지**: Wake Lock API

### 5.3 스트로크 저장

§4.1 포맷 유지. 필드 추가:

```json
{
  "points": [[x, y, t, p, tiltX, tiltY]],
  "pen": "id",
  "frame": "plan|persp",
  "seq": 0
}
```

`seq`는 획 순서. 부분 획 검증과 시간 단조성 검사에 쓰인다.

| 파서 (8볼륨 증분) | < 80ms |
| 씬 diff 적용 | < 20ms |
| 카메라 정합 | < 50ms |
| **획 → 3D 총 지연 p95** | **< 150ms** |
| 초기 로드 | < 3s (3G 제외) |
| 메모리 (20분 세션) | < 200MB |

예산 초과 시 프로파일링 결과를 `progress.md`에 남기고 원인별 대응을 보고한다.

## 9. 구현 순서

각 단계 종료 시 커밋하고 테스트를 돌린다.

### V-1. 파서 포팅 (가장 큼)

1. TS 프로젝트 구성, 기존 스키마를 TS 타입으로
2. 정규화 → PaleoSketch → 축 클러스터링 → 스냅 → 폐합 순으로 포팅
3. **각 모듈마다 Python 참조 구현과 출력 일치 테스트**
4. 볼륨 다중화, 관계 추론
5. 카메라 정합 (SVD 자체 구현 포함)
6. 전체 파이프라인 일치 검증 — SketchGraphs 홀드아웃에서 Python과 f1 차이 < 0.01

### V-2. Three.js 뷰어

1. 씬 초기화, 카메라, 조명, 그리드
2. IR → 볼륨 메시 (압출)
3. 씬 diff (오브젝트 풀, dispose)
4. confidence 표시 (§3.5)
5. 라벨, 치수 표시
6. 카메라 정합 적용 + 배경 이미지 오버레이
7. 시점 복귀 / 탑뷰 버튼

### V-3. 실시간 연결

1. Web Worker에 파서 배치
2. 증분 갱신 (영향 범위 조회)
3. 디바운스 + 중단 처리
4. 지연 계측 훅

### V-4. 화면 구성

1. 분할 레이아웃, 드래그 조정
2. 평면/투시 프레임 탭
3. 투시 프레임 정합 힌트
4. 3D 조작 (터치)

### V-5. 잉크 보강

1. 팜 리젝션, coalesced events
2. tilt 저장, seq 부여
3. Wake Lock, 확대 차단

### V-6. 발화

1. MediaRecorder + 마이크 권한
2. 서버 Whisper 엔드포인트
3. 부분 전사 (30초)
4. 규칙 폴백 브라우저 이식
5. 번역 로그 UI + 수정

### V-7. 저장·내보내기

1. IndexedDB 세션
2. 자동 저장
3. 4종 내보내기
4. §14 로깅 연결 + 수정 유형 질의

### V-8. 통합 검증

1. Playwright 하네스
2. S1~S10 시나리오
3. 성능 측정, 예산 대비 보고
4. 스크린샷 회귀

## 10. 멈춤 조건 (§13 준용)

- 파서 포팅에서 Python 대비 f1 차이 > 0.01
- 지연 예산을 두 배 이상 초과하고 원인 불명
- 같은 오류로 3회 실패
- IR 루트 필드가 12개 초과
- 기존 32 테스트 중 하나라도 실패

**멈추지 않는 것**: 개별 시나리오 실패, 성능 예산 소폭 초과, UI 세부.
잠정 처리 후 `checkpoints.md`에 누적하고 계속한다.

## 12. 이 작업 후 남는 것

프로토타입은 완성되나 다음은 여전히 없다.

- 실제 사람 손 획으로 검증된 적 없음 (§14 로깅이 그 경로)
- 질의 루프 (§6), 정정 학습 (§7)
- 층, 두께, 개구부, 사선, 곡선
- 다중 사용자, 서버 저장, 공유

이것들은 프로토타입 완료 후 별도 판단 대상이다.
