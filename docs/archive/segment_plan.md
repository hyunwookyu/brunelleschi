# 세그먼트 기반 재설계 — 계획

작성 2026-08-15 / 코드명 G (geometry)
docs/sketch3d_plan.md의 §4(획 → 3D)와 §5(자료구조)를 대체.
§3(카메라 확정), §1(제품 정의)은 유지.

---

## 0. 왜 바꾸는가

완주 후 판정이 "첫 시점에서 그리는 데는 겨우 선다, 돌려서 그리는 데는
서지 않는다"였다. 원인이 둘이다.

### 0.1 뷰포트를 분리했다

왼쪽 2D 캔버스와 오른쪽 3D 뷰를 나눠 왕복시켰다.
그래서 "첫 시점"과 "돌린 시점"이 별개 좌표계가 됐고, 여기서 파생된 문제:

- 돌린 시점 획이 첫 캔버스에 엉뚱하게 그려짐 (pts2d 좌표계 혼동)
- 돌린 시점 사선 오배정 — 자동으로 놓인 90건 전부 크게 틀림
- 시점 교차 시 후보가 0이 되는 미배치

### 0.2 획을 그대로 정합하려 했다

손떨림이 있는 곡선을 3D에 놓으려니 끝점 겨냥 오차가 그대로 배치 오차가 됐다.

- 배치율 0.846(첫 시점) / 0.112~0.419(돌린 시점)
- 사선이 축으로 오인 15.8%(첫 시점) / 79%(돌린 시점)
- 고치기 상한 모형에서도 21~35%가 크게 틀림
- 성립 구간이 끝점 오차 ≲1%인데 실측 자릿수가 2.8~5.1%

### 0.3 원칙은 유지된다

"획을 그대로 보존한다"를 어기지 않는다.
**보이는 것은 여전히 손 획**이고, 스냅 직선은 화면에 나오지 않는 내부 기하다.
손떨림은 그대로 남고, 그 획이 어느 3D 선에 속하는지만 직선이 정한다.

기존 원칙("방향만 판정하고 형태는 건드리지 않는다")의 확장이다 —
방향뿐 아니라 **위치도 직선이 정하고, 형태는 여전히 획이 정한다.**

## 1. 자료구조

```
Segment {
  id
  axis        // VP1|VP2|VP3|screen|face|free
  origin: Vec3, dir: Vec3   // 무한직선 L
  t0, t1      // 획이 정한 구간
  joints[]    // 다른 세그먼트와의 교차점
}

Stroke {
  id
  pts2d[]           // 원본 화면 좌표 (보존, 재계산용)
  segmentRef        // 매달린 세그먼트
  params[]          // 각 점의 L 위 매개변수 t
  offsets[]         // 각 점의 L로부터의 이탈 (떨림)
  mesh, color, width
}
```

**3D 위치는 `L(t) + offset(t)`로 재구성된다.**
세그먼트가 기하이고 오프셋이 표현이다.

교차·접합 판정이 전부 세그먼트끼리 일어나므로 손떨림이 계산에 들어오지 않는다.

---

## 2. 획 → 세그먼트

```
획 → 방향 판정 (어느 축인가)
   → 축 방향 무한직선 L 생성 (위치는 §3 앵커)
   → 획 양 끝을 L에 수직 투영 → 세그먼트 [t0, t1] 확정
   → 각 점을 L 위 매개변수 t로 파라미터화
   → 각 점의 L 이탈을 오프셋으로 보관
```

**획이 직선의 길이를 정한다.** 직선을 먼저 만들고 획을 맞추는 것이 아니므로,
"획이 직선보다 길거나 짧은" 문제가 발생하지 않는다.

### 2.1 떨림 평면

L과 시선이 만드는 평면의 법선 방향으로 오프셋을 둔다.
그린 시점에서 화면 투영이 원본과 정확히 일치하고(§4.5 보장 유지),
회전하면 떨림이 자연스럽게 3D로 보인다.

현재 `facing` 평면이 이 방식이므로 변경 없다.

---

## 3. 접합 — 세그먼트 3D 교차

기존: 획 끝점끼리 반경 안에 있는지 검사. 오차가 그대로 실패가 된다.

변경:

```
새 세그먼트 S를 기존 세그먼트들과 3D 교차 검사
  → 축이 다르면 최근접점 쌍 계산
  → 거리가 임계 안이면 교차로 판정
  → 두 세그먼트를 그 점까지 연장하거나 절단
```

**끝점이 정확할 필요가 없다.** 조금 못 미치거나 지나쳐도 교차점이 계산된다.
지나침이 오히려 정상이고, 손으로 그릴 때 자연스러운 동작이다.

현재 미배치의 대부분이 "끝점이 후보 반경 밖"인데, 교차 기반이면 그 개념이 없다.

### 3.1 앵커 — 씨앗 하나만

기존: 획마다 앵커를 찾고 못 찾으면 미배치.

변경: **첫 획만 앵커가 필요하고 나머지는 교차로 전파된다.**

```
첫 획   : 지면 접촉 가정(Z=0) 또는 화면 중앙 깊이
이후    : 기존 세그먼트와 교차 → 그 점이 깊이를 준다
         교차 없음 → 가까운 세그먼트와 같은 평면 가정
         그것도 없음 → 미배치 (화면에 남김)
```

연결된 것이 하나만 있어도 놓인다.

## 4. 화면 통합

### 4.1 겹침

```
초기 : 2D 잉크 층과 3D 씬이 같은 자리에 겹쳐 있다 (사용자는 모른다)
     ↓ 획 몇 개로 소실점이 잡히면
전환 : 2D 층이 사라지고 3D 카메라가 그 투시에 맞춰진다
     ↓
이후 : 계속 3D 위에 그린다
```

전환이 한 번뿐이고 그 뒤로는 뷰포트가 하나다.
**"첫 시점 / 돌린 시점"이라는 구분 자체가 없어진다.**
회전은 카메라 조작이고 좌표계는 계속 같다.

### 4.2 전환 조건

- 3점: 서로 다른 축 방향 3개가 각각 2획 이상 확인
- 2점: 축 2개 + 렌즈 슬라이더
- 1점: 축 1개 + 렌즈 슬라이더

상자 하나를 그리면 3점 조건이 자연스럽게 충족된다.

### 4.3 전환의 무변화

**카메라가 맞았다면 전환 순간 화면이 똑같아야 한다.**
사용자는 전환을 눈치채지 못한다. 뭔가 튀면 그것이 카메라가 틀렸다는 신호다.

전환 전후 화면 픽셀 차이를 측정 지표로 삼는다.

### 4.4 소실점 잠금

전환 후 카메라가 잠긴다. 이후 획은 소실점 갱신에 기여하지 않는다.

기존 §3.7 소프트 락보다 강하다 — 갱신 자체를 하지 않는다.
현재 "점을 찍거나 선을 그을 때마다 소실점이 튀는" 문제가 여기서 해소된다.

**되돌리기**: "카메라 재설정" 버튼 하나.
2D 상태로 돌아가고 그린 획은 남는다. 다시 잡히면 새 카메라로 전부 재계산된다.

## 5. 실시간 축 미리보기

기존: 그은 뒤에 판정. 틀리면 나중에 안다.

변경: **그리는 도중 축 색이 실시간으로 바뀐다.**

```
포인터 이동 중 : 현재 방향으로 판정한 축 색으로 획을 그린다
                축이 바뀌면 색이 즉시 바뀐다
펜 뗄 때       : 그 시점 색이 확정
```

사용자가 그으면서 본다. 틀린 색이면 각도를 조금 틀어 고친다.

**이것이 오배정 15.8%와 79%를 동시에 줄인다.**
사후 검사보다 강하고, 2D 증거로 구분 불가한 경우
(사선이 축 소실점을 2° 안으로 지나는 것, D-S22)도 사용자가 보면 안다.

축을 강제하지 않는 수정자(Shift 등)도 함께 둔다.

## 9. 위험

**교차 임계.** 세그먼트끼리 얼마나 가까우면 교차로 볼 것인가.
끝점 반경보다 관대해도 되지만, 너무 크면 무관한 세그먼트가 붙는다.
G-A에서 측정으로 정한다.

**첫 획의 깊이.** 씨앗 하나가 전체 스케일을 정한다.
틀리면 전부 함께 틀리지만, 상대 형태는 유지되므로 나중에 조정 가능하다.

**실시간 미리보기의 지연.** 포인터 이동마다 축 판정이 돌아야 한다.
현재 획 지연이 중앙 2.15ms이므로 여유가 있으나 측정 필요.

**전환 무변화.** 카메라가 정확히 맞아야 성립한다.
어긋나면 사용자가 전환을 인지하고, 그게 결함 신호가 된다.
어느 정도 차이까지 허용할지 G-B에서 정한다.

**실획 표본이 여전히 0이다.** 모든 임계가 Quick,Draw 기준 합성값이다.
이번 접근이 끝점 오차에 덜 민감하므로 그 의존이 줄지만, 축 판정은 그대로다.

## 10. assumptions

**신규**
- "세그먼트 교차가 끝점 반경보다 많이 붙인다" — G-A.1이 측정
- "씨앗 하나로 전파가 충분하다" — 연결 안 된 획의 비율로 확인
- "실시간 색 미리보기가 오배정을 줄인다" — 사용자 행동 의존, G-C에서 간접 측정
- "전환이 무변화로 보인다" — 픽셀 차이로 측정
- "획이 세그먼트의 길이를 정한다" — 획이 지나치거나 못 미쳤을 때
  교차가 그것을 흡수하는지

**유지**
