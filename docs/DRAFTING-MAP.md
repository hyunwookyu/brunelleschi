# 제도판 대응표

> 이 도구는 **제도판 위에 놓인 종이와 제도용구**로 느껴져야 한다. 메뉴와 도구모음이
> 아니다.
>
> ⚠⚠ **다만 말을 순화하는 일이 아니다.** 이 도구를 쓸 사람은 건축가이고 스냅 용어를
> 이미 안다. 「오스냅」을 「점 물림」으로 바꾸면 아날로그해지는 게 아니라 **부정확해질
> 뿐**이다. 아날로그를 만드는 것은 **아이콘과 배치**이고, 말은 **정확한 것**을 쓴다.
> 손대는 것은 **사용자가 신경 쓸 이유가 없는데 화면에 나와 있는 기술 서술**이다.
>
> 2026-08-27 작성 · 같은 날 개정(언어 순화 철회). `docs/DRAFTING-MAP.md`

## 0. 원칙 — 셋으로 가른다

| 무리 | 판정 | 어떻게 |
|---|---|---|
| **① 실물이 있다** | 연필·자·지우개·트레이싱지 | **아이콘을 실물로.** 이름은 이미 맞다 |
| **② 제도·CAD 의 말이다** | 지평선·소실점·오스냅·축 스냅·끝점·중점 | **그대로 둔다.** 사용자가 아는 말이다 |
| **③ 사용자가 신경 쓸 이유가 없다** | 자립 3D·대기 감쇠·렌더러 이름·승격 | **화면에서 뺀다.** 못 빼면 평범한 말로 |

### 규칙 하나 — 아이콘이 실물이면 동작도 실물이어야 한다

자 아이콘을 눌렀는데 체크박스가 뜨면 어긋난다. 실물 아이콘은 **약속**이다:
자는 **놓고 치우는** 것이지 켜고 끄는 것이 아니다. 이 규칙 때문에 빠진 기능이 하나
드러났다(§3).

### 규칙 둘 — 형태가 가른다, 색이 아니다

이 도구는 색을 세 번 뺐고(소실점 ✕ → 오스냅 → 축 넷) 지금 색을 갖는 것은 「탭하면
무엇이 되는가」의 예고뿐이다. 실물 아이콘은 그 결정과 **같은 방향**이다 — 자와
지우개는 형태가 다르므로 색이 필요 없다. **아이콘을 실물로 바꾸면서 색을 도로 들이지
않는다.**

## 1. ① 아이콘을 실물로 — 이름은 그대로

| 이름 (그대로) | 제도판의 실물 | 아이콘 |
|---|---|---|
| 연필 (2H~2B 랙) | 연필 | **랙 자체가 실물이다** — 아이콘보다 낫다. 지금 형태 유지 |
| 펜 · 니브 | 로트링 제도펜 | `ph:pen-nib` |
| 지우개 | 지우개 | `ph:eraser` |
| **축 스냅** | **삼각자 · T자** | **`mdi:set-square`** — 사람이 직접 지목한 자리다 |
| **오스냅** | 디바이더로 점을 옮겨 찍기 | **`ph:compass-tool`** (제도용 컴퍼스) |
| 치수 | 스케일 자 | `ph:ruler` |
| 축척 | 삼각 스케일 | **직접 그린다** |
| 지면 격자 | 바닥 눈금 | `ph:grid-four` |
| 트레이싱지 · 옐로 | 그대로 | **직접 그린다** (트레이싱지 롤 — `instrument-icons.md` 정본 · §5의 자작 목록과 같다) |
| 종이 (탭) | 도면집의 한 장 | 탭 자체가 종이다 |
| 면 | 채색 · 포셰 | 평행사변형 (지금 그대로) |
| 비우기 | — | 지금 그대로. 「새 종이」로 바꾸지 않는다 — 탭의 「+」와 말이 겹친다 |

⚠ **이름을 바꾸는 항목이 하나도 없다.** 이 표의 일은 아이콘과 배치다.

---

## 2. ② 그대로 두는 말

바꾸면 부정확해지거나 낯설어진다. 이 도구를 쓸 사람은 이 말을 이미 안다.

**투시 작도**: 지평선 · 소실점 · ✕ 표식 · 눈높이 · 1점/2점 투시 · 작도 시점 · 파선
**스냅**: 오스냅 · 축 스냅 · 스냅 반경 · 끝점 · 정점 · 중점 · 교차점 ·
**겉보기 교차**(AutoCAD 의 말 그대로) · 수선의 발 · 연장선 · 근처점 · 소실점
**그 밖**: 치수 · 축척 · 면 · 종이 질감 · 겹침선(모서리 넘기기)

⚠ 오스냅 기호(□ ◇ △ ✕ …)도 그대로다. Rhino·AutoCAD 의 기호를 아는 사람에게는
그것이 곧 이름이다.

---

## 3. ③ 화면에서 뺄 것 — 사용자가 신경 쓸 이유가 없는 것

여기가 이 표의 실제 일이다.

| 지금 화면의 말 | 판정 | 어떻게 |
|---|---|---|
| **「획이 위치를 소유한다 (개정 3)」** | ⛔ 실험 깃발이 설정에 나와 있다 | **설정에서 뺀다** → 진단 패널로. 없애지는 않는다(A-4 로 옛 경로 유지) |
| **「대기 획은 그린 시점에서만」** | 내부 동작의 서술 | **「다른 각도에서는 숨긴다」** |
| **「무한소수 표기」** | 내부 서술 | **「소수점 그대로」** |
| classic / brush 렌더러 | 내부 이름 | 화면에는 **「종이 질감」** 하나 (지금도 그렇다 — 내부 이름이 새어 나오지 않게만) |
| 대기 · 승격 | 화면에 이름이 안 나온다 | **그대로 안 쓴다.** 파선이 말한다 |
| 진단 패널 | 감춰져 있다 | 그대로 |

⚠ 이 넷 말고는 건드리지 않는다. **더 찾아내려 하지 마라** — 정확한 말을 지우는 쪽이
손해다.

---

## 4. ⚠⚠ 표를 만들다 드러난 것 — **자를 치울 수 없다**

축 스냅은 **임계가 없고 자유 방향이 없다.** 확정 획은 언제나 가장 가까운 축에 붙는다
(`draft.ts` 갈래 ④ — 「그 외에는 항상 가장 가까운 축이다」). 자유로 남는 것은 둘뿐이다:
소실점에서 뻗는 살, 그리고 새 축을 만드는 획.

이것을 실물로 옮기면 **삼각자를 영영 못 치우는 상태**다.

실제 제도판에서는 자를 치우는 일이 늘 있다 — 수목, 인물, 가구의 곡선, 스케일감을
주는 낙서. 지금은 그 길이 없다. **삼각자 아이콘을 붙이는 순간 그 약속이 화면에
생긴다**(규칙 하나) — 그러니 이 자리는 언젠가 답해야 한다.

⚠ 기본값은 **자를 댄 상태**다. 이 도구는 작도 도구이고 자유 곡선이 예외다.
그리고 자를 치운 획은 축이 없으므로 3D 로 안 올라간다 — 대기로 남거나 2D 장식으로
남는다. **그 갈래를 어떻게 둘지가 다음 결정이다.** 여기서 정하지 않는다.

## 5. 아이콘 — 최종 (2026-08-27 확정)

⚠⚠ 실물 렌더 시도(면 분할·그라데이션·평면 단면)는 **전부 폐기**됐다. 사람이 정했다:
「소스로 가져왔던 아이콘 모음으로 가고, **직접 그리는 도구는 원래 프로그램에서 쓰던 거
유지.** 소스 아이콘 스타일 유지해서 나머지 없는 것들 그리자.」

| 갈래 | 무엇 | 어떻게 |
|---|---|---|
| **직접 그리는 도구** | 연필통 · 펜 · 지우개 둘 · 면 | **지금 앱의 실물 그림 유지. 손대지 않는다** |
| **그 외 전부** | 축 스냅 · 오스냅 · 치수 · 겹 · 동작들 | **선 아이콘 하나의 문법** — Phosphor(light)·mdi + 같은 문법의 자작 |

- 소스 배정: **축 스냅 = mdi `set-square`** · **오스냅 = ph `compass-tool`** ·
  치수 = ph `ruler` · 격자 = ph `grid-four` · 동작 = ph `arrows-out`·`plus`·`eye`·
  `eye-slash`·`lock-simple` 등. 굵기는 **light**(지금 앱의 가는 선과 무게가 맞는다 —
  세션이 화면 대조로 확정하고 원장에 적는다).
- 세트에 없는 것(**트레이싱지 롤 · 삼각 스케일 · T자**)은 `docs/instrument-icons.md` 의
  자작 원본을 쓴다 — **같은 선 문법**(fill:none · stroke currentColor · round)이다.
- **트레이싱지/옐로 구분은 아이콘이 한다**(사람이 정했다): 옐로 롤만 고리를
  **`#e9d98a`** 로 채운다. 색 칩을 따로 두지 않는다 — 옐로 트레이스는 이름 자체가
  색이라 정체가 아이콘 밖으로 나가면 안 된다. **선 아이콘의 유일한 색 예외**다.
  ⚠ 22px 랙에서 「선택됨」으로 오독되는지는 실기기 확인 항목이다(`instrument-icons.md`).
- 넣는 법: `npm i -D @phosphor-icons/core`(개발 의존성 · light 는 `*-light.svg`) →
  path 만 `index.html` 로 → `LICENSE` 는 **받은 패키지의 파일을 읽어** 한 줄.
  자작 셋은 npm 무관 — md 가 정본. ⛔ CC BY 세트 금지.

## 6. 화면 배치 — 네 자리 (2026-08-27 확정)

사람이 물었다: 「그리기 도구나 스냅 등 기능적 도구, 파일 등 시스템 도구로 직관적으로
UX에서 잘 구분되어 있는 상태인가?」 **아니었다** — 오른쪽 막대에 다섯 층위가 한 줄로
쌓여 있었고 가르는 채널이 공백 하나뿐이었다.

| 자리 | 무엇 | 근거 |
|---|---|---|
| **위 왼쪽** | **종이** — 탭 + 그 아래 **종속 탭**(트레이싱지·옐로) | 어느 장인가. 겹은 도구가 아니라 종이다 |
| **위 오른쪽** | **눈** — 작도 시점으로 · 전체 화면 · 표시(지평선 · 지면 격자 · 다른 각도에서는 숨긴다) | 「이 종이를 어떻게 보는가」는 종이 옆이 제자리 |
| **오른쪽 세로** | **손** — 자(스냅) · 연필통 · 펜 · 지우개 둘 · 면 · 굵기 · 치수 | 매 획마다 쓴다 → 펜이 닿는 쪽 |
| **오른쪽 맨 아래(접힘)** | **서랍** — 파일 · 종이 질감 · 진단 | 가끔 연다 |

- **되돌리기·다시실행**은 은유가 없다(제도판에서는 지우개가 그 역할). **손 띠 맨 위**에
  두되 도구와 시각적으로 가른다.
- **자(삼각자) = 스냅 묶음의 입구.** 누르면 오스냅 종류·반경이 열린다. 이것으로
  **「기능적 도구」 층위가 처음으로 화면에 존재**하게 된다. ⚠ 「자를 치우는」 토글은
  아직 없다 — 묶음 안에 **자리만** 비운다(§4).
- **가르는 채널이 공백이 아니다**: 도구는 종이 위에 **놓여 있고**(배경 없이), 서랍은
  **닫혀 있고**(`<details>`), 종이 띠는 **종이의 가장자리**다.
- ⛔ 리본을 만들지 않는다. 선례(Procreate · Krita · Concepts · Clip Studio)가 전부
  「떠 있는 크롬을 줄이고 필요할 때 펜 끝에 불러낸다」로 간다.
- **나중**: 펜 끝 팝업(길게 누르면 경도 고르기가 펜 자리에) — Krita 팝업 팔레트 ·
  Concepts 툴 휠. 경도 7단계가 원형에 정확히 맞는다.

## 6-b. 겹 — 종속 탭이고 목적을 제안하지 않는다

사람이 정했다: 「트레이싱지와 옐로페이퍼를 종이(탭)에 **종속된 탭**처럼. **앱에서 기능을
굳이 구분하거나 제안하지는 말고** 사실상 같은 건데 사용자가 자기 목적에 맞게 갖다 쓰도록.
종이와 다른 건 **여러 개를 같이 겹쳐볼 수 있다는 것.**」

- 종이는 **배타적**(하나만 활성), 겹은 **가산적**(여럿 동시). 그 차이가 형태로 갈려야 한다.
- 상태는 **켬/끔 둘**이다 — 겹이 쌓이면 아래는 저절로 흐려지므로 `dim` 이 필요 없다.
- 중요한 것은 목적이 아니라 **얹었을 때 어떻게 보이느냐**다: **곱 합성**(겹칠수록 어두워지고
  짙어진다 — 알파는 반대로 밝아진다) · **섬유질은 층마다 다른 시드**(`rng32(layer.id)` —
  같은 무늬가 겹치면 곱해져 격자가 드러난다) · 바탕 종이에는 결을 **안 준다.**

## 7. 이 표가 아직 안 정한 것

- **자를 치운 상태**의 갈래(§4) — 그 획이 3D 로 안 올라가는데 어떻게 둘 것인가.
- **T자와 삼각자를 가를 것인가.** 지금 축은 {vp0, vp1, V} 또는 {vp0, H, V} 셋이고
  한 「자」가 셋을 다 한다. 하나로 두는 것이 맞다고 보지만 적어 둔다.
- **트레이싱지 롤을 어떻게 그릴 것인가** — 직접 그릴 다섯 중 가장 자주 보인다.
