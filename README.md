# SKETCH2SPACE — 실기 테스트 안내

투시 스케치 3D 도구. 현행 계획서는 [`docs/sketch3d_plan.md`](docs/sketch3d_plan.md),
작업 규칙은 [`CLAUDE.md`](CLAUDE.md), 진행 기록은 [`progress.md`](progress.md).

이 문서는 **실제로 그려보고 그 획을 측정에 넣기까지의 절차**를 다룬다.
**이 도구가 무엇을 못 하는지와 그 수치**는 [`PROTOTYPE.md`](PROTOTYPE.md)에 따로 있다 —
쓰기 전에 그것부터 읽는 편이 낫다.

---

## 0. 실획을 주시면 무엇이 달라지는가 (**지금 가장 필요한 것**)

이 프로젝트의 **가장 큰 위험 둘이 표본 문제**다.

| 전제 | 지금 값 | 출처 | 문제 |
|---|---|---|---|
| **AS-6** 한 획 = 한 축 | 위반율 **0.699**(n=1816) · 꺾인 획 비율 0.6775(n=4785, 다른 표본) | Quick,Draw | 마우스·손가락 **낙서**다 |
| **AS-12** 끝점 겨냥 오차 | **0.028~0.051** (성립 구간은 ~0.01) | Quick,Draw 환산 | 위와 같고, 게다가 **다른 양**을 환산한 것이다 |

둘 다 **대상 사용자(스타일러스·투시도 숙련자)를 대표하지 않는다**(AS-13).
그래서 **이 수치로 설계 결정을 하지 않는다** — tolerance를 넉넉히 잡거나 판정을 보수적으로
만들거나 미배치 폴백을 과하게 설계하지 않는다. 현재 값은 잠정이고, **실획이 들어오면 조정한다.**

### 획을 주는 방법

1. 앱을 연다(아래 1절. iPad든 데스크톱이든 좋다).
2. 소실점을 확정하고 **평소대로** 그린다. 고쳐 그리지 말고 평소 손대로 긋는다 —
   재는 것이 손의 성질이므로 잘 그리려고 하면 측정이 망가진다.
3. 하단 **"획 내보내기"**를 누른다(세션 JSON이 내려받아진다).
4. 그 파일을 저장소의 **`sessions/`** 에 넣는다.
5. `cd web && npx vitest run test/real_ink.test.ts` →
   `stage0/out/real_ink.json`에 AS-6·AS-12·미배치율·화각별 편차가 기록된다.

담기는 것: 원본 포인터 표본 `[x, y, t, 필압, 기울기X, 기울기Y]` + 판정 결과 + 배치 결과 + 카메라.
담기지 않는 것: 사용자 식별 정보. 화면 좌표와 그림 내용뿐이다.

## 0.5 이 도구가 지금 하는 것과 **안 하는 것** (범위)

**전제**: 그린 획을 그대로 3D로 올린다 — 직선으로 펴지 않고 손떨림도 남긴다(`CLAUDE.md` §1).
그 전제 위에서 **자동으로 놓는 범위가 좁다.** 좁힌 것은 전부 "놓은 것이 맞는지 확인할 수단이
있는가"로 갈렸고, 수단이 없으면 **놓지 않고 사용자에게 넘긴다**(A-3 · D-S15).

| 획 | 자동 배치 | 왜 |
|---|---|---|
| 소실점 셋 중 하나를 향하는 **곧은 획** | **된다** | 축 + 앵커가 획 전체를 정한다 |
| 화면과 나란한 곧은 획 | 된다 | 같은 이유(소실점이 무한원) |
| **면 위 사선**(곧은 것) | 된다 — 첫 시점에서만 | 축 두 개가 펴는 평면 + 시선 광선(D-S14). **돌린 시점에서는 안 한다**(D-S19) |
| **한 획에 방향이 둘 이상**(꺾인 획) | **안 된다** | 축 하나에 담을 수 없다(D-S3). **Quick,Draw 낙서**의 **67.7%**가 여기 해당한다(AS-6·AS-13) |
| **크게 휜 획**(`bend > 0.18`) | **안 된다** | 평면 경로의 검사가 **끝점 둘**만 보므로 가운데가 검증되지 않는다(D-S17) |
| **경사 방향**(지붕·계단) | **안 된다** | 경사 소실점은 후보가 직선이라 획으로 못 가른다(D-S17) |
| 아무것에도 안 닿는 획 | 안 된다 | 깊이를 정할 근거가 없다 |

**곧은 축 획도 늘 놓이는 것은 아니다.** 정합성 검사가 앵커를 못 고르면 안 놓는다 —
합성 조건(끝점 오차 1%)에서 **축이 정해진 획의 15%가 미배치**다(D-S16). 조용히 틀리게 놓는
것보다 낫다는 선택이고, 그래서 아래 `고치기`가 있다.

**안 놓인 획은 사라지지 않는다.** 화면에 회색 파선으로 남고 **`고치기`로 직접 붙인다** —
후보 점을 누르거나 깊이를 직접 준다(D-S18). 양 끝을 다 고르면 확정, 한쪽만 고르면
**미확정(주황)**으로 표시된다. 돌린 시점에서 그린 획은 그 시점으로 돌아가면 같은 방법으로 붙인다.

### ⚠ 돌려서 그릴 때 사선을 조심한다

돌린 시점에서 **면 위 사선**을 그으면 **축으로 잘못 읽히는 일이 있다**. 화면에서 소실점을
지나는 선은 그 축과 **구분되지 않기** 때문이고(투영의 애매성), 임계로는 안 갈린다 —
그 사선들은 축 소실점에 **2° 안으로** 맞는다(D-S22).

대응으로 **돌린 시점의 판정을 보수적으로** 했다(부적합도 임계 절반 + 정합성 검사 필수).
조용히 틀린 배치가 궤도에 따라 **29~80% 줄지만 완전히 없어지지는 않는다.**
대가로 **돌린 시점의 배치율이 절반 아래로 떨어진다** — 안 놓인 획은 `고치기`로 붙인다.

**사선은 첫 시점에서 긋는 편이 안전하다**(첫 시점의 오배정은 15.8%다).
잘못 놓인 것은 `고치기`로 다시 지정할 수 있다.

### 굽은 획이 얼마나 되는가

`bend > 0.18`이면 자동 평면 배치에서 빠진다. Quick,Draw 실획에서 그 비율은 **60%**인데,
**갈라 세면 다른 그림이 나온다**(`stage0/out/bend_share.json`):

| | 비율 | `bend > 0.18` |
|---|---|---|
| **꺾인 획**(한 획에 방향이 여럿) | 67.7% | 88% |
| **매끄러운 획**(방향 하나) | 32.3% | **1.2%** |

**두 수를 다 읽어야 한다.** `freeBendMax`가 평면 경로에서 빼는 것은 **획 전체의 60%**이고,
그중 88%가 꺾인 획이다. 꺾인 획은 축에도 못 담기므로(AS-6) 어차피 자동 배치 밖이지만,
**평면 경로의 대상이기는 했다** — 미분류 획이 그 경로로 가기 때문이다. 매끄러운 획만 보면
제한에 걸리는 것은 **1.2%**다.
_초판은 "새로 뺀 것은 1.2%뿐"이라고 적었는데 **틀렸다**(D-S21) — 꺾인 획도 평면 경로의
대상이고, 그중 11.7%는 `bend ≤ 0.18`이라 제한을 통과한다._
_표본이 Quick,Draw(마우스 낙서)라 대상 사용자를 대표하지 않는다(AS-13). 자릿수만 읽는다 —
`bend_share.json@1671e540`(값은 `@503a75cb` 실행과 같다)._

### 면은 만들지 않는다

돌려 보면 **선만 보인다**(속이 비친다). 획이 튜브 메쉬라 **획끼리는 서로 가리고**(뒤 모서리의
30%가 가려진다 — _원장 밖의 값이고 유리한 자세를 골라 잰 것이다, AS-4_) 지면 격자·축 색·음영이 앞뒤를 잡아 주므로 형태는 읽힌다. 면을 지어내는 것은
**그리지 않은 기하를 만드는 것**이라 하지 않는다(D-S20).

## 1. 실행

```bash
cd web && npm install
```

```bash
cd web && npm run dev
```

포트가 겹치면 `npm run dev:5222`(HTTP, 5222)를 쓴다 — 5173을 다른 프로세스가 잡고 있을 때.

서버가 뜨면 **iPad에서 열 주소**가 콘솔에 출력된다(같은 Wi-Fi 필요):

```
  iPad에서 열 주소 (같은 Wi-Fi):
    https://172.30.1.81:5173
```

### HTTPS인 이유

**Wake Lock**(화면 꺼짐 방지)과 **getUserMedia**(V-6 마이크)는 secure context를 요구한다.
`localhost`는 예외적으로 secure로 취급되지만 **LAN IP는 아니므로**, iPad에서 열려면 HTTPS여야 한다.

### iPad 인증서 신뢰

자체 서명 인증서(`@vitejs/plugin-basic-ssl`)라 처음 열면 경고가 뜬다.

1. Safari에서 주소를 연다
2. **자세히 보기 → 이 웹사이트 방문**(iOS 버전에 따라 "고급 → 계속")
3. 그래도 막히면 아래 폴백

### 막힐 때 폴백 (HTTP)

```bash
cd web && npm run dev:http
```

HTTP로 뜬다. **Wake Lock과 마이크는 동작하지 않는다**(secure context가 아니므로).
드로잉·파싱·3D·치수 입력·내보내기는 모두 정상 동작하므로 잉크 품질 확인에는 충분하다.

## 2. iPad 동작 점검 목록

실기에서 확인할 항목.

| # | 항목 | 확인 방법 | 기대 |
|---|---|---|---|
| 1 | **팜 리젝션** | 손바닥을 댄 채 펜으로 그린다 | 손바닥 자국이 잉크로 안 남는다(펜이 한 번 감지되면 터치는 배제) |
| 2 | **coalesced 획 매끄러움** | 빠르게 곡선을 긋는다 | 각진 폴리라인이 아니라 매끄럽게 이어진다 |
| 3 | **필압·기울기 유입** | 펜을 눕혀 세게/약하게 긋고 내보내기 | JSON의 점이 `[x,y,t,p,tiltX,tiltY]`이고 tilt가 0이 아니다 |
| 4 | **확대 차단·더블탭 방지** | 두 손가락 확대·더블탭을 시도한다 | 화면이 확대되지 않는다 |
| 5 | **소실점 확정** | `축1`/`축2`/`축3`으로 셋을 찍는다 | 상태창에 "3점 투시 · 확정"이 뜨고 격자가 깔린다 |
| 6 | **획 → 3D** | `그리기`로 상자를 그린다 | 축 색으로 칠해지고 오른쪽 3D에 튜브로 쌓인다 |
| 7 | **회전 후 이어 그리기** | 3D를 돌리고 `여기서 그리기` | 소실점을 다시 안 찍어도 그 시점으로 놓인다(카메라가 잠긴다) |
| 8 | **고치기** | 안 놓인 획을 `고치기`로 고른다 | 후보 점이 뜨고, 누르면 붙는다. 한쪽만 고르면 주황(미확정) |
| 9 | **실행 취소·지우개** | `Ctrl+Z` / `지우개` | 되돌아간다. 지운 뒤 다른 획이 제멋대로 움직이지 않는다 |
| 10 | **내보내기** | 하단 `획 내보내기` | 세션 JSON이 내려받아진다 — **실획 분석의 유일한 통로**(0절) |
| 11 | **자동 저장** | 그린 뒤 탭을 닫았다 다시 연다 | 그대로 열린다(하단에 "저장됨 hh:mm:ss"). 지운 것·손으로 붙인 것까지 같다 |
| 12 | **OBJ·glTF** | 하단 `OBJ` / `glTF` | 파일이 내려받아지고 다른 도구에서 **폴리라인**으로 열린다(면은 없다) |
| 13 | **좌표 정합** | `진단`을 켜고 화면 여기저기를 눌러 본다 | 십자가 **손끝에 정확히** 온다. 어긋나면 진단 상자의 `Δ`가 그 값이고, **원점에서 멀수록 커지면 배율 · 일정하면 오프셋**이다 |
| 14 | **오프라인** | **빌드본**(`npm run build && npx vite preview`)을 한 번 연 뒤 기내 모드로 새로고침 | 그대로 뜬다(서비스 워커). 홈 화면에 추가하면 아이콘이 나온다. **개발 서버에는 서비스 워커가 없다** — `npm run dev`로는 확인되지 않는다 |

### 좌표가 어긋날 때 (진단)

하단 **`진단`** 버튼을 켜면 dpr · 캔버스 CSS/백버퍼 크기 · 실제 배율 · `client → local → back`
변환과 그 차이 `Δ` · 3D 오버레이와 렌더러가 같은 상자인지 · `visualViewport` 오프셋이 뜨고,
**닿은 자리에 십자가 그려진다**. 십자가 손끝에서 벗어나면 그만큼이 어긋남이다.
_iPad(dpr 2~3)에서 잉크가 dpr배 어긋나던 버그가 있었고 고쳤다 — `test/canvas_frame.test.ts`와
`e2e/coords.spec.ts`(dpr 1·2·3)가 그 자리를 잠근다._

### 저장·내보내기가 하는 일 (S-9)

- **자동 저장(IndexedDB)** — 그릴 때마다 브라우저에 남는다. 서버로 가지 않는다.
  담는 것은 `pts2d` 원본 + 카메라 입력 + **3D 배치 결과**다. 배치 결과까지 담는 이유는
  재생성이 화면과 갈리기 때문이다 — 합성 측정에서 **손으로 붙인 획 9개 중 9개가**
  재생성하면 안 놓였다(지우개 이력이 없을 때. `persist.json@1671e540`, D-S23).
  `처음부터`를 누르면 저장된 것도 함께 지워진다.
- **카메라를 다시 조정하면 손으로 붙인 배치는 다시 계산된다** — 일부는 안 놓이고 일부는
  다른 자리에 놓인다. 앵커가 다른 획 위의 점이고 그 획도 함께 움직이기 때문이다
  (f 10% 변화에 기존 기하가 상자 대각의 약 8% 이동). 지어내지 않고 **몇 개가 그렇게 됐는지
  알린다**. 돌린 시점에서 그린 획도 첫 카메라로는 재생성되지 않는다(좌표계가 다르다).
- **OBJ** — `v` + `l`(폴리라인). 면(`f`)은 없다. 획 하나가 `o` 그룹 하나다.
- **glTF 2.0** — 획 하나가 `LINE_STRIP` 하나. 버퍼가 파일 안에 들어가므로 파일 하나로 끝난다.
- 좌표는 **Y 위 · −Z 앞**으로 나간다(내부는 y 아래·z 안쪽인 카메라 좌표계다).

### 아직 없는 것

- **레이어·다중 선택**(S-7 잔여)
- 저장 슬롯은 **하나**다(자동 저장). 여러 작업을 나누려면 내보내기를 쓴다
- 자동 배치의 범위 제약은 **0.5절**에 있고, **측정된 한계는 [`PROTOTYPE.md`](PROTOTYPE.md)에 있다**

### 종단 검증 (S-10)

```bash
cd web && npx playwright test
```

카메라 확정 → 그리기 → 회전 → 이어 그리기 → 고치기(두 시점) → 저장 → 새로고침 복원 →
내보내기 → 지우개·실행 취소를 **실제 포인터 이벤트로** 한 바퀴 돈다. 결과는
`stage0/out/e2e.json`, 스크린샷은 `stage0/out/e2e/`에 남는다.
실측: 획 지연 **중앙 2.15ms**, 궤도 프레임 16.6ms, 복원 152ms(저장한 것이 그대로 돌아온다).

## 3. 실획을 분석에 넣기

내보낸 세션 JSON을 `sessions/`에 넣고:

```bash
cd web && npx vitest run test/real_ink.test.ts
```

→ `stage0/out/real_ink.json`에 AS-6 위반율 · AS-12 끝점 겨냥 오차 · 미배치율 · 판정 분포가
기록된다. 지금은 `awaiting_samples`다.

### 왜 이것이 중요한가

현재 임계는 **전부 Quick,Draw**(마우스·손가락 낙서)에 근거한다. 애플펜슬은 필압·기울기·
샘플링률이 달라 분포가 다를 수 있고, 다르면 **`AXIS_TOL`·접합 반경·미배치 임계를 재산출**한다.
재산출하면 STALE 탐지가 그 값을 쓴 측정 산출물을 자동으로 표시한다(4절).

**특히 이번에 하나가 늘었다** — 첫 시점 정합성 검사의 이득이 끝점 오차에 **단조 감소**한다
(0.005에서 3.2배, 0.02에서 1.13배). 채택 근거가 **끝점 오차 ≲1% 구간에 걸려 있고**,
Quick,Draw 자릿수(0.028~0.051)가 맞다면 그 검사는 거의 무용하다. 숙련자 획이 다르면 유효하다.
**어느 쪽인지는 실획만이 답한다.**

→ 세션 포맷에 `input.penSeen`이 필수인 이유가 이것이다. 어느 입력으로 그린 획인지 모르면
분리 자체가 불가능하다.

## 4. 개발 명령

```bash
cd web && npm test && npm run typecheck
```

```bash
python -m pytest tests/ -q && python selfcheck.py
```

`selfcheck.py`는 `stage0/out/`의 모든 측정 산출물을 스캔해 의심 수치(정확히 1.0/0.0인 비율,
단일 범주 분포, 비결정 시드 패턴)를 보고한다. **의심 ≠ 오류**이며, 각 플래그는 원인을 확인해
`progress.md`에 기록한다(§13 자기검증).

빌드(오프라인·PWA 확인):

```bash
cd web && npm run build && npx vite preview
```

빌드가 서비스 워커에 **사전 캐시 목록**을 넣는다(`vite.config.ts`의 `swPrecache`). 아이콘
PNG는 `npm run icons`가 `icon.svg`와 같은 그림으로 다시 만든다(의존성 없이 stdlib만 쓴다).
