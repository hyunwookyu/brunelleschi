# Brunelleschi

**투시도와 입체를 동시에 보면서 실시간으로 입체를 만든다.**
빈 화면에 투시도를 그리면 소실점이 잡히는 순간 그때까지의 획이 3D로 올라가고,
그 뒤로는 시작점 스냅·축 추론·미리보기가 실시간으로 돈다.
사용자는 계속 **종이에 투시도를 그린 것**이고, 3D 공간을 조작한 적이 없다.

> **이름** — **필리포 브루넬레스키**(Filippo Brunelleschi). 1415년경 피렌체
> **산 조반니 세례당** 앞에서, 판에 그린 그림에 구멍을 뚫고 거울에 비춰
> 실제 건물과 겹쳐 보이게 했다. **선 투시가 눈에 보이는 것과 맞는다**는 것을
> 작도가 아니라 **실험으로** 보인 첫 사례다. 이 도구가 하려는 것도 같다 —
> 그린 투시도와 세워진 입체가 **같은 픽셀에 놓이는지**를 매 획마다 확인한다.

현행 계획서는 [`docs/line_plan.md`](docs/line_plan.md)(개정 2), 작업 규칙은
[`CLAUDE.md`](CLAUDE.md), 진행 기록은 [`progress.md`](progress.md).

**이 도구가 무엇을 못 하는지와 그 수치**는 [`PROTOTYPE.md`](PROTOTYPE.md)에 따로 있다 —
쓰기 전에 그것부터 읽는 편이 낫다.
**사람 판단이 필요한 것**은 [`QUESTIONS.md`](QUESTIONS.md)에 있다.

이 문서는 **실행 방법과, 실제로 그려본 획을 측정에 넣기까지의 절차**를 다룬다.

## 0. 실획을 주시면 무엇이 달라지는가 (**지금 가장 필요한 것**)

이 프로젝트의 **가장 큰 위험 둘이 표본 문제**다.

| 전제 | 지금 값 | 출처 | 문제 |
|---|---|---|---|
| **AS-6** 한 획 = 한 축 | 위반율 **0.699**(n=1816) · 꺾인 획 비율 0.6775(n=4785, 다른 표본) | Quick,Draw | 마우스·손가락 **낙서**다 |
| **AS-12** 끝점 겨냥 오차 | **0.028~0.051** (성립 구간은 ~0.01) | Quick,Draw 환산 | 위와 같고, 게다가 **다른 양**을 환산한 것이다 |

둘 다 **대상 사용자(스타일러스·투시도 숙련자)를 대표하지 않는다**(AS-13).
그래서 **이 수치로 설계 결정을 하지 않는다** — tolerance를 넉넉히 잡거나 판정을 보수적으로
만들거나 미배치 폴백을 과하게 설계하지 않는다. 현재 값은 잠정이고, **실획이 들어오면 조정한다.**

### 획을 주는 방법

1. 앱을 연다(아래 1절. iPad든 데스크톱이든 좋다).
2. 소실점을 확정하고 **평소대로** 그린다. 고쳐 그리지 말고 평소 손대로 긋는다 —
   재는 것이 손의 성질이므로 잘 그리려고 하면 측정이 망가진다.
3. 하단 **"획 내보내기"**를 누른다(세션 JSON이 내려받아진다).
4. 그 파일을 저장소의 **`sessions/`** 에 넣는다.
5. `cd web && npx vitest run test/real_ink.test.ts` →
   `stage0/out/real_ink.json`에 AS-6·AS-12·미배치율·화각별 편차가 기록된다.

담기는 것: 원본 포인터 표본 `[x, y, t, 필압, 기울기X, 기울기Y]` + 판정 결과 + 배치 결과 + 카메라.
담기지 않는 것: 사용자 식별 정보. 화면 좌표와 그림 내용뿐이다.

⚠ **획의 저작권은 그린 사람의 것이다.** 이 저장소의 코드 라이선스(MIT)는 `sessions/`에
들어오는 그림에 미치지 않는다. 기존 표본인 **Quick,Draw는 Google의 CC BY 4.0**이고
그것도 코드와 별개다(D-L33).

## 0.5 되는 것과 **안 되는 것** (범위)

**전제**: 획은 **직선 세그먼트**가 되고 손떨림은 버린다(계획서 §1.1 — 프리핸드 보존은
미뤘고 `pts2d`를 보존하므로 나중에 표현 계층으로 돌아온다). 남는 것은 시작점과 끝점 둘이고,
그것이 SketchUp이 다루는 것과 같다.

**놓는 규칙 하나**: *시작점이 3D에 확정되고 축이 정해지면 놓는다.*
둘 중 하나가 없으면 **놓지 않고 2D 레이어에 남긴다** — 그것은 실패가 아니라 **대기**이고,
조건이 갖춰지면 승격하며 **승격은 연쇄한다**(§9.1).

| 획 | 자동 배치 | 왜 |
|---|---|---|
| 소실점 중 하나를 향하는 **곧은 획** | **된다** | 축 + 앵커가 획 전체를 정한다 |
| 화면과 나란한 곧은 획 | 된다 | 같은 이유(소실점이 무한원, 이론서 2.2) |
| **이어 그린 획**(끝점이 기존 기하에 붙는다) | 된다 | 스냅이 시작점을 3D에 확정한다(§3) |
| **돌린 시점에서 이어 그리기** | 된다 | 그 각도가 새 뷰가 되고 기하를 시점 좌표로 옮겨 푼다(§9.3) |
| **면 위 사선** | **안 된다** | 축이 방향만 주고 위치를 안 준다. 면 지정이 필요하고 그것은 §6이다(D-L28 · `QUESTIONS.md` a) |
| **한 획에 방향이 둘 이상**(꺾인 획) | **안 된다** | 축 하나에 담을 수 없다. Quick,Draw 낙서의 **67.7%**가 여기 해당한다(AS-6·AS-13) |
| **크게 휜 획 · 곡선**(아치·원기둥) | **안 된다** | 프리핸드와 함께 미뤘다. ⚠ 원·타원은 **카메라 확정에도 쓰이므로**(이론서 8.7) 우선순위가 다르다 |
| **경사 방향**(지붕·계단) | **안 된다** | 경사 소실점은 후보가 직선이라 획 하나로 못 가른다. 이론서 15.1 |
| 아무것에도 안 닿는 획 | 안 된다 | 깊이를 정할 근거가 없다 |
| 해칭·치수선·메모 | **안 된다(그리고 그것이 맞다)** | 다만 지금은 **미배치로 집계된다** — `QUESTIONS.md` b |

**안 놓인 획은 사라지지 않는다.** 화면에 2D로 남고, 나중에 조건이 갖춰지면 올라간다.
`고치기`로 고르거나 지울 수 있다.

### ⚠ 카메라는 **사용자가 맞춘다** — 자동 확정이 없다

이것이 이 도구의 가장 큰 제약이고 **측정이 그렇게 정했다**:
축 방향 오차가 **4~10° 대역**인데 필요한 것은 **0.5°**다(AS-L10 반증).
획을 100개까지 늘려도 단조로 안 준다.

**2026-08-16에 소실점 확정을 규칙 기반으로 바꿨다**(D-L37) — 검출도 가이드도 없다.
**선만 그으면 카메라가 선다**: 화면 가로·세로 선은 축 자체(무한원), 깊이선 둘의 교점이
첫 소실점이고 그것이 지평선을 정의하며, 다른 방향 깊이선 **하나**가 두 번째를 정한다.
세 번째는 수심 조건으로 유도한다(이론서 6.3). **애매하면 묻는다 — 추정하지 않는다.**

같은 픽스처에서 **규칙 6.93° 대 검출 9.17°**로 나아졌지만(`rule_camera.json`)
**대역 안에서 자리를 바꾼 것뿐이고 0.5°에는 못 간다.**
⚠⚠ **그리고 순서가 지배한다**(AS-L13) — 축별로 몰아 그으면 6.93°, **번갈아 그으면 32.57°**다.
사람이 어느 쪽으로 긋는지 **표본이 0이다.**

### 면은 만들지 않는다

돌려 보면 **선만 보인다**(속이 비친다). 획이 튜브 메쉬라 획끼리 서로 가리고 지면 격자·축
색이 앞뒤를 잡아 주므로 형태는 읽힌다. 면을 지어내는 것은 **그리지 않은 기하를 만드는 것**
이라 하지 않는다(D-S20). ⚠ **내보내기에는 그것이 부담이다** — `PROTOTYPE.md` §5.7.

## 1. 실행

```bash
cd web && npm install
```

```bash
cd web && npm run dev
```

포트가 겹치면 `npm run dev:5222`(HTTP, 5222)를 쓴다 — 5173을 다른 프로세스가 잡고 있을 때.

서버가 뜨면 **iPad에서 열 주소**가 콘솔에 출력된다(같은 Wi-Fi 필요):

```
  iPad에서 열 주소 (같은 Wi-Fi):
    https://172.30.1.81:5173
```

### HTTPS인 이유

**Wake Lock**(화면 꺼짐 방지)과 **getUserMedia**(V-6 마이크)는 secure context를 요구한다.
`localhost`는 예외적으로 secure로 취급되지만 **LAN IP는 아니므로**, iPad에서 열려면 HTTPS여야 한다.

### iPad 인증서 신뢰

자체 서명 인증서(`@vitejs/plugin-basic-ssl`)라 처음 열면 경고가 뜬다.

1. Safari에서 주소를 연다
2. **자세히 보기 → 이 웹사이트 방문**(iOS 버전에 따라 "고급 → 계속")
3. 그래도 막히면 아래 폴백

### 막힐 때 폴백 (HTTP)

```bash
cd web && npm run dev:http
```

HTTP로 뜬다. **Wake Lock과 마이크는 동작하지 않는다**(secure context가 아니므로).
드로잉·파싱·3D·치수 입력·내보내기는 모두 정상 동작하므로 잉크 품질 확인에는 충분하다.

## 1.5 배포와 원격 접속 (L-D.2)

**계산이 전부 브라우저에서 돈다 — 서버가 필요 없다.** 그래서 정적 호스팅만으로 동작하고,
**PC가 꺼져 있어도 아이패드에서 열린다**(같은 네트워크일 필요도 없다).

### 정적 배포 (GitHub Pages)

## ▶ **배포본**: <https://hyunwookyu.github.io/brunelleschi/>

`.github/workflows/pages.yml`이 `main` 푸시에 빌드→배포한다. **2026-08-16에 처음 실행됐고
셋 다 초록이다**(`build` · `deploy` · `measure`). 그 전까지 이 자리에는
"아직 한 번도 실행되지 않았다"고 적혀 있었다 — **적힌 것과 도는 것은 다르기 때문이다**(#32의 거울상).

**job을 둘로 가른다**:

| job | 무엇 | 배포를 막는가 |
|---|---|---|
| `build` → `deploy` | `tsc` · `npm run build` · **`static_deploy.spec.ts`** | **막는다**(A-4) |
| `measure` | `npx vitest run` 전체 | **안 막는다**(`continue-on-error`) |

⚠ **측정 하네스가 배포를 막지 않는다.** `data/quickdraw`·`sessions/`가 CI에 없어
그 둘은 **건너뛰고**, 건너뛴 사실이 vitest의 `skipped`와 작업 요약에 남는다 —
**통과로 세지 않는다**(등록처는 `web/test/dataDeps.ts`).
로컬에서 `S2S_REQUIRE_DATA=1`로 돌리면 **그 건너뛰기가 실패로 바뀐다.**

빌드는 **상대 경로**(`base: "./"`)를 쓴다 — Pages의 하위 경로(`/<repo>/`)든 루트든
그대로 열리고 리포지토리 이름을 어디에도 안 박는다. 다른 base가 필요하면:

```bash
cd web && S2S_BASE=/my-path/ npm run build
```

⚠ **인앱 브라우저(메신저 내장 웹뷰)에서는 서비스 워커가 막힌다** — 등록이 실패하므로
**오프라인이 안 된다**. Safari/Chrome으로 열어야 한다(실측: 등록이 "unknown error"로 거절됐다).

**확인은 자동이다**: `web/e2e/static_deploy.spec.ts`가 빌드본을 **하위 경로에 올려**
① 열리는지 ② 서비스 워커가 그 경로를 scope로 잡는지 ③ **오프라인 새로고침에서도 뜨는지**를
실제로 잰다. 로컬에서 같은 확인:

```bash
cd web && npm run build && npx playwright test e2e/static_deploy.spec.ts
```

**배포본에서 확인한 것**(2026-08-16, 브라우저 실측 — ⚠ **원장 밖 관측이다**):
`/brunelleschi/`와 `/brunelleschi/l.html` 둘 다 **200** · `window.S2S`가 서고 도구 막대가 뜬다 ·
서비스 워커가 **`/brunelleschi/`를 scope로** 잡고 페이지를 제어한다 · 콘솔 오류 0.
**루트로 들어와도 열린다** — `public/index.html`이 `l.html`로 보낸다(UI가 아니라 리다이렉트 한 장이다).

### 개발 중 원격 접속 — cloudflared (권장)

```bash
cloudflared tunnel --url https://localhost:5173
```

같은 망이 아니어도 접속되고 **HTTPS가 자동으로 붙는다** — 자체 서명 인증서 경고가 사라지고
Wake Lock·마이크 권한이 정상 동작한다(secure context가 성립한다).
출력되는 `https://<임의>.trycloudflare.com` 주소를 아이패드에서 연다.
`npm run dev:http`(HTTP)로 띄웠다면 `--url http://localhost:5173`으로 준다.

### 대안 — LAN + 자체 서명 (기존 절차)

같은 Wi-Fi에서만 되고 인증서 경고를 넘겨야 한다. 절차는 1절에 그대로 있다.
**cloudflared가 안 될 때의 폴백**으로 남긴다.

## 2. iPad 동작 점검 목록

실기에서 확인할 항목. **화면은 하나다**(단일 뷰포트 — 잉크와 3D가 같은 자리에 겹친다).

| # | 항목 | 확인 방법 | 기대 |
|---|---|---|---|
| 1 | **팜 리젝션** | 손바닥을 댄 채 펜으로 그린다 | 손바닥 자국이 잉크로 안 남는다(펜이 한 번 감지되면 터치는 배제) |
| 2 | **coalesced 획 매끄러움** | 빠르게 곡선을 긋는다 | 각진 폴리라인이 아니라 매끄럽게 이어진다 |
| 3 | **필압·기울기 유입** | 펜을 눕혀 세게/약하게 긋고 `획 내보내기` | 점이 `[x,y,t,p,tiltX,tiltY]`이고 tilt가 0이 아니다 |
| 4 | **확대 차단·더블탭 방지** | 두 손가락 확대·더블탭을 시도한다 | 화면이 확대되지 않는다 |
| 5 | **선만 그어 카메라 세우기** | 수평선 하나 · 수직선 하나 · **한 방향 깊이선 둘**을 긋는다 | 상태 줄이 슬롯 셋을 보이고 **다음에 그을 것**을 한 줄로 안내한다. 깊이선 둘째에서 소실점과 **지평선 y**가 뜬다(1점 투시) |
| 6 | **2점으로 올리기 · 묻기** | **다른 방향** 깊이선을 **하나** 더 긋는다 | 지평선과의 교점이 두 번째 소실점이 된다(세 개가 아니다). 애매한 각의 선을 그으면 **묻는 패널**이 뜬다 — 답할 때까지 그 획은 2D로 대기한다 |
| 7 | **확정 — 전환이 무변화다** | `확정` | 3D가 **잉크가 있던 바로 그 픽셀**에 그려진다(화면이 안 튄다). 상태 줄에 차수와 `fSource`가 뜬다 |
| 8 | **실시간 그리기** | `그리기`로 이어서 긋는다 | 시작점이 기존 기하에 **스냅**되고, 긋는 동안 축 색 미리보기가 따라온다 |
| 9 | **궤도 후 이어 그리기** | `궤도`로 돌린 뒤 `그리기` | 소실점을 다시 안 찍어도 놓인다. **그 각도가 새 뷰가 된다**(뷰 목록에 뜬다) |
| 10 | **차수 승격** | `소실점 다시` → 축을 하나 더 세우고 `차수 승격` | 2점 → 3점이 되고 **무엇을 잃었는지** 패널에 뜬다. `2점으로 되돌리기` 버튼이 생긴다 |
| 11 | **고치기·지우기** | `고치기`로 획을 고른다 | 고른 획이 강조되고 지울 수 있다. ⚠ **축 지정은 안 올린다**(D-L28 — 축은 방향만 주고 위치를 안 준다) |
| 12 | **실행 취소** | `실행취소` | 되돌아간다. **카메라까지 함께** 되돌아간다(둘 중 하나만 되돌리면 좌표계가 섞인다) |
| 13 | **자동 저장** | 그린 뒤 탭을 닫았다 다시 연다 | 그대로 열린다(하단에 "저장됨 hh:mm:ss"). **뷰와 2D 레이어까지** 같다 |
| 14 | **내보내기** | `OBJ` / `glTF` / `.brnl 저장` | 파일이 내려받아진다. OBJ·glTF는 **폴리라인만**(면 없음), `.brnl`은 **뷰와 2D 레이어까지** |
| 15 | **획 내보내기** | 하단 `획 내보내기` | 세션 JSON이 내려받아진다 — **실획 분석의 유일한 통로**(0절) |
| 16 | **좌표 정합** | 화면 여기저기를 그어 본다 | 잉크가 **손끝에 정확히** 온다. 어긋나면 콘솔에서 `S2S.diag()`를 본다(아래) |
| 17 | **오프라인** | **빌드본**(`npm run build && npx vite preview`)을 한 번 연 뒤 기내 모드로 새로고침 | 그대로 뜬다(서비스 워커). 홈 화면에 추가하면 **Brunel**이라는 이름으로 아이콘이 나온다. **개발 서버에는 서비스 워커가 없다** |

### 좌표가 어긋날 때 (진단)

새 UI에는 진단 **버튼이 없다** — 콘솔에서 부른다:

```bash
# 브라우저 콘솔에서
S2S.diag()
```

dpr · 캔버스 CSS/백버퍼 크기 · 실제 배율 · **stretch**(백버퍼 ÷ CSS 상자) ·
잉크와 three 렌더러가 같은 상자인지(`view_vs_overlay`) · `SIZE_HEAL` 발동 횟수 ·
`visualViewport` 오프셋이 나온다.

- 어긋남이 **원점에서 멀수록 커진다** → **배율**(백버퍼 ↔ CSS 불일치, dpr 이중 적용)
- 어긋남이 **일정하다** → **오프셋**(rect 미적용·스크롤·안전영역)

_iPad(dpr 2~3)에서 잉크가 dpr배 어긋나던 버그가 있었고 고쳤다 — `test/canvas_frame.test.ts`와
`e2e/coords.spec.ts`(dpr 1·2·3)가 그 자리를 잠근다. 그 스펙에는 **버그를 되살려 탐침이
실제로 잡는지 보는 `[회귀]` 팔**이 있다(PITFALLS #21)._

### 저장·내보내기가 하는 일 (L-D.2 — 뷰가 들어왔다)

- **자동 저장(IndexedDB)** — 그릴 때마다 브라우저에 남는다. 서버로 가지 않는다.
  담는 것은 `pts2d` 원본 + 카메라 **입력**(푼 결과가 아니다) + **3D 배치 결과**
  — 그리고 **뷰 목록과 뷰별 2D 레이어**다. 배치 결과까지 담는 이유는
  재생성이 화면과 갈리기 때문이다 — 합성 측정에서 **손으로 붙인 획 9개 중 9개가**
  재생성하면 안 놓였다(지우개 이력이 없을 때. `persist.json@1b6175a4`, D-S23).
  `처음부터`를 누르면 저장된 것도 함께 지워진다.
- **뷰와 2D 레이어가 새로고침을 넘는다**(§9.2) — 아직 3D로 안 올라간 대기 획은
  **그린 시점의 소유**로 남는다. 뷰가 없으면 그 획들은 좌표계를 잃고 통째로 사라진다.
  원장: `doc_store.json@1b6175a4`(직렬화 7건) · `stage_browser.json@1b6175a4`의
  `l_d3_save_roundtrip`(실제 브라우저 왕복).
- ⚠⚠ **옛 UI로 그린 저장(v1)은 열 수 없다.** v1 문서에는 뷰가 없어 소유 관계를
  지어내야 하고, 그것은 없는 정보를 만드는 것이다(D-L29). **그리고 2026-08-16에
  옛 UI를 삭제했으므로 그 문서를 열 수단이 없어졌다** — IndexedDB의 `current` 키에
  남아 있지만 읽는 코드가 없다. 새 UI는 `current2`를 쓴다(키를 갈라 두었다).
- **저장 v2가 못 담는 것**(복원 뒤 이렇게 보인다):
  되돌리기 이력(깊이 0이 된다) · 차수 표식(승격이 무엇을 잃었는지 안 보인다) ·
  **못 살린 스냅 표식**(⚠ 가장 나쁘다 — 조용히 틀린 시작점이 정상으로 보인다) ·
  가이드 핸들 상태 · `color`·`width`·`layer`.
- **카메라를 다시 조정하면 손으로 붙인 배치는 다시 계산된다** — 일부는 안 놓이고 일부는
  다른 자리에 놓인다. 앵커가 다른 획 위의 점이고 그 획도 함께 움직이기 때문이다
  (f 10% 변화에 기존 기하가 상자 대각의 약 8% 이동). 지어내지 않고 **몇 개가 그렇게 됐는지
  알린다**. 돌린 시점에서 그린 획도 첫 카메라로는 재생성되지 않는다(좌표계가 다르다).
- **OBJ** — `v` + `l`(폴리라인). 면(`f`)은 없다. 획 하나가 `o` 그룹 하나다.
- **glTF 2.0** — 획 하나가 `LINE_STRIP` 하나. 버퍼가 파일 안에 들어가므로 파일 하나로 끝난다.
- 좌표는 **Y 위 · −Z 앞**으로 나간다(내부는 y 아래·z 안쪽인 카메라 좌표계다).

### 아직 없는 것

- **레이어·다중 선택**(S-7 잔여)
- 저장 슬롯은 **하나**다(자동 저장). 여러 작업을 나누려면 `.brnl 저장`을 쓴다 —
  **파일이 슬롯이다**(판단 근거는 `DEFERRED.md`)
- **곡선·경사·면 위 사선**이 자동 배치 밖이다(0.5절)
- **사람 판단이 필요한 다섯**은 [`QUESTIONS.md`](QUESTIONS.md)에 있다 —
  면 위 임의 점 스냅 · 승격 대상이 아닌 획 · 근경 자동완성 · 지평선 수평 · 카메라 롤
- **실사용 취약점**(덧그림 병합 · 교차점 절단 · 스냅 후보 순환 · 뷰 누적 · 면 내보내기)은
  [`PROTOTYPE.md`](PROTOTYPE.md) §5에 있다 — **예상이고 측정이 아니다**
- 자동 배치의 범위 제약은 **0.5절**에 있고, **측정된 한계는 [`PROTOTYPE.md`](PROTOTYPE.md)에 있다**

### 종단 검증 (L-D.3)

```bash
cd web && npx playwright test
```

**실제 브라우저에서 실제 포인터 이벤트로** 돈다 — 카메라 확정 → 그리기 → 궤도 → 이어 그리기
→ 차수 승격·되돌리기 → 저장·새로고침 복원 → 내보내기. 결과는 `stage0/out/stage_browser.json`
(`l_d3` 외 블록별), 정적 배포 확인은 `static_deploy.json`.

사전 등록한 판정 다섯이 전부 선다 — 상자 둘에서 배치가 두 상자를 잇는다 · **승격 연쇄 3회** ·
차수 표식 2·3점 · 획 지연 **중앙 10ms 미만** · 스크린샷 두 판이 동일.
⚠ **지연·복원의 밀리초 수치는 여기 안 적는다** — 기계·실행마다 흔들려서(같은 기계에서도
2.1↔2.2ms · 1152↔1175ms) 문서가 곧 낡는다. **판정은 자릿수**이고 값은
`stage_browser.json@1b6175a4`의 `l_d3`에 있다. 개발 서버 기준이므로 **상한**이다.
⚠ 옛 UI의 값(`archive_W/e2e.json`)과 **견주지 않는다** — 다른 화면·다른 구간이다.
⚠ `dist/`가 낡으면 `static_deploy`가 실패한다 — `npm run build`를 먼저 돌린다.

## 3. 실획을 분석에 넣기

내보낸 세션 JSON을 `sessions/`에 넣고:

```bash
cd web && npx vitest run test/real_ink.test.ts
```

→ `stage0/out/real_ink.json`에 AS-6 위반율 · AS-12 끝점 겨냥 오차 · 미배치율 · 판정 분포가
기록된다. 지금은 `awaiting_samples`다.

### 왜 이것이 중요한가

현재 임계는 **전부 Quick,Draw**(마우스·손가락 낙서)에 근거한다. 애플펜슬은 필압·기울기·
샘플링률이 달라 분포가 다를 수 있고, 다르면 **`AXIS_TOL`·접합 반경·미배치 임계를 재산출**한다.
재산출하면 STALE 탐지가 그 값을 쓴 측정 산출물을 자동으로 표시한다(4절).

**특히 이번에 하나가 늘었다** — 첫 시점 정합성 검사의 이득이 끝점 오차에 **단조 감소**한다
(0.005에서 3.2배, 0.02에서 1.13배). 채택 근거가 **끝점 오차 ≲1% 구간에 걸려 있고**,
Quick,Draw 자릿수(0.028~0.051)가 맞다면 그 검사는 거의 무용하다. 숙련자 획이 다르면 유효하다.
**어느 쪽인지는 실획만이 답한다.**

→ 세션 포맷에 `input.penSeen`이 필수인 이유가 이것이다. 어느 입력으로 그린 획인지 모르면
분리 자체가 불가능하다.

## 4. 개발 명령

```bash
cd web && npm test && npm run typecheck
```

```bash
python -m pytest tests/ -q && python selfcheck.py
```

`selfcheck.py`는 `stage0/out/`의 모든 측정 산출물을 스캔해 의심 수치(정확히 1.0/0.0인 비율,
단일 범주 분포, 비결정 시드 패턴)를 보고한다. **의심 ≠ 오류**이며, 각 플래그는 원인을 확인해
`progress.md`에 기록한다(§13 자기검증).

빌드(오프라인·PWA 확인):

```bash
cd web && npm run build && npx vite preview
```

빌드가 서비스 워커에 **사전 캐시 목록**을 넣는다(`vite.config.ts`의 `swPrecache`). 아이콘
PNG는 `npm run icons`가 `icon.svg`와 같은 그림으로 다시 만든다(의존성 없이 stdlib만 쓴다).
