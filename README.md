# SKETCH2SPACE — 실기 테스트 안내

투시 스케치 3D 도구. 현행 계획서는 [`docs/sketch3d_plan.md`](docs/sketch3d_plan.md),
작업 규칙은 [`CLAUDE.md`](CLAUDE.md), 진행 기록은 [`progress.md`](progress.md).

이 문서는 **실제로 그려보고 그 획을 측정에 넣기까지의 절차**를 다룬다.

---

## 0. 실획을 주시면 무엇이 달라지는가 (**지금 가장 필요한 것**)

이 프로젝트의 **가장 큰 위험 둘이 표본 문제**다.

| 전제 | 지금 값 | 출처 | 문제 |
|---|---|---|---|
| **AS-6** 한 획 = 한 축 | 위반율 **0.699** | Quick,Draw | 마우스·손가락 **낙서**다 |
| **AS-12** 끝점 겨냥 오차 | **0.028~0.051** (성립 구간은 ~0.01) | Quick,Draw 환산 | 위와 같고, 게다가 **다른 양**을 환산한 것이다 |

둘 다 **대상 사용자(스타일러스·투시도 숙련자)를 대표하지 않는다**(AS-13).
그래서 **이 수치로 설계 결정을 하지 않는다** — tolerance를 넉넉히 잡거나 판정을 보수적으로
만들거나 미배치 폴백을 과하게 설계하지 않는다. 현재 값은 잠정이고, **실획이 들어오면 조정한다.**

### 획을 주는 방법

1. 앱을 연다(아래 1절. iPad든 데스크톱이든 좋다).
2. 소실점을 확정하고 **평소대로** 그린다. 고쳐 그리지 말고 평소 손대로 긋는다 —
   재는 것이 손의 성질이므로 잘 그리려고 하면 측정이 망가진다.
3. 하단 **"획 내보내기"**를 누른다(세션 JSON이 내려받아진다).
4. 그 파일을 저장소의 **`sessions/`** 에 넣는다.
5. `cd web && npx vitest run test/real_ink.test.ts` →
   `stage0/out/real_ink.json`에 AS-6·AS-12·미배치율·화각별 편차가 기록된다.

담기는 것: 원본 포인터 표본 `[x, y, t, 필압, 기울기X, 기울기Y]` + 판정 결과 + 배치 결과 + 카메라.
담기지 않는 것: 사용자 식별 정보. 화면 좌표와 그림 내용뿐이다.

## 1. 실행

```bash
cd web && npm install
```

```bash
cd web && npm run dev
```

포트가 겹치면 `npm run dev:5222`(HTTP, 5222)를 쓴다 — 5173을 다른 프로세스가 잡고 있을 때.

서버가 뜨면 **iPad에서 열 주소**가 콘솔에 출력된다(같은 Wi-Fi 필요):

```
  iPad에서 열 주소 (같은 Wi-Fi):
    https://172.30.1.81:5173
```

### HTTPS인 이유

**Wake Lock**(화면 꺼짐 방지)과 **getUserMedia**(V-6 마이크)는 secure context를 요구한다.
`localhost`는 예외적으로 secure로 취급되지만 **LAN IP는 아니므로**, iPad에서 열려면 HTTPS여야 한다.

### iPad 인증서 신뢰

자체 서명 인증서(`@vitejs/plugin-basic-ssl`)라 처음 열면 경고가 뜬다.

1. Safari에서 주소를 연다
2. **자세히 보기 → 이 웹사이트 방문**(iOS 버전에 따라 "고급 → 계속")
3. 그래도 막히면 아래 폴백

### 막힐 때 폴백 (HTTP)

```bash
cd web && npm run dev:http
```

HTTP로 뜬다. **Wake Lock과 마이크는 동작하지 않는다**(secure context가 아니므로).
드로잉·파싱·3D·치수 입력·내보내기는 모두 정상 동작하므로 잉크 품질 확인에는 충분하다.

## 2. iPad 동작 점검 목록

실기에서 확인할 항목. 각 항목의 근거는 괄호 안 문서를 참조.

| # | 항목 | 확인 방법 | 기대 |
|---|---|---|---|
| 1 | **팜 리젝션** | 손바닥을 화면에 댄 채 펜으로 그린다 | 손바닥 자국이 잉크로 남지 않는다. 펜이 한 번이라도 감지되면 터치는 전부 배제된다(조건부 팜 리젝션, V-5a) |
| 2 | **coalesced 획 매끄러움** | 빠르게 곡선을 긋는다 | 각진 폴리라인이 아니라 매끄럽게 이어진다. 펜/터치에서만 `getCoalescedEvents` 사용(V-5b) |
| 3 | **필압·기울기 유입** | 펜을 눕혀 세게/약하게 긋고 내보내기 | JSON의 점이 `[x,y,t,p,tiltX,tiltY]` 6튜플이고 tilt가 0이 아니다(§5.3) |
| 4 | **확대 차단·더블탭 방지** | 두 손가락 확대, 더블탭을 시도한다 | 화면이 확대되지 않는다(`touch-action:none` + gesturestart/dblclick 차단) |
| 5 | **3D 터치 조작** | 오른쪽 3D 뷰를 한 손가락/두 손가락으로 조작 | 1지 궤도 회전, 2지 팬·줌. [시점 복귀]·[탑뷰]가 동작 |
| 6 | **볼륨 픽 → 치수 패널** | 3D에서 볼륨을 탭 | 치수 패널이 열리고 숫자를 넣으면 즉시 반영된다(발화 앵커와 같은 전파 경로, V-4a) |
| 7 | **축 토글 (B-1b)** | 하단 [축 A/B]를 누른다 | 폭/깊이가 뒤바뀐 대안 해로 전환된다. **기하가 두 해를 구분하지 못하므로**(재투영 오차 정확히 동일) 보고 고르는 것이 정답이다 |
| 8 | **내보내기** | 하단 [내보내기] | 세션 JSON이 다운로드된다. 이것이 실획 분석의 유일한 통로(4.3) |

### 아직 없는 것

- **발화**(V-6): 마이크·Whisper·번역 로그 UI 미구현
- **세션 저장**(V-7): IndexedDB 자동 저장·복원 미구현. 지금은 내보내기만 있다
- **다중 뷰 정합**(덩어리 C 5번): 여러 투시를 묶는 경로 없음
- **투시 → IR 브라우저 경로**: 카메라 복원은 Python(`stage_perspective/`)에만 있다.
  브라우저는 아직 평면 프레임 획만 파싱한다

## 3. 실획을 분석에 넣기 (4.4)

내보낸 세션 JSON을 그대로 두 스크립트에 넘긴다.

```bash
python stage0/10_ink_noise_model.py path/to/session.json
```

```bash
python stage0/12_corner_error.py path/to/session.json
```

Quick,Draw 경로와 **동일한 측정 함수**를 쓰므로 두 분포를 직접 비교할 수 있다.

### 왜 이것이 중요한가 — 재작업 위험

현재 Track 2 임계와 1-bis 불확실성 전파는 **전부 Quick,Draw 코너 오차**에 근거한다
(precise 1.68% / medium 2.69% / coarse 4.21% of 도형 대각).
그런데 **Quick,Draw는 마우스·손가락 입력**이다.

애플펜슬은 필압·기울기·샘플링률이 달라 저주파 휘어짐 분포가 다를 수 있다. 다르면
**노이즈 모델을 펜/마우스 두 벌로 분리하고 Track 2 임계를 재산출**해야 한다.
`assumptions.md`의 **V-A**에 재작업 위험으로 등록돼 있다.

→ 그래서 세션 포맷에 `input.penSeen`을 필수로 두었다. 어느 입력으로 그린 획인지 모르면
분리 자체가 불가능하다.

## 4. 개발 명령

```bash
cd web && npm test && npm run typecheck
```

```bash
python -m pytest tests/ -q && python selfcheck.py
```

`selfcheck.py`는 `stage0/out/`의 모든 측정 산출물을 스캔해 의심 수치(정확히 1.0/0.0인 비율,
단일 범주 분포, 비결정 시드 패턴)를 보고한다. **의심 ≠ 오류**이며, 각 플래그는 원인을 확인해
`progress.md`에 기록한다(§13 자기검증).
