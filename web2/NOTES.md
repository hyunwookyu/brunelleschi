# web2 — 결정과 측정

문서는 이것 하나다. 결정·측정·되돌릴 조건을 여기 적는다.

## 2026-08-21 — 시작 (1단계 골격)

**갈래**: `web2` (origin/main에서). 기존 `web/`은 안 건드린다.
배포 전환은 아직 아니다 — `web/`이 배포에서 돌고 있고, web2가 1단계뿐이므로
대신할 만하지 않다. 전환 판단은 5단계(저장·내보내기·빌드 식별자) 이후 다시.

### 구조 결정

- **소실점·카메라 단일 출처** = `src/core/camera.ts`의 `analyze()`.
  획 목록의 순수 폴드로 매번 계산한다(파생 상태 무저장, 원칙 b).
  작도 획의 역할(지평선/깊이선/내용)도 저장하지 않고 순서 재생으로 나온다 —
  미리보기와 확정이 같은 `classifyNext()`를 쓰므로 재생이 어긋나지 않는다.
  정적 검사(`test/static.test.ts`)가 밖에서의 직접 계산(주점 `W/2`,
  `DEFAULT_F_RATIO`, `quatConj` 사영)을 막는다.
- **세계 좌표 = 작도 카메라 프레임**(원점 눈, +x 오른쪽, +y 위, 시선 −z).
  지평선 y = 주점 y, 피치 0, 롤 0. 축 = 유한 소실점 방향 + 화면 평행(H·V).
  1점 상태에서 H축(화면 평행 가로)은 vp0 방향과 직교하지 않을 수 있다 —
  작도가 요구하는 것은 직교가 아니라 방향이므로 그대로 둔다(빗각 기둥도 유효한 입체다).
- **획이 그려진 뷰 포즈를 획에 저장한다**(`Stroke.view`, 작도 포즈면 생략).
  파생이 아니라 입력 맥락이다 — 궤도 후 이어 그리기의 광선이 이것에서 나온다.

### 게이지 (임의 좌표가 아닌 이유를 적는다)

- **첫 앵커**: 3D가 하나도 없는 상태에서 처음 그린 **화면 평행** 획의 시작점을
  깊이 z=−f 평면에 놓는다. 단안 투시는 전역 스케일이 원리적으로 모호하므로
  이것은 좌표 임의 지정이 아니라 **단위 선택**이다(그 평면에서 화면 1px = 세계 1단위).
  화면 평행이 아닌 획은 앵커가 되지 못하고 대기한다 — 지시의 "화면 평행 선이 있으면
  그 평면에서 깊이가 정해진다"를 그대로 구현했다.
  이후의 미연결 획은 화면 평행이어도 대기다 — 게이지는 한 번뿐, 두 번째부터는
  깊이를 모르는 것이므로 놓으면 조용히 틀린 배치가 된다.
  되돌릴 조건: 실척 입력(치수)이 생기면 게이지가 그것으로 대체된다.
- **1점 상태의 f = 0.87·W**: 깊이 배율 게이지(임의값). 화각 참고 대역(≈60°)의 값을
  골랐을 뿐 근거는 "임의여도 된다"이다. 2점이 되면 f² = |PV₁|·|PV₂|로 대체된다.

### 그 외 결정

- **f² ≤ 0 (두 소실점이 주점 같은 쪽)**: 두 번째 깊이선은 소실점이 되지 못하고
  내용 획으로 남는다(획은 남고 카메라만 안 건드린다). 최상단 한 줄로 알린다.
  거부는 이것 하나다(원칙 f).
- **작도 중 실수로 그은 짧은 선**: 소실점 기여 최소 길이(0.04·대각) 미만이면
  카메라를 안 건드리고 내용 획이 된다.
- **자유 방향 획**: 양끝이 다 3D에 붙어야 확정. 한쪽만이면 대기 —
  깊이 정보가 없는데 놓으면 임의 좌표가 되기 때문.
- **실행취소는 내용 획만**. 작도(지평선·깊이선)는 실행취소 대상이 아니다 —
  "그림만 되돌린다. 카메라는 별개다". 작도를 고치려면 처음부터(리셋은 추후).
- **대기 획의 궤도 중 표시**: 자기 포즈의 화면 좌표로 항상 그리되 포즈가 다르면
  흐리게. 3D가 없어 정확한 재사영이 불가능한 상태에서 불변식 j(사라지지 않는다)를
  지키는 타협. 되돌릴 조건: 혼란이 확인되면 자기 포즈에서만 진하게.
- **궤도 후 작도선 표시**: 작도 포즈에서만 원본 세그먼트, 돌린 뒤에는 파생
  표식(소실점 ×)만. 깊이선은 방향 정의라 3D 깊이가 없다.
- **데스크톱 입력**(확인용): 마우스 좌 그리기 · 중 드래그 궤도 · 우 드래그 팬 ·
  휠 줌 (SketchUp 선례).
- **캔버스 크기 = 첫 로드 시점 창 크기로 고정**(doc.frame). 리사이즈 대응은 미룸 —
  HANDOFF에 남긴다.

## 2026-08-21 — 2단계 (오스냅 · 연결과 대기)

- **오스냅 = `core/osnap.ts`**. Rhino 관행: 정점 > 끝점 > 중점 > 교차점 > 수선 발 >
  연장선 > 근처점, 종류별 토글·반경 조절(4~20px, 기본 8). 정확한 것이 앞선다.
- **점 스냅이 방향(축) 스냅을 이긴다** — Rhino 선례. 오스냅이 없을 때만 축 스냅.
- **중점은 3D 중점의 사영** — 투시에서 화면 중점과 다르다(깊이획에서 ~34px 차이,
  osnap.test가 반례로 박음). 화면 중점 자리는 근처점이 잡는다(선분 위 3D 점 — 정확).
- **교차점은 3D 실제 교차만**(간격 ≤ 0.01·기하 크기 = 3D bbox 대각).
  화면 교차·다른 깊이는 반례 테스트로 배제 확인. 이 목록(`intersections3`)을
  3단계 자동 분할이 그대로 쓴다.
- **수선 발**: 그리는 중이고 시작점이 3D일 때만. 발이 끝점에 닿으면 끝점의 몫.
- **연장선**: 광선-직선 최근접의 파라미터가 선분 밖(±0.02 밖)일 때. 조준용 2D 점 —
  자유 획의 끝이 연장선에만 붙으면 3D 깊이가 안 정해져 대기한다(끝 좌표는 조준일 뿐).
- **대기 획은 끝점·중점만 후보(2D)** — 2D 교차는 가림과 구별 불가라 뺀다.
- **선분 위 시작**(lift 확장): 시작 2D가 확정 선분의 사영 위(병합 허용 0.002·대각)면
  광선-선분 직선 최근접점으로 3D가 정해진다 — "확정된 선과 교차하거나 끝점이 붙으면".
- **정점 병합은 3D 거리 0.002·기하 크기** — 같은 자리 끝점 2개 이상이면 정점.
- 오스냅 설정 UI는 임시 패널(우측) — 7단계에서 세로바로 흡수.

## 2026-08-21 — 3단계 (지우개 · 자동 분할 · 매달린 것)

- **조각은 저장하지 않는다** — `core/pieces.ts`가 획 + 3D 교차 목록(`intersections3`,
  오스냅과 같은 출처)에서 매번 계산한다. 승격 획은 3D 실제 교차에서만 나뉜다
  (화면 교차는 가림 — 반례 테스트). 끝점 접촉(t=0·1)은 분할이 아니다.
  대기 획은 깊이를 몰라 나뉘지 않는다 — 통째 한 조각.
- **지우개는 조각 단위**(기본 12px, 4~60 조절): 닿은 조각을 문서에서 지우고
  남은 조각들을 새 획으로 등재한다(끝점 = 3D 절단점의 사영 — 교차점 위라
  리프팅이 다시 정확히 붙는다). 드래그 한 번 = op 하나(실행취소 단위).
- **작도 획(지평선·깊이선)은 지우개 대상이 아니다** — 카메라는 별개다.
- **매달린 것들의 처리(정의)**: 지워진 획에 3D 결정을 의존하던 획은 **대기로
  내려간다**. 사라지는 것은 지운 조각뿐이다(불변식 j). 재연결하면 다시 올라간다.
  단, 지워진 앵커의 역할은 다음 화면 평행 획이 이어받으므로(재폴드) 화면은 안 변한다.
- **실행취소를 op 기반으로 재작성** — 획 추가 op·지우개 드래그 op. 지운 획은
  원래 인덱스로 복원된다(작도 폴드가 순서에 의존하므로 인덱스 보존이 필수).

## 2026-08-21 — 4단계 (시점)

- **뷰 큐브**(`core/viewcube.ts`): 기준 좌표계 = 그린 공간의 축(X=vp0 방향·Y=수직·
  Z=외적, 정규직교 — 세계 축이 아니다). 면·모서리·꼭짓점 = 6+12+8 시점.
  면 = 1점 시점: 그 축 소실점이 주점에 정확히 오고 피치 0·롤 0(테스트로 박음).
  그리기(cubeGeom)와 클릭 판정(cubeHit)이 같은 출처. 위젯은 정사영이며
  장면 사영이 아니다 — 방향 변환은 camera.ts의 `dirInCamera`로(원칙 a 유지).
  전환은 즉시(애니메이션 없음 — 가장 단순한 것. 필요해지면 slerp).
- **팬·줌 분리**: 작도 포즈에서는 화면 조작(뷰 오프셋 `{s,ox,oy}` — 문서 좌표
  불변, 렌더 변환으로만), 궤도 후에는 공간 조작(돌리·팬). 뷰 오프셋의 3D 반영은
  투영 항등식 s·(px+f·X/−Z)+ox = (s·px+ox)+(s·f)·X/−Z 로 정확하다(주점·f 변환).
  화면 좌표↔문서 좌표 변환은 `screenToDoc`/`docToScreen` 단일 출처.
  오스냅·지우개 반경은 화면 px이므로 배율로 나눠 문서 좌표에 적용한다.
- **시점 저장**: 포즈+뷰 오프셋을 슬롯에 저장·복귀(임시 버튼 UI). '작도 시점'은
  포즈와 뷰 오프셋을 함께 리셋한다.

## 2026-08-21 — 5단계 (저장·내보내기·빌드)

- **.brnl = JSON**(`core/file.ts`): 프레임·획(원본 좌표·뷰 포즈)·nextId·저장 시점만.
  카메라·소실점·리프팅은 파생이라 안 담는다 — 복원 후 재계산이 같은 값을 내는 것을
  테스트가 확인한다. 파싱은 전 필드 검증(깨진 입력 → null·최상단 알림).
- **자동 저장**: 문서·시점 변경 400ms 뒤 localStorage. 시작 시 복원.
  복원 프레임이 창과 다르면 뷰 배율로 맞춘다(문서 좌표 불변).
- **내보내기**: OBJ(선분당 v 2 + l 1) · glTF 2.0(LINES, 버퍼 내장 data URI).
  좌표계는 세계(작도 카메라 프레임) 그대로. 재료→레이어는 6단계에서.
- **빌드 식별자**: `git rev-parse --short HEAD` + 빌드 시각을 vite define으로 박고
  우하단에 표시. **서비스 워커**: 문서 network-first, 캐시 이름에 빌드 식별자 —
  빌드마다 바뀌어 새 빌드가 한 번에 나간다. 등록은 프로덕션 빌드에서만
  (Playwright는 매번 새 컨텍스트라 SW 문제를 e2e가 못 잡는다 — 함정 목록 그대로).
- **창 크기 변경**: 캔버스·렌더러만 따라가고 문서 프레임(좌표계)은 불변.

## 2026-08-21 — 6단계 (재료)

- **재료 = 경도표**(`core/material.ts`): 2H·H·F·HB·B·2B·잉크. 어두움·굵기·입자가
  2H→2B 단조 증가(테스트), 잉크는 균일(grain 0)·불투명 1. 보조선·결과선 분류 없음.
- **획에 재료 저장**(`Stroke.mat{grade,press}`) — 입력 맥락. 지운 조각의 남은
  부분도 재료 유지. .brnl 왕복 보존, 모르는 경도는 파싱 거부.
- **질감**: 3D 본체는 경도별 Line2 재질(색·굵기·투명도, 화면 고정), 흑연 입자는
  2D 오버레이가 사영 선분 위에 얹는다. 획별 시드 고정 rng32 — 프레임마다 같은
  입자(Math.random 없음). 필압은 입자 밀도·진하기에 반영(본체 재질은 경도별 공유라
  획별 변조 불가 — 필요해지면 획별 재질로).
- **지우개 둘**: 연필 지우개는 흑연만, 펜 지우개는 잉크만 — 겹쳐 있어도 서로
  안 건드린다(선따기). 단위·e2e 양쪽에서 확인.
- **내보내기 = 재료가 레이어**: OBJ `g`/`usemtl`+MTL(Kd 색), glTF 재료별
  프리미티브+baseColorFactor.
- **수리(6단계에서 발견)**: 연결이 시작점 방향으로만 풀려서, 끝점만 확정점에 닿은
  축 획이 대기로 남았다(지우개 후 연쇄가 주저앉는 e2e에서 발견). **연결은 방향이
  없다** — 끝점 쪽이 먼저 확정되면 시작점을 광선-직선 최근접으로 푼다(lift.ts).

## 2026-08-21 — 7단계 (UI 정리)

- **우측 세로바 하나**(접기 가능): 위 실행취소·다시실행 / 가운데 도구(펜·연필
  지우개·펜 지우개)·재료(심 인디케이터+경도 슬라이더)·크기 / 아래 파일·설정(접힘).
- **우측 상단**: 큐브(캔버스 그림, 우상단 구석) + 작도 시점·시점 저장·저장된 시점.
- **좌측·하단 비움**. 알림은 최상단 한 줄 유지(원칙 g).
- 아이콘은 글리프(✏·▱·▰·↶·↷) — 외부 에셋 없음.

### 측정·검증 (1단계)

- 단위 39건 근처(카메라·리프팅·스냅·정적) — 수치는 실행이 정본.
- 불변식 h(소실점=교점, 오차 0)·i(표시=스냅 단일 출처)·j(대기 획 잔존)·
  k(승격 전후 재사영 불변)를 테스트로 박았고, k와 h는 버그를 되살려
  (부분 유지 사영 / 반올림 저장) 실제로 잡히는 것을 확인하는 짝 테스트가 있다.
- e2e는 dpr 1과 2 두 프로젝트로 같은 흐름을 돈다.
